# 네트워크 활용(TCP/IP) — 네트워크 접근 계층

> 자동 생성 — 원본은 `cards/netaccess.js`. 직접 수정 금지.

## 네트워크 접근 계층 · 주요 기능 — Network Access Layer

`네트워크 보안`  `OSI 1·2 통합` `PDU=프레임` `MAC 48비트` `프레이밍·오류검출(CRC)` `LLC + MAC 부계층`

**한줄:** TCP/IP 최하위 계층(OSI 물리+데이터링크) / PDU=프레임, 주소=MAC(48비트) / 프레이밍·물리주소지정·매체접근제어·오류검출(CRC)

**위치 · 역할**

TCP/IP의 **1계층(맨 아래)**으로 OSI의 **물리 계층 + 데이터링크 계층**을 합친 것. **같은 네트워크 안에서 인접 장비끼리** 실제로 데이터를 주고받는 일을 담당한다(멀리 보내는 것은 상위 IP의 몫).
- PDU = **프레임(Frame)** · 주소 = **MAC 주소** · 대표 기술 = **이더넷(Ethernet)**·Wi-Fi
- 데이터링크는 두 부계층으로 나뉜다 — **LLC**(Logical Link Control, 상위와의 인터페이스·흐름/오류 제어)와 **MAC**(Media Access Control, **매체 접근 제어**)

**주요 기능 (시험 출제 포인트)**

- **프레이밍(Framing)** — 상위 패킷에 헤더·트레일러를 붙여 **프레임**으로 만들고, 시작·끝을 구분
- **물리 주소 지정** — 출발지·목적지 **MAC 주소** 표기
- **매체 접근 제어(MAC)** — 여러 장치가 **하나의 회선을 공유**할 때 **누가 언제 보낼지** 조정 → **CSMA/CD·CSMA/CA·토큰 패싱**
- **오류 검출** — 프레임 끝의 **FCS**에 **CRC** 값을 넣어 **훼손 여부를 검사**. **검출만 하고 버린다**(재전송은 상위 TCP의 몫)
- **흐름 제어** — 인접 구간의 전송 속도 조절
- **물리 계층 몫** — 비트를 **전기·광 신호로 변환**, 케이블·커넥터 규격

**MAC 주소 · 이더넷 프레임**

**MAC 주소** = **48비트(6바이트)**, 16진수 12자리(`00-1A-2B-3C-4D-5E`). 앞 **3바이트=제조사 식별(OUI)**, 뒤 3바이트=일련번호. **랜카드에 새겨진 고유 주소**지만 **소프트웨어로 변경(MAC 스푸핑) 가능**하다.
**브로드캐스트 주소** = `FF:FF:FF:FF:FF:FF`.

```
[프리앰블][목적지 MAC 6][출발지 MAC 6][타입 2][데이터 46~1500][FCS 4]
```

데이터 최대 **1500바이트 = MTU**.

**보안 — 이 계층의 공격**

- **MAC 스푸핑** — MAC 주소를 위조해 **MAC 기반 인증·필터링 우회**
- **MAC 플러딩** — 스위치의 MAC 테이블을 가짜로 채워 **허브처럼 만들어 스니핑**
- **ARP 스푸핑** — IP↔MAC 매핑을 속여 **중간자 공격**
**대응**: 스위치 **포트 보안**(포트당 MAC 수 제한·고정), **동적 ARP 검사(DAI)**, **802.1X 인증**, 미사용 포트 비활성화.

> **시험 한줄정리:** 네트워크 접근 계층 = **OSI 1·2 통합**(TCP/IP 최하위), PDU=**프레임**, 주소=**MAC 48비트**(앞 3바이트 제조사) / 기능=**프레이밍·물리주소·매체접근제어·오류검출(CRC/FCS, 검출만)** / 부계층 **LLC + MAC** / 공격=MAC 스푸핑·플러딩 → 포트 보안·802.1X

_관련 개념: csma · vlan · netdevice_

## CSMA/CD · CSMA/CA — Collision Detection / Collision Avoidance

`네트워크 보안`  `CD=유선 이더넷` `CA=무선 Wi-Fi` `감지 vs 회피` `JAM·백오프` `RTS/CTS·숨은 노드`

**한줄:** 회선을 공유할 때 충돌을 다루는 방식 / CD=유선, 충돌을 감지하고 재전송 / CA=무선, 충돌을 미리 회피(감지가 불가능해서)

**공통 — CSMA란**

**CSMA(Carrier Sense Multiple Access)** = **반송파 감지 다중 접근**. 여러 장치가 하나의 회선을 공유할 때, **보내기 전에 먼저 회선이 비었는지 엿듣고(Carrier Sense)** 비어 있으면 전송하는 방식. 그래도 **동시에** 보내면 충돌이 나므로, 그 뒤 처리가 **CD냐 CA냐**로 갈린다.

**CSMA/CD — 유선 이더넷 (Collision Detection)**

**충돌을 감지**해서 수습하는 방식.
- **1 감지** — 회선이 비었는지 확인

- **2 전송** — 비었으면 전송 시작

- **3 충돌 감지** — 전송 중에도 계속 감시

- **4 JAM 신호** — 충돌을 모두에게 알림

- **5 백오프 후 재전송** — **임의 시간** 대기(이진 지수 백오프)

**랜덤 대기**가 핵심 — 같은 시간을 기다리면 또 부딪히기 때문이다.**[지금은?]** 충돌은 **반이중(half-duplex)·허브** 환경의 문제다. **스위치 + 전이중(full-duplex)**에서는 **충돌 자체가 발생하지 않아** CSMA/CD가 사실상 필요 없다.

**CSMA/CA — 무선 LAN (Collision Avoidance)**

**충돌을 미리 피하는** 방식. Wi-Fi(**IEEE 802.11**)가 사용.**[왜 무선은 '감지'를 못 하나 (핵심 이유)]** ① 전송 중에는 **자기 신호가 너무 강해** 남의 신호를 들을 수 없다. ② **숨은 노드 문제** — A와 C가 서로의 신호는 못 듣지만 가운데 B에게는 둘 다 닿아, 서로 비었다고 착각하고 동시에 보낸다.
**동작**: 회선이 빈 것을 확인 → **일정 시간(IFS) 대기 + 랜덤 백오프** → 전송 → 받은 쪽이 **ACK로 확인**(ACK가 없으면 충돌로 보고 재전송).
**RTS/CTS**(전송 요청/허가) 교환을 쓰면 **숨은 노드 문제**를 완화할 수 있다.

**비교 · 함정**

- **CSMA/CD**: **유선**(이더넷) · 충돌 **감지**(사후 처리) · JAM + 백오프 재전송

- **CSMA/CA**: **무선**(Wi-Fi) · 충돌 **회피**(사전 예방) · IFS+백오프, **ACK 확인**, RTS/CTS

**함정**: '무선은 CSMA/CD를 쓴다'(X) — **무선은 충돌 감지가 불가능**해서 CA를 쓴다. **D=Detection(감지), A=Avoidance(회피)**로 구분.

> **시험 한줄정리:** **CSMA**=보내기 전 회선을 엿듣는 방식 / **CSMA/CD=유선(이더넷)·충돌 감지** → JAM 신호 + **랜덤 백오프** 재전송(스위치·전이중이면 불필요) / **CSMA/CA=무선(Wi-Fi)·충돌 회피** → 감지가 **불가능**(자기 신호·숨은 노드)해서, IFS+백오프·**ACK**·RTS/CTS

_관련 개념: netaccess · netdevice · vlan_

## VLAN (가상 랜) — Virtual LAN · IEEE 802.1Q

`네트워크 보안`  `논리적 분할` `브로드캐스트 도메인 분리` `802.1Q 태깅` `트렁크 포트` `VLAN 홉핑`

**한줄:** 물리적 위치와 무관하게 스위치를 논리적으로 분할 / 브로드캐스트 도메인을 나눠 트래픽·보안 영역 분리 / 802.1Q 태그로 여러 VLAN을 한 회선(트렁크)에 실음

**정의 · 왜 쓰나**

**VLAN(Virtual LAN)** — 하나의 물리 스위치를 **여러 개의 논리적 네트워크로 나누는** 기술. 원래 **브로드캐스트 도메인은 라우터만** 나눌 수 있었는데, VLAN을 쓰면 **스위치에서도** 나눌 수 있다.
- **브로드캐스트 트래픽 감소** — 불필요한 전파 범위를 줄여 성능 향상
- **보안·격리** — 부서·용도별로 나눠 **서로 직접 통신하지 못하게**(예: 사무망 / 서버망 / 게스트망)
- **유연성** — 자리를 옮겨도 **케이블 공사 없이** 설정만으로 같은 그룹 유지
**다른 VLAN끼리 통신하려면 반드시 라우터·L3 스위치**를 거쳐야 한다 → 그 지점에서 **ACL로 통제**할 수 있다는 것이 보안상 장점.

**구성 방식 · 802.1Q 태깅**

- **포트 기반(정적)** — 스위치 포트마다 VLAN 지정. 가장 일반적
- **MAC 기반·프로토콜 기반(동적)** — 장비 MAC이나 프로토콜로 자동 할당
**[802.1Q 태그와 트렁크]** 스위치를 넘어갈 때 **어느 VLAN 소속인지** 표시하려고 프레임에 **VLAN ID(12비트, 1~4094)**를 삽입하는 것이 **IEEE 802.1Q 태깅**. 이렇게 **여러 VLAN을 한 회선에 실어 나르는 포트**를 **트렁크(Trunk) 포트**라 하고, 단말이 붙는 일반 포트는 **액세스(Access) 포트**다. 태그 없이 다니는 VLAN이 **네이티브 VLAN**(기본은 VLAN 1).

**VLAN 홉핑 (보안 위협)**

VLAN으로 나눠도 **완벽한 격리는 아니다**. **VLAN 홉핑(Hopping)**은 다른 VLAN으로 **넘어가는** 공격이다.
- **스위치 스푸핑** — 공격자가 자기 포트를 **트렁크인 것처럼 협상(DTP)**시켜 **모든 VLAN 트래픽**을 받아본다
- **더블 태깅(이중 태깅)** — 태그를 **두 개** 붙여 보내면 첫 스위치가 바깥 태그만 떼고 넘겨, 안쪽 태그로 **다른 VLAN에 도달**한다(네이티브 VLAN을 악용)

**대응**

- **DTP(트렁크 자동 협상) 비활성화** — 트렁크는 **수동으로만** 지정
- **네이티브 VLAN을 기본값(1)에서 변경**하고, 사용하지 않는 전용 VLAN으로 둘 것
- **미사용 포트는 셧다운**하고 사용하지 않는 VLAN에 격리
- **포트 보안**(MAC 수 제한)·**802.1X 인증**·VLAN 간 **ACL** 적용

> **시험 한줄정리:** VLAN=물리 위치와 무관하게 **스위치를 논리 분할** → **브로드캐스트 도메인 분리**(원래 라우터만 가능) / **802.1Q 태그(VLAN ID 12비트)**·**트렁크** vs 액세스 포트 / **VLAN 간 통신은 라우터·L3** 필요 / 위협=**VLAN 홉핑**(스위치 스푸핑·더블 태깅) → DTP 끄기·네이티브 VLAN 변경

_관련 개념: netaccess · netdevice · subnet_
