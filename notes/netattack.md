# 네트워크 기반 공격 — 스캐닝·스니핑·스푸핑·하이재킹

> 자동 생성 — 원본은 `cards/netattack.js`. 직접 수정 금지.

## 포트 스캐닝 — Port Scanning

`네트워크 보안`  `정찰 단계` `SYN=스텔스 스캔` `SYN+ACK 열림·RST 닫힘` `FIN·NULL·XMAS` `무응답=필터링`

**한줄:** 열린 포트·서비스를 찾는 정찰 / TCP Connect(완전)·SYN(스텔스)·FIN/NULL/XMAS(우회)·UDP / SYN+ACK=열림, RST=닫힘, 무응답=필터링

**목적 — 공격의 첫 단계**

대상 시스템의 **열린 포트·동작 중인 서비스·버전·OS**를 알아내는 행위. 킬체인의 **①정찰(Reconnaissance)** 단계에 해당하며, 여기서 얻은 정보로 **어느 취약점을 쓸지** 정한다. 대표 도구는 **Nmap**.

**응답으로 판정하는 법 (시험 핵심)**

- **SYN+ACK** 응답 → **포트 열림(Open)**
- **RST** 응답 → **포트 닫힘(Closed)**
- **무응답** → **방화벽에 의해 필터링(Filtered)**
이 세 가지 대응이 그대로 문제로 나온다.

**스캔 종류**

- **TCP Connect 스캔** — **3-way handshake를 완전히 맺는다**. 정확하지만 **연결 로그가 남아** 탐지되기 쉽다
- **TCP SYN 스캔(Half-Open · 스텔스)** — SYN을 보내 **SYN+ACK가 오면 RST로 끊어** 연결을 완성하지 않는다 → **로그에 덜 남아** 가장 널리 쓰인다
- **FIN · NULL · XMAS 스캔** — 비정상 플래그로 보내 **방화벽·IDS를 우회**. 규격상 **닫힌 포트만 RST로 응답**하고 열린 포트는 **무응답**이다
→ **NULL**=플래그 전부 0 · **FIN**=FIN만 · **XMAS**=**FIN+PSH+URG**(불 켜진 트리처럼)
- **ACK 스캔** — 포트 개폐가 아니라 **방화벽 필터링 여부**를 확인
- **UDP 스캔** — 응답이 없으면 열림으로 추정, **ICMP Port Unreachable**이 오면 닫힘. **느리고 부정확**

**대응**

**불필요한 포트·서비스 차단**(가장 근본) · 방화벽에서 **필요한 것만 허용** · **IDS/IPS의 임계치 탐지**(짧은 시간에 많은 포트 접근 = 스캔 징후) · **배너 숨기기**로 버전 노출 차단 · 로그 모니터링.

> **시험 한줄정리:** 포트 스캔=**정찰 단계**(Nmap) / 판정 **SYN+ACK=열림 · RST=닫힘 · 무응답=필터링** / 종류 **Connect(완전·로그남음)** · **SYN(스텔스·Half-Open)** · **FIN/NULL/XMAS(우회, 열림=무응답)** · ACK(방화벽 확인) · UDP(느림) / 대응=불필요 포트 차단·IPS 임계치

_관련 개념: sniffing · killchain · translayer_

## 스니핑 — Sniffing

`네트워크 보안`  `수동적 공격` `무차별 모드` `허브=쉬움` `스위치는 ARP 스푸핑 필요` `암호화가 근본 대응`

**한줄:** 네트워크를 지나는 패킷을 몰래 들여다보는 수동적 공격(기밀성 침해) / 랜카드를 무차별 모드로 / 스위치 환경에선 MAC 플러딩·ARP 스푸핑을 곁들여야 가능

**정의 · 수동적 공격**

네트워크를 오가는 **패킷을 가로채 들여다보는** 행위. 데이터를 **바꾸지 않고 훔쳐보기만** 하므로 **수동적(Passive) 공격**이며 **기밀성**을 침해한다.**[무차별 모드(Promiscuous Mode)]** 랜카드는 원래 **자기 MAC 주소로 온 프레임만** 위로 올린다. 이 모드를 켜면 **자기 것이 아닌 프레임까지 전부** 받아들여 분석할 수 있다. 도구: **Wireshark·tcpdump**.
**탐지가 어렵다** — 조용히 듣기만 하므로 트래픽을 만들지 않는다.

**허브 vs 스위치 — 스위치에서 스니핑하는 법**

**허브**는 받은 프레임을 **모든 포트에 복사**하므로 무차별 모드만 켜면 바로 도청된다. **스위치**는 **목적지 포트로만** 보내므로 그냥은 안 된다. 그래서 다음 기법을 함께 쓴다.
- **MAC 플러딩(스위치 재밍)** — 가짜 MAC을 대량으로 보내 **MAC 테이블을 넘치게** 하면 스위치가 **허브처럼 모든 포트로 뿌린다**
- **ARP 스푸핑** — IP↔MAC을 속여 **트래픽이 공격자를 거쳐** 가게 한다(가장 대표적)
- **ARP 리다이렉트** — 자신이 **게이트웨이인 것처럼** 속인다
- **ICMP 리다이렉트** — 경로 변경 메시지를 위조해 우회시킨다
- **포트 미러링(SPAN) 악용** — 관리용 미러 포트를 이용

**스니퍼 탐지 방법**

- **ping 테스트** — **존재하지 않는 MAC**으로 ping을 보낸다. 정상 호스트는 무시하지만 **무차별 모드면 응답**한다
- **ARP 테스트** — 위조 ARP 요청에 반응하는지 확인
- **DNS 테스트** — 스니퍼가 IP를 이름으로 바꾸려 **역방향 DNS 조회**를 일으키는 것을 관찰
- **유인(Decoy)** — 가짜 계정·비밀번호를 흘려보내 **그것으로 접속을 시도**하는지 본다

**대응 — 암호화가 근본**

스니핑 자체를 완전히 막기는 어렵다. 그래서 **가로채도 못 읽게** 만드는 것이 정답이다.
- **암호화 통신** — **SSL/TLS(HTTPS)·SSH·VPN**. Telnet·FTP 같은 **평문 프로토콜 폐기**
- **스위치 사용** + **포트 보안**(포트당 MAC 수 제한)으로 MAC 플러딩 차단
- **정적 ARP**·**DAI**로 ARP 스푸핑 차단

> **시험 한줄정리:** 스니핑=**수동적** 공격(기밀성), 랜카드 **무차별 모드** / 허브=바로 가능, **스위치는 MAC 플러딩·ARP 스푸핑** 필요 / 탐지=**ping·ARP·DNS·유인** 테스트 / 대응=**암호화(SSL·SSH·VPN)**가 근본

_관련 개념: arpspoof · netdevice · hijacking_

## IP 스푸핑 — IP Spoofing

`네트워크 보안`  `출발지 IP 위조` `신뢰관계 악용` `r 계열 서비스` `순서번호 예측 필요` `인그레스 필터링`

**한줄:** 출발지 IP를 위조해 신원을 숨기거나 신뢰관계를 악용 / 응답이 공격자에게 안 오므로 순서번호 예측이 필요(blind) / 대응=인그레스 필터링·신뢰관계 제거

**정의 · 왜 가능한가**

IP 패킷의 **출발지 주소를 다른 IP로 위조**해 보내는 것. IP 프로토콜은 **출발지를 검증하지 않기** 때문에 원리적으로 막을 수 없다.**[핵심 제약]** 응답은 **위조한 IP의 주인에게** 가지 **공격자에게 오지 않는다**. 그래서 응답을 못 보고 하는 **블라인드(blind) 공격**이 되며, TCP라면 **순서번호를 예측**해야 연결을 이어갈 수 있다.

**어디에 쓰이나**

- **신뢰관계 악용** — 유닉스의 **r 계열 서비스**(`rlogin`·`rsh`·`rexec`)는 `.rhosts`·`/etc/hosts.equiv`에 등록된 **IP만 보고 비밀번호 없이** 접속을 허용한다 → **그 IP로 위조**하면 인증 통과(고전적 공격)
- **접근 제어 우회** — IP 기반 **ACL·방화벽 규칙**을 속인다
- **신원 은폐·추적 회피** — 공격 근원을 감춘다
- **반사·증폭 공격의 전제** — **스머프·DRDoS**는 출발지를 **피해자로** 위조하는 것이 핵심
- **Land Attack** — 출발지를 **목적지와 동일하게** 위조

**대응**

- **인그레스 필터링(Ingress Filtering)** — 외부에서 들어오는 패킷의 출발지가 **내부 IP로 위조**돼 있으면 차단. **이그레스 필터링**은 나가는 패킷의 출발지가 내부 대역이 맞는지 검사
- **uRPF** — 들어온 **경로가 그 출발지에 맞는지** 라우터가 역방향으로 검증
- **r 계열 서비스 제거** → **SSH**로 대체(IP가 아니라 **키·비밀번호로 인증**)
- **초기 순서번호(ISN) 난수화**로 예측 차단
- IP가 아닌 **암호학적 인증**에 의존하도록 설계

> **시험 한줄정리:** IP 스푸핑=**출발지 IP 위조**(IP는 출발지를 검증 안 함) / 응답이 안 와서 **블라인드** → **순서번호 예측** 필요 / 용도=**신뢰관계(r 서비스) 악용**·ACL 우회·**스머프/DRDoS 전제**·Land / 대응=**인그레스 필터링·uRPF·r서비스 제거·ISN 난수화**

_관련 개념: arpspoof · hijacking · dos_

## ARP 스푸핑 (ARP 캐시 포이즈닝) — ARP Spoofing / Cache Poisoning

`네트워크 보안`  `ARP에 인증 없음` `IP↔MAC 위조` `중간자(MITM)` `스위치에서도 스니핑` `정적 ARP·DAI`

**한줄:** ARP에 인증이 없다는 점을 악용해 IP↔MAC 매핑을 속임 / 피해자 ARP 캐시를 오염시켜 트래픽이 공격자를 거치게 함(중간자) / 대응=정적 ARP·DAI

**왜 통하나 — ARP의 구조적 결함**

ARP는 **인증이 전혀 없다**. “그 IP는 내 MAC이야”라는 응답이 오면 **요청한 적이 없어도 그대로 믿고** 캐시에 저장한다(gratuitous ARP). 설계 당시 **신뢰된 내부망**을 전제했기 때문이다.

**동작 원리**

- **1 위조 응답** — 피해자에게 “**게이트웨이 IP = 공격자 MAC**”, 게이트웨이에는 “**피해자 IP = 공격자 MAC**”

- **2 캐시 오염** — 양쪽 ARP 캐시가 **공격자 MAC**으로 바뀜

- **3 중간자** — 모든 트래픽이 **공격자를 거쳐** 흐름(MITM)

- **4 전달·조작** — 훔쳐보고 **그대로 넘겨줘** 눈치채지 못하게(안 넘기면 DoS)

**스위치 환경에서도 스니핑을 가능하게 만드는** 대표 기법이며, **세션 하이재킹·중간자 공격의 발판**이 된다.

**탐지**

`arp -a`로 ARP 캐시를 확인해 **서로 다른 IP가 같은 MAC**을 가리키면 의심한다(특히 **게이트웨이 MAC이 바뀐 경우**). 그 밖에 **ARP 응답이 비정상적으로 자주** 오가는지, 전용 탐지 도구(arpwatch)로 **MAC 변경 이력**을 감시한다.

**대응**

- **정적 ARP 등록** — `arp -s`로 **게이트웨이 MAC을 고정**(가장 확실하지만 관리 부담)
- **DAI(Dynamic ARP Inspection)** — 스위치가 **DHCP 스누핑 정보와 대조**해 위조 ARP를 차단
- **포트 보안**(포트당 MAC 제한), **VLAN 분리**로 피해 범위 축소
- **암호화 통신(HTTPS·SSH·VPN)** — 가로채도 **못 읽게**

> **시험 한줄정리:** ARP 스푸핑=**인증 없는 ARP**를 악용해 **IP↔MAC 위조** → 캐시 오염 → **중간자(MITM)** / **스위치에서도 스니핑** 가능하게 만드는 핵심 기법 / 탐지=`arp -a`에 **같은 MAC이 여러 IP** / 대응=**정적 ARP·DAI**·포트보안·암호화

_관련 개념: sniffing · netproto · hijacking_

## 세션 하이재킹 — Session Hijacking

`네트워크 보안`  `인증 이후를 노림` `순서번호 예측` `ACK 스톰` `세션 ID 탈취` `암호화·재발급`

**한줄:** 이미 인증된 세션을 가로채 그 사용자로 행세 / 인증 과정을 통째로 우회하므로 비밀번호가 강해도 소용없음 / TCP는 순서번호 예측, 웹은 세션 ID 탈취

**핵심 — 인증 '이후'를 노린다**

비밀번호를 깨는 게 아니라, **정상적으로 인증이 끝난 세션에 끼어드는** 공격이다.**[그래서 무서운 점]** **아무리 강한 비밀번호·MFA를 써도 무력화**된다. 인증은 이미 통과된 상태이기 때문이다. 이것이 세션 하이재킹의 가장 큰 특징으로 출제된다.

**TCP 세션 하이재킹**

- 스니핑이나 **순서번호 예측**으로 진행 중인 연결의 **순서번호·확인응답번호**를 알아낸다
- 그 값으로 **위조 패킷을 주입**해 서버가 공격자를 정상 클라이언트로 착각하게 만든다
- 원래 클라이언트와 서버의 순서번호가 **어긋나**, 서로 ACK를 주고받으며 **ACK 스톰(ACK Storm)**이 발생한다 → **탐지 단서**
**ARP 스푸핑과 결합**하면 중간자 위치를 확보해 훨씬 쉬워진다.

**웹 세션 하이재킹**

**세션 ID(쿠키)**를 훔치면 그대로 로그인된 상태가 된다.
- **스니핑** — 평문 HTTP 구간에서 쿠키 탈취
- **XSS** — `document.cookie`를 빼돌림
- **세션 고정(Session Fixation)** — 공격자가 정한 세션 ID를 쓰게 만든 뒤 그대로 사용
- 예측 가능한 세션 ID

**대응**

- **암호화** — **SSL/TLS·SSH·VPN**. 가로채도 순서번호·쿠키를 못 읽게(가장 근본)
- **ISN(초기 순서번호) 난수화** — 예측 차단
- **세션 ID**: 충분히 긴 난수, **로그인 성공 시 재발급**(세션 고정 대응), **타임아웃**, 쿠키에 **Secure·HttpOnly·SameSite**
- 비정상 **ACK 스톰·RST** 모니터링, 지속적 재인증

> **시험 한줄정리:** 세션 하이재킹=**인증 끝난 세션**을 가로챔 → **강한 비밀번호·MFA도 무력화** / TCP=**순서번호 예측**+위조 주입 → **ACK 스톰**이 단서 / 웹=**세션 ID 탈취**(스니핑·XSS·세션고정) / 대응=**암호화·ISN 난수화·세션ID 재발급·HttpOnly**

_관련 개념: arpspoof · cookiesession · ipspoof_

## 원격 접속 공격 · 대응 — Remote Access Attacks

`네트워크 보안`  `Telnet 23·SSH 22·RDP 3389` `무차별 대입·크리덴셜 스터핑` `평문 프로토콜 도청` `랜섬웨어 초기 침투` `키 인증·IP 제한·MFA`

**한줄:** 인터넷에 열린 원격 관리 포트를 노림(Telnet·SSH·RDP·VNC) / 무차별 대입·유출 계정 재사용·평문 도청·취약점 / 성공하면 곧바로 시스템 장악

**표적이 되는 서비스**

**Telnet(23) · SSH(22) · RDP(3389) · VNC(5900) · FTP(21)** 등 **원격에서 시스템을 조작하는 통로**가 대상이다. 이런 포트가 인터넷에 열려 있으면 **자동화된 봇이 24시간 로그인을 시도**한다.

**동작 원리 · 특징**

- **무차별 대입·사전 공격** — 약한 비밀번호를 자동으로 반복 시도(가장 흔함)
- **크리덴셜 스터핑** — 다른 곳에서 **유출된 계정**을 그대로 대입(비밀번호 재사용을 노림)
- **평문 프로토콜 도청** — **Telnet·FTP는 ID·비밀번호가 평문**이라 스니핑 한 번이면 끝
- **취약점 익스플로잇** — 원격 서비스의 원격 코드 실행 취약점
- **중간자·세션 하이재킹** — 인증된 세션을 가로챔
**[특징]** 성공하면 **곧바로 시스템 제어권**이 넘어간다(권한 상승을 거칠 필요도 없이). 특히 **RDP는 랜섬웨어의 대표적인 초기 침투 경로**다.

**대응 (출제 포인트)**

- **Telnet 폐기 → SSH 사용**(암호화). FTP도 **SFTP·FTPS**로
- **키 기반 인증**으로 전환하고 **비밀번호 인증 비활성화**, **root 직접 로그인 금지**(`PermitRootLogin no`)
- **접근 IP 제한** — 방화벽·ACL·**TCP Wrapper**(`hosts.allow`/`hosts.deny`)
- **기본 포트 변경**(자동 스캔 회피 — 보조 수단일 뿐)
- **계정 잠금·시도 횟수 제한**(fail2ban 등), **MFA** 적용
- **VPN·점프 서버(배스천 호스트)를 거치게** 하고 인터넷 직접 노출을 없앤다 ← 가장 확실
- **로그 감사**(`/var/log/secure`·`btmp`로 실패 로그인 확인)

> **시험 한줄정리:** 원격 접속 공격=**Telnet 23·SSH 22·RDP 3389·VNC 5900** 표적 / 수법=**무차별 대입·크리덴셜 스터핑·평문 도청(Telnet·FTP)·취약점** / 성공 시 **즉시 장악**(RDP=랜섬웨어 초기 침투) / 대응=**SSH·키 인증·root 로그인 금지·IP 제한·계정 잠금·MFA·VPN 경유**

_관련 개념: hijacking · sniffing · passwdfile_
