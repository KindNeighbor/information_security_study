# 네트워크 보안 기술 — 침입차단·침입탐지

> 자동 생성 — 원본은 `cards/firewall.js`. 직접 수정 금지.

## 침입차단 시스템 (방화벽) · 유형 — Firewall Types

`네트워크 보안`  `패킷필터링 3·4계층` `애플리케이션 게이트웨이 7계층` `회선 게이트웨이 5계층` `상태기반=현재 주류` `혼합형`

**한줄:** 내부·외부 경계에서 정책에 따라 트래픽을 허용·차단 / 패킷필터링(3·4)·애플리케이션 게이트웨이(7)·회선 게이트웨이(5)·상태기반 검사·혼합형

**정의 · 기본 원칙**

신뢰하는 내부망과 신뢰할 수 없는 외부망 **경계**에 두고, **정해진 정책(규칙)에 따라 트래픽을 허용·차단**하는 시스템.**[기본 정책]** **Deny All(모두 차단) 후 필요한 것만 허용**하는 것이 원칙이다(화이트리스트). 반대로 Permit All은 위험하다.
**한계**: 경계를 지나가는 것만 본다 → **내부자 공격·우회 경로(모뎀·USB)·암호화된 악성 트래픽**은 막지 못한다.

**① 패킷 필터링 (3·4계층)**

**IP 주소·포트 번호·프로토콜·TCP 플래그**만 보고 판단한다(라우터 ACL이 대표).
- **장점**: **속도가 빠르고** 부하가 적으며 구현이 단순, 사용자에게 투명
- **단점**: **데이터(페이로드) 내용을 못 본다**, **연결 상태를 기억하지 않는다**, 로깅·**사용자 인증이 어렵다**, IP 스푸핑에 취약

**② 애플리케이션 게이트웨이 · ③ 회선 게이트웨이**

- **애플리케이션 게이트웨이 (7계층·프록시)**: 서비스마다 **프록시 데몬**을 두고 **내용까지 검사**. **강력한 인증·상세 로깅** 가능.
**단점**: **느리고** 서비스마다 **프록시가 필요**해 확장성이 떨어진다.

- **회선 게이트웨이 (5계층·세션)**: 클라이언트와 프록시 사이에 **가상 회선**을 만들어 중계(**SOCKS**가 대표). **응용에 독립적**이라 여러 서비스를 한 번에 지원.
**단점**: 클라이언트에 **전용(수정된) 프로그램**이 필요.

**④ 상태 기반 패킷 검사 (현재 주류)**

**Stateful Inspection** — 패킷 하나만 보지 않고 **연결(세션)의 상태를 테이블로 기억**해, 그 문맥에 맞는 패킷인지 판단한다.**[왜 좋은가]** 내가 요청해서 **돌아오는 응답**인지, 아니면 **난데없이 들어온 패킷**인지 구분할 수 있다 → 패킷 필터링의 최대 약점을 해결. **속도와 보안을 절충**해 현재 방화벽의 표준이 됐다.
**⑤ 혼합형(Hybrid)** — 위 방식들을 **조합**해 장점을 취한 형태.

> **시험 한줄정리:** 방화벽=경계에서 정책대로 허용·차단(**Deny All 후 필요한 것만**) / **패킷필터링(3·4계층·빠름·내용 못봄)** · **애플리케이션 게이트웨이(7계층·프록시·정밀하나 느림)** · **회선 게이트웨이(5계층·SOCKS)** · **상태기반 검사(세션 상태 기억·현재 주류)** · 혼합형 / 한계=내부자·우회경로

_관련 개념: fwarch · ids · netdevice_

## 방화벽 구축 형태 — Firewall Architectures

`네트워크 보안`  `스크리닝 라우터` `듀얼 홈드 호스트` `스크린드 호스트` `스크린드 서브넷=DMZ` `베스천 호스트`

**한줄:** 스크리닝 라우터(라우터만) → 듀얼 홈드 호스트(NIC 2개·라우팅 차단) → 스크린드 호스트(라우터+베스천) → 스크린드 서브넷(라우터 2개·DMZ, 가장 안전)

**베스천 호스트 (공통 개념)**

**베스천 호스트(Bastion Host)** — 내부망을 지키는 **요새**라는 뜻. 외부에 직접 노출되는 **최전방 방어 호스트**로, 불필요한 서비스·계정을 모두 제거하고 **철저히 강화(하드닝)**한 뒤 로그를 집중 감시한다. 아래 구조들의 핵심 부품이다.

**구축 형태 4가지 (안전도 순)**

- **1 스크리닝 라우터** — **라우터가 패킷 필터링**만 수행. **저렴·빠름**. 3·4계층만 보고 **로깅·세밀한 제어가 약함**.

- **2 듀얼 홈드 호스트** — **네트워크 카드(NIC) 2개**(내부/외부)를 단 호스트. **라우팅 기능을 꺼서** 직접 통과가 불가능 → **반드시 프록시를 거쳐야** 한다.

- **3 스크린드 호스트** — **스크리닝 라우터 + 베스천 호스트** 조합. 라우터가 1차, 베스천이 2차 → **2단계 방어**. 라우터가 뚫리면 내부가 노출.

- **4 스크린드 서브넷** — **라우터 2개 사이에 완충지대(DMZ)**를 두고 그 안에 베스천 호스트를 배치. **가장 안전**하지만 **비용·구축이 복잡하고 느리다**.

**DMZ — 왜 필요한가**

**DMZ(비무장지대)**는 외부에 공개해야 하는 서버(**웹·메일·DNS**)를 두는 **완충 구역**이다. 이들을 내부망에 두면 **서버가 뚫렸을 때 내부 전체가 노출**되므로, **외부↔DMZ는 허용하되 DMZ↔내부는 엄격히 제한**한다. 스크린드 서브넷이 바로 이 구조다.

> **시험 한줄정리:** **베스천 호스트**=강화한 최전방 요새 / **스크리닝 라우터**(라우터만·저렴) → **듀얼 홈드**(NIC 2개·**라우팅 차단**) → **스크린드 호스트**(라우터+베스천·2단계) → **스크린드 서브넷**(라우터 2개·**DMZ**·**가장 안전**·복잡) / DMZ=공개 서버 완충지대

_관련 개념: firewall · ids · subnet_

## 침입탐지 시스템 (IDS) · 탐지 기법 — Intrusion Detection System

`네트워크 보안`  `HIDS vs NIDS` `지식기반=오용탐지` `행위기반=이상탐지` `오탐 vs 미탐` `제로데이는 행위기반만`

**한줄:** 침입 시도를 탐지해 경보 / 수집원별 HIDS·NIDS / 탐지법 지식기반(시그니처, 오탐 낮음·제로데이 못잡음) vs 행위기반(이상, 제로데이 가능·오탐 높음)

**정의 · 동작 순서**

네트워크나 시스템의 활동을 감시해 **침입 시도를 탐지하고 관리자에게 경보**하는 시스템. **탐지·경보가 본분**이고 **차단은 IPS의 몫**이다.
동작: **데이터 수집 → 데이터 가공·축약 → 분석·탐지 → 보고·대응**.

**① 데이터 수집원에 따른 분류**

- **HIDS (호스트 기반)**: 특정 서버에 설치해 **시스템 로그·파일 무결성·프로세스**를 감시.
➕ **암호화된 트래픽도 복호화 후** 볼 수 있고, 내부자 행위 탐지에 강함
➖ **서버마다 설치·부하**, 그 호스트만 봄

- **NIDS (네트워크 기반)**: 네트워크 구간의 **패킷**을 수집해 감시(스니핑 방식).
➕ **여러 시스템을 한 번에**, 대상 시스템에 부하 없음
➖ **암호화된 트래픽은 못 봄**, 고속 구간에서 **패킷 누락**

**② 탐지 기법 — 최다 출제 지점**

- **지식 기반 = 오용 탐지 (Misuse · Signature)**: **알려진 공격 패턴(시그니처)**과 비교해 일치하면 경보.
➕ **오탐(False Positive)이 낮고** 빠르며 결과가 명확
➖ **알려지지 않은 공격(제로데이)을 못 잡는다** → **미탐이 높다**, 시그니처를 계속 갱신해야

- **행위 기반 = 이상 탐지 (Anomaly)**: **평소 정상 상태(프로파일)**를 만들어 두고 **통계적 편차**가 크면 경보.
➕ **알려지지 않은 새로운 공격도 탐지 가능**
➖ **오탐(False Positive)이 높고** 정상 프로파일 학습이 필요

**[용어 짝]** **오탐(False Positive)** = 정상을 공격이라고 **잘못 경보** · **미탐(False Negative)** = 공격을 정상으로 보고 **놓침**. “제로데이를 탐지할 수 있는 것은?” → **행위 기반**이 정답.

**한계**

IDS는 **탐지만** 하므로 경보 후 **사람이 대응**해야 한다(그래서 IPS가 나옴). **오탐이 많으면 경보 피로**로 진짜 공격을 놓치게 되고, **암호화 트래픽 증가**로 NIDS의 가시성이 계속 줄고 있다.

> **시험 한줄정리:** IDS=탐지·경보(차단은 IPS) / 수집원 **HIDS**(호스트·암호화도 봄·부하) vs **NIDS**(패킷·광범위·암호화 못봄) / 탐지법 **지식기반=오용(시그니처, 오탐↓·제로데이 X)** vs **행위기반=이상(프로파일, 제로데이 O·오탐↑)** / 오탐=정상을 공격으로, 미탐=공격을 놓침

_관련 개념: snort · ips · firewall_

## Snort · Suricata · YARA — Snort Rules · Suricata · YARA

`네트워크 보안`  `룰 헤더+룰 옵션` `msg·content·sid·rev` `nocase·offset·depth` `수리카타=멀티스레드` `YARA=악성코드 식별`

**한줄:** Snort=오픈소스 룰 기반 NIDS/IPS(룰 헤더+옵션) / Suricata=멀티스레드로 고속, Snort 룰 호환 / YARA는 네트워크가 아니라 파일·메모리의 악성코드 식별용

**Snort — 룰 구조**

대표적인 **오픈소스 NIDS/IPS**. 탐지 규칙(룰)은 **룰 헤더 + 룰 옵션**으로 구성된다.

```
alert tcp any any -> 192.168.0.0/24 80 (msg:"Web Attack"; content:"/etc/passwd"; nocase; sid:1000001; rev:1;)
└──────── 룰 헤더 ────────┘ └──────────── 룰 옵션 ────────────┘
```

**룰 헤더** = `동작 프로토콜 출발지IP 출발지포트 -> 목적지IP 목적지포트`
**동작(action)**: **alert**(경보+로그) · **log**(로그만) · **pass**(무시) · **drop**(차단+로그) · **reject**(차단+거부응답) · sdrop(조용히 차단)

**Snort 주요 옵션 (출제 포인트)**

- **msg** — 경보에 출력할 **메시지**
- **content** — **페이로드에서 찾을 문자열·바이트**(핵심 옵션)
- **nocase** — content 검사 시 **대소문자 무시**
- **offset / depth** — 검사 **시작 위치** / 검사할 **범위**
- **sid** — 룰의 **고유 번호**(사용자 정의는 1,000,000 이상) · **rev** — 룰 **개정 번호**
- **flags** — **TCP 플래그** 조건(예: `flags:S;` = SYN)
- **threshold** — 임계치(횟수·시간)로 과도한 경보 억제
- **classtype / priority** — 공격 분류·우선순위 · **pcre** — 정규식 검사

**Suricata · YARA — 무엇이 다른가**

- **Suricata (수리카타)**: 오픈소스 IDS/IPS. **멀티스레드**로 동작해 **고속·대용량 처리**에 유리(Snort의 대표적 한계를 보완). **Snort 룰과 호환**되고 파일 추출·TLS 로깅 등 기능이 풍부.

- **YARA**: **목적이 다르다** — 네트워크 패킷이 아니라 **파일·메모리**를 대상으로 **악성코드를 식별·분류**하는 룰 엔진. 문자열·바이트 패턴으로 “이 파일이 어떤 악성코드 계열인가”를 판단한다. 룰은 **meta·strings·condition** 세 부분.

**정리**: **Snort·Suricata = 네트워크 트래픽**, **YARA = 파일·악성코드**.

> **시험 한줄정리:** Snort 룰 = **룰 헤더**(`action proto 출발지 -> 목적지`) + **룰 옵션** / 옵션 **msg·content·nocase·offset/depth·sid·rev·flags·threshold·pcre** / **Suricata=멀티스레드 고속·Snort 룰 호환** / **YARA=파일·메모리의 악성코드 식별**(네트워크 아님)

_관련 개념: ids · ips · sectools_

## 침입대응 시스템 (IPS) · 허니팟 — IPS · Honeypot

`네트워크 보안`  `IDS=탐지 IPS=차단` `인라인 vs 미러링` `오탐 시 정상 차단` `허니팟=미끼` `허니넷`

**한줄:** IPS=탐지에서 그치지 않고 실시간 차단(인라인 배치) / 허니팟=일부러 취약하게 만든 미끼로 공격을 유인·분석하고 실제 시스템을 보호

**IDS vs IPS (비교로 출제)**

- **IDS**: **탐지·경보**까지. 트래픽 **복사본**을 보는 **미러링(수동)** 배치라 통신에 영향이 없다. 대응은 **사람이**.

- **IPS**: **탐지 + 실시간 차단**. 트래픽이 **통과하는 경로에 놓는 인라인** 배치.
➖ **오탐이 나면 정상 트래픽까지 차단**되고, 장비 장애·지연이 **통신 전체에 영향**을 준다.

**핵심 한 줄**: **IDS는 CCTV, IPS는 자동문 잠금장치.**

**허니팟 (Honeypot)**

**일부러 취약하게 만들어 공격자를 끌어들이는 미끼 시스템**. 실제 자산이 아니므로 **여기 들어온 트래픽은 곧 공격**으로 볼 수 있다(오탐이 거의 없다).
- **목적**: 공격 **유인·지연**(실제 시스템에서 시선 돌리기), 공격 **기법·도구 수집·분석**, 조기 경보
- **갖춰야 할 조건**: **쉽게 발견·접근**될 수 있어야 하고, 실제처럼 **시스템 구성요소를 갖춰야** 하며, **지속적으로 감시·기록**되어야 한다
- **허니넷(Honeynet)** — 허니팟 여러 대로 구성한 **네트워크**

**허니팟의 위험**

공격자가 허니팟을 **장악해 다른 시스템을 공격하는 발판(경유지)**으로 쓸 수 있다. 그래서 반드시 **실제 내부망과 격리**하고, **나가는 트래픽을 통제**하며 상시 모니터링해야 한다. 법적 문제(유인 논란)도 고려 대상이다.

> **시험 한줄정리:** **IDS=탐지·경보(미러링·수동)** vs **IPS=탐지+실시간 차단(인라인)** — IPS는 **오탐 시 정상 트래픽까지 차단** / **허니팟**=미끼로 유인·지연·기법 수집(들어오면 곧 공격), 조건=**쉽게 발견·실제처럼·지속 감시**, **허니넷**=허니팟 네트워크 / 위험=경유지 악용 → **격리**

_관련 개념: ids · snort · firewall_
