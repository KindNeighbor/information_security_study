## 암호화의 개요 — 과정과 분류 — Cryptography Basics

`정보보안 일반`  `평문·암호문·키` `커크호프의 원리` `혼돈과 확산` `치환 vs 전치` `블록 vs 스트림`

**한줄:** 암호화=평문을 키로 암호문으로 바꾸는 것, 복호화는 그 역 / 커크호프의 원리에 따라 알고리즘은 공개하고 키만 숨긴다 / 기법은 치환·전치, 대칭·비대칭, 블록·스트림으로 갈린다

**기본 용어와 과정**

- **평문(Plaintext, P)** — 원래 메시지 / **암호문(Ciphertext, C)** — 변환된 메시지
- **암호화(Encryption)** — **C = E(K, P)** / **복호화(Decryption)** — **P = D(K, C)**
- **키(Key)** — 변환을 결정하는 비밀 값. **암호 강도는 알고리즘이 아니라 키에 달려 있다**
- **암호학(Cryptography)**=암호를 만드는 학문 / **암호분석(Cryptanalysis)**=깨는 학문. 둘을 합쳐 **암호론(Cryptology)**
**[커크호프의 원리 (Kerckhoffs' Principle)]** **"암호 알고리즘은 공개되어도 키만 안전하면 된다."** 알고리즘을 숨겨서 안전을 얻으려는 것을 **은닉에 의한 보안(Security by Obscurity)**이라 하며 **나쁜 설계**로 본다. AES·RSA가 모두 공개된 이유.

**혼돈과 확산 (섀넌의 두 원리)**

- **혼돈 (Confusion)**: **암호문과 키의 관계**를 복잡하게 만든다. 암호문을 봐도 **키를 유추할 수 없게**. 주로 **치환(S-box)**으로 구현

- **확산 (Diffusion)**: **평문의 통계적 성질**을 흩뜨린다. **평문 한 비트만 바뀌어도 암호문 절반이 바뀌게**(눈사태 효과). 주로 **전치·순열(P-box)**로 구현

**[연결]** 블록 암호는 **치환과 전치를 여러 라운드 반복**해 이 둘을 달성한다. **눈사태 효과(Avalanche Effect)**는 좋은 암호·해시의 필수 성질.

**암호 기법의 분류 (3가지 축)**

- **① 변환 방식 — 치환 vs 전치**: **치환(Substitution)**: 글자를 **다른 글자로 바꾼다**(시저·비제네르)
**전치(Transposition)**: 글자는 그대로 두고 **순서만 섞는다**(스키테일)
→ 현대 암호는 **둘을 섞어 반복**(Product Cipher, 곱 암호)

- **② 키 방식 — 대칭 vs 비대칭**: **대칭키**: 암·복호화 키가 같다(빠름) / **비대칭(공개키)**: 키가 한 쌍(느림, 키 분배 해결)
→ 상세는 PART 04 「대칭키 암호」·「공개키 암호」 카드

- **③ 처리 단위 — 블록 vs 스트림**: **블록**: 일정 길이로 잘라 처리 / **스트림**: 비트 단위로 키 스트림과 XOR

- **대칭키·비대칭키·해시**를 **암호 기술의 3대 축**으로 묶어 출제하기도 한다(해시는 **키가 없고 복호화도 없다**)

> **시험 한줄정리:** **C=E(K,P) / P=D(K,C)**, 강도는 **키**에 달림 / **커크호프의 원리 = 알고리즘은 공개, 키만 비밀**(은닉에 의한 보안은 나쁜 설계) / **혼돈=암호문·키 관계 복잡(치환·S박스)**, **확산=평문 성질 흩뜨림(전치·P박스, 눈사태 효과)** / 분류 **치환·전치 / 대칭·비대칭 / 블록·스트림**

_관련 개념: classic · blockmode · symkey_

## 고전 암호 — 시저 · 다중 치환 · 힐 암호 — Classical Ciphers

`정보보안 일반`  `시저=3칸 이동` `단일 치환=빈도분석에 취약` `비제네르=다중 치환` `힐=행렬 곱` `일회용 패드=완전 비밀`

**한줄:** 시저는 알파벳을 일정 칸 미는 단일 치환으로 빈도분석에 바로 뚫린다 / 비제네르 같은 다중 치환은 같은 글자가 매번 다르게 암호화되고, 힐 암호는 여러 글자를 행렬로 한꺼번에 바꾼다

**시저 암호와 단일 치환**

**시저 암호(Caesar Cipher)** — 알파벳을 **일정 칸(k)만큼 이동**시키는 가장 단순한 치환 암호.

```
암호화:  C = (P + k) mod 26
복호화:  P = (C − k) mod 26

k=3일 때   A→D,  B→E,  HELLO → KHOOR
```

- 키가 **26개(사실상 25개)**뿐이라 **전수조사(Brute Force)로 즉시 해독**
- **단일 치환 암호(Monoalphabetic)** — 대응표를 임의로 짜면 키 공간이 **26!**로 커지지만, **같은 평문 글자가 늘 같은 암호문 글자**가 되므로 **빈도 분석(Frequency Analysis)**에 그대로 뚫린다(영어에서 가장 흔한 글자는 **E**)

**다중 치환 암호 (Polyalphabetic)**

빈도 분석을 막으려고 **여러 개의 치환표를 번갈아** 쓰는 방식. **같은 평문 글자가 위치에 따라 다른 암호문**이 된다.
- **비제네르(Vigenère) 암호** — 대표적인 다중 치환. **키워드를 반복**해 글자마다 다른 이동량을 적용

```
평문  A T T A C K
키    L E M O N L      (키워드 LEMON 반복)
암호  L X F O P V      C = (P + K) mod 26
```

수백 년간 "해독 불가"로 불렸으나 **키 길이를 알아내면(카시스키 검사·index of coincidence)** 여러 개의 시저 암호로 쪼개져 풀린다
- **플레이페어(Playfair)** — **2글자(다이그램) 단위**로 5×5 표를 이용해 치환
- **에니그마** — 회전자로 매 글자마다 치환표가 바뀌는 기계식 다중 치환

**힐 암호 (Hill Cipher)와 전치 암호**

- **힐 암호 (Hill Cipher)**: **여러 글자를 묶어 행렬 곱**으로 한꺼번에 암호화하는 **다중 문자(Polygraphic) 치환**.
**C = K · P mod 26**, 복호화는 **P = K⁻¹ · C mod 26**(키 행렬의 **역행렬**이 존재해야 함)
장점 **글자 하나가 여러 글자에 영향을 줘 빈도 분석에 강하다**
단점 **선형 변환이라 기지 평문 공격(Known Plaintext)에 취약** — 평문·암호문 쌍이 몇 개 있으면 키 행렬이 계산된다

- **전치 암호 (Transposition)**: 글자를 **바꾸지 않고 순서만 재배열**.
**스키테일(Scytale)** — 막대에 띠를 감아 읽는 고대 방식
**열 전치(Columnar)** — 표에 채워 넣고 열 순서를 바꿔 읽는다
특징: **글자 빈도가 그대로 보존**되므로 빈도 분포만 보면 "전치 암호구나"를 알 수 있다

**[일회용 패드 (One-Time Pad)]** 평문과 **같은 길이의 진짜 난수 키**를 **한 번만** 써서 XOR하면 **이론적으로 절대 해독 불가(완전 비밀성, Perfect Secrecy)**가 증명된다. 다만 **키 길이·키 분배·재사용 금지** 때문에 현실에서 쓰기 어렵다.

> **시험 한줄정리:** **시저 = C=(P+k) mod 26**, 키 25개라 전수조사로 즉사 / **단일 치환=빈도 분석에 취약** → **다중 치환(비제네르, 키워드 반복)**으로 대응하나 **키 길이를 알면 풀림** / **힐 암호=행렬 곱(역행렬로 복호화), 기지 평문 공격에 취약** / **전치=순서만 섞어 빈도가 보존됨** / **일회용 패드만 완전 비밀성 증명**

_관련 개념: cryptobasic · cryptanalysis · symkey_

## 블록 암호 구조와 운용 모드 (ECB·CBC·CFB·OFB·CTR) — Block Cipher Structure & Modes of Operation

`정보보안 일반`  `Feistel vs SPN` `ECB=같은 평문·같은 암호문` `CBC=IV와 XOR·체이닝` `CTR=병렬 가능` `OFB·CTR은 스트림처럼`

**한줄:** 블록 암호 구조는 Feistel(암복호화 구조 동일)과 SPN(병렬·빠름)으로 나뉜다 / 운용 모드 중 ECB는 패턴이 드러나 금지, CBC는 IV와 연쇄, CFB·OFB·CTR은 스트림처럼 동작하며 CTR만 병렬 처리가 된다

**블록 암호의 두 구조 — Feistel vs SPN**

- **Feistel 구조**: 블록을 **좌·우 절반으로 나눠** 한쪽에만 함수를 적용하고 **XOR 후 자리를 바꾸는** 것을 반복.
최대 장점 = **암호화와 복호화 구조가 같다**(라운드 키만 역순). 그래서 **구현이 간단**하고, 라운드 함수가 **역함수일 필요가 없다**
단점 **한 라운드에 절반만 처리**해 라운드 수가 많이 필요
예: **DES·3DES·SEED·Blowfish·RC5**

- **SPN 구조 (Substitution-Permutation Network)**: **블록 전체**에 **치환(S-box)과 순열(P-box)**을 반복 적용.
장점 **한 라운드에 전체를 처리해 빠르고 병렬화에 유리**, 적은 라운드로 충분
단점 **복호화를 위해 각 단계의 역함수가 따로 필요**해 구현이 복잡
예: **AES·ARIA·IDEA(변형)**

**[암기]** **Feistel = DES·3DES·SEED**, **SPN = AES·ARIA**. 짝을 바꿔 내는 문항이 흔하다.

**운용 모드 5가지 (표로 통째 출제)**

- **ECB (Electronic Code Book) — 전자 부호표**: 각 블록을 **독립적으로** 암호화. 구조가 가장 단순하고 **병렬 처리 가능**.
**치명적 결함: 같은 평문 블록 → 같은 암호문 블록**이라 **패턴이 그대로 드러난다**(펭귄 이미지 예시). **실무 사용 금지**

- **CBC (Cipher Block Chaining) — 암호 블록 연쇄**: 평문 블록을 **앞 블록의 암호문과 XOR**한 뒤 암호화. 첫 블록은 **IV(초기화 벡터)**와 XOR.
**가장 널리 쓰인 표준 모드**. **암호화는 순차적(병렬 불가)**, **복호화는 병렬 가능**
주의 **IV는 매번 달라야** 하고, **한 블록이 깨지면 그 블록과 다음 블록에 영향**(오류 전파 2블록)

- **CFB (Cipher FeedBack) — 암호 피드백**: **앞의 암호문을 암호화**해 만든 값과 평문을 XOR. **블록 암호를 스트림처럼** 쓴다.
**패딩이 필요 없다**. 암호화는 순차적, **복호화도 블록 암호의 "암호화" 함수만 사용**

- **OFB (Output FeedBack) — 출력 피드백**: **암호화 출력을 다시 입력으로** 넣어 **키 스트림을 미리 생성**하고 평문과 XOR.
키 스트림이 **평문·암호문과 무관**해 **미리 계산 가능**, **오류가 전파되지 않는다**(해당 비트만 손상) → **음성·영상 등 실시간 통신**에 적합

- **CTR (CounTeR) — 카운터**: **1씩 증가하는 카운터(+논스)**를 암호화해 키 스트림을 만들고 평문과 XOR.
**암호화·복호화 모두 완전 병렬 처리 가능**하고 **임의 블록에 바로 접근**할 수 있어 **현대에 가장 선호**. **카운터를 재사용하면 치명적**
인증까지 결합한 것이 **GCM(Galois/Counter Mode)**

**모드 비교 핵심 정리**

- **패딩이 필요한 모드** = **ECB·CBC**(블록 단위) / **필요 없는 모드** = **CFB·OFB·CTR**(스트림처럼 동작)
- **병렬 처리** — 암호화까지 병렬 되는 것은 **ECB·CTR**뿐. CBC·CFB는 **복호화만** 병렬 가능, OFB는 키 스트림 생성이 순차
- **오류 전파** — **OFB·CTR은 전파 없음**(해당 비트만), CBC·CFB는 **다음 블록까지**, ECB는 **그 블록만**
- **IV/논스 필요** — ECB만 필요 없다. 나머지는 모두 필요하며 **재사용하면 안전성이 무너진다**
- 기억법: **"ECB는 쓰지 마라, CBC는 연쇄, CTR은 병렬"** 세 문장이면 대부분의 문항이 풀린다

> **시험 한줄정리:** 구조 **Feistel(암·복호화 구조 동일, DES·SEED)** vs **SPN(전체 처리·빠름, AES·ARIA)** / 모드 **ECB=독립·패턴 노출로 금지**, **CBC=IV와 XOR 연쇄(복호화만 병렬)**, **CFB=암호문 피드백**, **OFB=키스트림 사전 생성·오류 전파 없음**, **CTR=카운터·완전 병렬(GCM의 토대)** / 패딩 필요는 **ECB·CBC**만

_관련 개념: symalg · symkey · cryptobasic_

## 블록 암호 알고리즘 상세 — DES · IDEA · RC5 · AES · SEED — DES / IDEA / RC5 / AES / SEED

`정보보안 일반`  `DES=64블록·56키·16라운드` `3DES=EDE` `IDEA=128키·PGP` `RC5=가변 파라미터` `AES=SPN·10/12/14라운드`

**한줄:** DES는 64비트 블록·56비트 키·Feistel 16라운드로 지금은 취약하고, 3DES(EDE)로 연명하다 AES가 표준이 됐다 / IDEA는 PGP에, RC5는 파라미터가 모두 가변인 것이 특징

**DES — 구조와 암·복호화 과정**

**DES(Data Encryption Standard)** — 1977년 미국 표준. **블록 64비트 · 키 56비트(패리티 8비트 포함하면 64) · Feistel 16라운드**.① 초기 순열 (IP)64비트 평문의 순서를 정해진 표대로 섞는다(보안 효과는 없고 하드웨어 편의용)
→
② 좌·우 32비트 분할L0, R0로 나눈다
→
③ 16라운드 반복**Lᵢ = Rᵢ₋₁**, **Rᵢ = Lᵢ₋₁ ⊕ f(Rᵢ₋₁, Kᵢ)** — f 안에서 **확장(32→48) → 라운드키 XOR → S박스 8개(48→32) → 순열 P**
→
④ 좌우 교환 후 최종 순열 (IP⁻¹)암호문 64비트 완성

- **복호화 = 같은 구조에 라운드 키만 K16→K1 역순**으로 넣으면 끝(Feistel의 최대 장점)
- **S박스(Substitution Box)**가 DES의 **유일한 비선형 요소**이자 보안의 핵심. 여기서 **혼돈**이 발생
- **취약점** — **키가 56비트뿐**이라 전수조사로 깨진다(1998년 56시간 만에 해독). **약한 키(Weak Key)**도 존재
- **3DES** — **EDE 방식(암호화→복호화→암호화)**으로 3번 적용. 키 2개면 112비트, 3개면 168비트 강도. **호환성 때문에 EDE**를 쓴다(키를 모두 같게 하면 **단일 DES와 동일**해져 하위 호환). 단점은 **3배 느림**

**AES · SEED**

- **AES (Advanced Encryption Standard)**: 2001년 DES를 대체한 **현재 표준**. 공모전에서 뽑힌 **Rijndael**(레인달) 알고리즘.
**블록 128비트 고정**, 키 **128 / 192 / 256비트** → 라운드 **10 / 12 / 14**
**SPN 구조**. 한 라운드 = **SubBytes(치환) → ShiftRows(행 이동) → MixColumns(열 섞기) → AddRoundKey(키 XOR)** (**마지막 라운드에는 MixColumns가 없다**)

- **SEED**: **KISA와 ETRI**가 개발한 **국내 표준**(1999). **블록 128비트**, 키 **128/256비트**, **Feistel 16라운드**.
전자상거래·금융에서 널리 쓰였다. 국제 표준(ISO/IEC, IETF)에도 등록

**IDEA · RC5 · 기타**

- **IDEA(International Data Encryption Algorithm)** — 스위스에서 개발. **블록 64비트 · 키 128비트 · 8.5라운드**. **XOR · 덧셈 · 곱셈**이라는 **서로 다른 세 연산을 섞는** 것이 특징. **PGP에 채택**된 것으로 유명. 특허 때문에 확산이 제한됐다
- **RC5** — 론 리베스트(RSA의 R) 설계. **블록 크기·키 길이·라운드 수가 모두 가변**인 것이 최대 특징. **데이터 종속 회전(Data-dependent rotation)**을 사용하고 구조가 매우 단순하다. 후속이 **RC6**(AES 최종 후보)
- **Blowfish / Twofish** — 슈나이어 설계, 특허 없이 공개 / **Skipjack** — 미 NSA, 클리퍼 칩
- **혼합(하이브리드) 암호화** — **데이터는 빠른 대칭키로**, **그 대칭키만 공개키로** 암호화해 함께 보낸다. **전자봉투(Digital Envelope)**가 이것이며 **SSL/TLS·PGP·SET**가 모두 이 방식

> **시험 한줄정리:** **DES=64블록·56키·Feistel 16라운드**, **Rᵢ=Lᵢ₋₁⊕f(Rᵢ₋₁,Kᵢ)**, **복호화는 라운드 키 역순**, **S박스가 유일한 비선형 요소** / **3DES=EDE(암→복→암)** / **AES=Rijndael·128블록·키128/192/256→라운드10/12/14·SPN(SubBytes·ShiftRows·MixColumns·AddRoundKey, 마지막엔 MixColumns 없음)** / **IDEA=64블록·128키·PGP**, **RC5=블록·키·라운드 모두 가변**, **SEED=국내 128비트 Feistel**

_관련 개념: blockmode · symkey · dhrsa_

## 암호 분석 방법의 종류 — Cryptanalysis

`정보보안 일반`  `암호문 단독·기지 평문` `선택 평문·선택 암호문` `차분·선형 분석` `부채널 공격` `중간 만남 공격`

**한줄:** 공격자가 무엇을 가졌느냐로 암호문 단독→기지 평문→선택 평문→선택 암호문 순으로 공격이 강해진다 / 기법으로는 전수조사·차분 분석·선형 분석·부채널 공격이 대표적

**가진 정보에 따른 4분류 (순서째로 출제)**

① 암호문 단독 공격 (COA, Ciphertext Only)**암호문만** 가지고 분석. 공격자에게 **가장 불리**하지만 **가장 현실적**. 빈도 분석이 여기
→
② 기지(알려진) 평문 공격 (KPA, Known Plaintext)**평문–암호문 쌍을 일부 알고 있다**. 메일 머리말·파일 헤더처럼 예측 가능한 부분을 이용
→
③ 선택 평문 공격 (CPA, Chosen Plaintext)**원하는 평문을 넣어 암호문을 얻을 수 있다**. 암호화 장치에 접근 가능한 상황(공개키는 누구나 암호화 가능하므로 **항상 CPA에 노출**)
→
④ 선택 암호문 공격 (CCA, Chosen Ciphertext)**원하는 암호문을 넣어 평문을 얻을 수 있다**. 공격자에게 **가장 유리**. 패딩 오라클 공격이 대표 사례

**[암기]** **암단 → 기평 → 선평 → 선암** 순으로 **공격자의 능력이 강해진다**. "가장 강력한 공격은?" → **선택 암호문 공격**.

**대표적인 공격 기법**

- **전수 조사(Brute Force / 완전 탐색)** — 모든 키를 다 시도. **키 길이가 짧으면 성립**(DES 56비트)
- **차분 분석(Differential Cryptanalysis)** — **평문 쌍의 차이가 암호문 차이에 어떻게 나타나는지** 통계적으로 추적. **선택 평문 공격**에 해당. DES의 S박스는 이미 이 공격을 염두에 두고 설계돼 있었다
- **선형 분석(Linear Cryptanalysis)** — 평문·암호문·키 비트 사이의 **선형 근사식**을 찾아 키를 추정. **기지 평문 공격**에 해당
- **중간 만남 공격(Meet-in-the-Middle)** — 2중 암호화(2DES)에서 **양쪽에서 계산해 중간값을 맞춰** 키를 찾는다. **2DES를 쓰지 않고 3DES를 쓰는 이유**
- **부채널 공격(Side Channel)** — 알고리즘이 아니라 **구현의 물리적 흔적**을 관찰. **전력 소모(DPA)·연산 시간·전자파·소리·발열**. 수학적으로 안전해도 뚫린다
- **재전송(Replay)** · **중간자(MITM)** · **사전 공격** · **레인보우 테이블**(해시 대상)

> **시험 한줄정리:** 능력 순서 **암호문 단독(COA) → 기지 평문(KPA) → 선택 평문(CPA) → 선택 암호문(CCA, 가장 강력)** / 기법 **전수조사 · 차분 분석(선택 평문) · 선형 분석(기지 평문) · 중간 만남 공격(2DES가 아닌 3DES를 쓰는 이유) · 부채널 공격(전력·시간·전자파로 구현을 노림)**

_관련 개념: classic · symalg · hash_

## 디피-헬만 키 교환과 RSA 암·복호화 과정 — Diffie-Hellman Key Exchange / RSA

`정보보안 일반`  `DH=이산대수·키 교환 전용` `g^ab mod p` `중간자 공격에 취약` `RSA=소인수분해` `C=M^e mod n`

**한줄:** 디피-헬만은 공개된 채널에서 서로 g^ab mod p라는 같은 비밀값에 도달하는 키 교환 방식(인증이 없어 중간자에 취약) / RSA는 C=M^e mod n으로 암호화하고 M=C^d mod n으로 복호화한다

**디피-헬만 키 교환 과정**

1976년 **최초의 공개키 개념**. **암호화 알고리즘이 아니라 "키를 나눠 갖는" 방법**이다. 근거는 **이산대수 문제**(g^x mod p는 쉽지만 x를 되찾기는 어렵다).

```
공개 값:  소수 p,  원시근 g       ← 누구나 알아도 됨

① 앨리스: 비밀 a 선택 → A = g^a mod p 를 전송
② 밥    : 비밀 b 선택 → B = g^b mod p 를 전송
③ 앨리스: K = B^a mod p = g^(ba) mod p
④ 밥    : K = A^b mod p = g^(ab) mod p

→ 둘은 같은 K에 도달하지만, 도청자는 p·g·A·B만 보고는
   a·b를 알 수 없어 K를 계산할 수 없다
```

- **키를 실제로 전송하지 않고도** 공유 비밀을 만든다는 것이 핵심
- **치명적 약점: 인증 기능이 없다** → **중간자 공격(MITM)**에 그대로 노출. 중간자가 양쪽과 각각 DH를 수행하면 **양쪽 다 속는다**
대책 = **전자서명·인증서로 상대를 확인**(SSL/TLS·IPSec의 IKE가 이렇게 쓴다)
- **DHE/ECDHE** — 매 세션 새 값을 쓰는 **임시(Ephemeral)** 방식. **순방향 비밀성(PFS)**을 제공해 나중에 서버 개인키가 유출돼도 **과거 통신은 복호화되지 않는다**

**RSA 키 생성과 암·복호화**

근거는 **소인수분해의 어려움**(큰 두 소수의 곱은 쉽지만 되돌리기는 어렵다).

```
[키 생성]
① 큰 소수 p, q 선택 →  n = p × q
② ø(n) = (p−1)(q−1)                    ← 오일러 함수
③ ø(n)과 서로소인 e 선택               ← 공개키 지수 (보통 65537)
④ e × d ≡ 1 (mod ø(n)) 인 d 계산        ← 개인키 지수

   공개키 = (e, n)      개인키 = (d, n)

[암호화]  C = M^e mod n      ← 수신자의 공개키
[복호화]  M = C^d mod n      ← 수신자의 개인키
[서 명]  S = M^d mod n  (개인키) →  검증 M = S^e mod n (공개키)
```

- **p·q는 반드시 폐기**해야 한다 — 알려지면 d가 즉시 계산된다
- 안전성은 **n을 소인수분해하지 못한다**는 데 전적으로 의존 → 현재 **2048비트 이상** 권장
- **양자 컴퓨터의 쇼어(Shor) 알고리즘**이 소인수분해·이산대수를 모두 깨므로 **RSA·DH·ECC가 함께 위협**받는다 → **양자내성암호(PQC)**로 전환 중

**혼합(하이브리드) 암호화 — 실제로 쓰는 방식**

공개키는 **너무 느려서** 대용량 데이터에 직접 쓸 수 없다. 그래서 **둘을 조합**한다.① 세션 키 생성송신자가 **임시 대칭키(세션 키)**를 난수로 만든다
→
② 데이터 암호화본문은 **빠른 대칭키(AES)**로 암호화
→
③ 세션 키 암호화**세션 키만** 수신자의 **공개키**로 암호화 = **전자봉투**
→
④ 전송·복호화수신자가 **개인키로 세션 키를 풀고**, 그 키로 본문을 복호화

**[정리]** **속도는 대칭키에서, 키 분배는 공개키에서** 가져온다. **SSL/TLS·PGP·S/MIME·SET**가 전부 이 구조다.

> **시험 한줄정리:** **DH: 공개 p·g, 각자 a·b → A=g^a, B=g^b 교환 → 공유키 K=g^(ab) mod p**, 키를 보내지 않고 공유하지만 **인증이 없어 중간자에 취약**(서명 필요), **DHE/ECDHE는 순방향 비밀성** / **RSA: n=pq, ø(n)=(p−1)(q−1), ed≡1 mod ø(n) → C=M^e mod n, M=C^d mod n**, **p·q는 폐기** / 실제 사용은 **하이브리드(전자봉투)**

_관련 개념: pubkey · symalg · esignalg_

## 해시 함수 — 조건 · 종류 · 생일 공격 — Hash Function / Birthday Attack

`정보보안 일반`  `일방향성·충돌 저항성` `고정 길이 출력` `MD5·SHA-1 폐기` `생일 공격=2^(n/2)` `랜덤 오라클 모델`

**한줄:** 해시는 임의 길이 입력을 고정 길이로 줄이는 일방향 함수로 키가 없고 복호화도 없다 / 조건은 일방향성과 두 종류의 충돌 저항성이며, 생일 공격 때문에 실질 안전성은 출력 길이의 절반이다

**특징과 갖춰야 할 조건**

**해시 함수** — **임의 길이 입력 → 고정 길이 출력(다이제스트)**. **키가 없고, 복호화가 불가능**하다(암호화가 아니다).
- **압축성** — 출력이 **고정 길이**
- **계산 용이성** — 해시값을 구하는 것은 **빨라야** 한다
- **일방향성(Preimage Resistance)** — **해시값 h로부터 원본 M을 찾을 수 없어야** 한다
- **두 번째 역상 저항성(Second Preimage Resistance, 약한 충돌 저항성)** — 주어진 **M과 같은 해시값을 갖는 다른 M′**을 찾을 수 없어야 한다
- **충돌 저항성(Collision Resistance, 강한 충돌 저항성)** — **해시값이 같은 아무 두 입력 쌍**을 찾을 수 없어야 한다. **가장 강한 조건**
- **눈사태 효과** — 입력이 **1비트만 바뀌어도 출력이 완전히 달라져야** 한다
**[용도]** **무결성 검증 · 전자서명(해시에 서명) · 패스워드 저장(해시+솔트) · 블록체인 · 파일 중복 확인**. **기밀성은 제공하지 않는다.**

**생일 공격 (Birthday Attack)**

**생일 역설** — 사람이 **23명만 모여도** 생일이 같은 쌍이 있을 확률이 **50%를 넘는다**. "특정 날짜와 같은 사람"이 아니라 **"아무 두 사람"**을 찾기 때문에 훨씬 쉽다.
- 해시에 적용하면 — **n비트 출력**의 해시에서 **충돌 쌍**을 찾는 데 필요한 시도 횟수는 **2ⁿ이 아니라 약 2^(n/2)**
- 즉 **SHA-256의 충돌 저항 강도는 실질적으로 128비트**. **출력 길이를 충돌 저항성의 2배로 잡아야** 하는 이유
- 공격 시나리오: 내용은 다르지만 **해시가 같은 두 계약서**를 미리 준비해 서명받은 뒤 바꿔치기 → **전자서명 위조**
- **일방향성(2ⁿ)**보다 **충돌 저항성(2^(n/2))**이 먼저 무너진다는 것이 핵심

**해시 알고리즘의 종류**

- **MD5** — 출력 **128비트**. **충돌이 실제로 발견되어 폐기**. 무결성 확인용 체크섬 정도로만 잔존
- **SHA-1** — 출력 **160비트**. **2017년 실제 충돌(SHAttered) 성공** → **사용 금지**
- **SHA-2 계열** — **SHA-224/256/384/512**. **현재 표준**. SHA-256이 가장 널리 쓰인다(블록체인 포함)
- **SHA-3(Keccak)** — SHA-2와 **내부 구조가 전혀 다른**(스펀지 구조) 차세대 표준. SHA-2를 대체하려는 것이 아니라 **대비책**으로 표준화
- **HAS-160** — **국내 표준** 해시(160비트). **KCDSA와 짝**으로 사용. 현재는 **LSH**(국내 신규 표준)로 대체
- **bcrypt · scrypt · PBKDF2 · Argon2** — **일부러 느리게** 만든 패스워드 전용 해시. 무차별 대입을 어렵게 한다(**일반 해시는 너무 빨라 패스워드 저장에 부적합**)
- 대부분 **머클-담고르(Merkle-Damgård) 구조**를 쓰며, 이 때문에 **길이 확장 공격**이 가능해 HMAC 같은 설계가 필요해졌다

**랜덤 오라클 모델 (Random Oracle Model)**

해시 함수를 **"완벽한 이상적 함수"라고 가정**하고 암호 방식의 안전성을 증명하는 **이론적 모델**.
- 가정하는 성질: **어떤 입력이 들어와도 완전한 난수를 출력**하고, **같은 입력에는 늘 같은 값**을 돌려주며, 출력으로부터 **입력을 전혀 알 수 없다**
- 왜 쓰나 — 실제 해시(SHA-256 등)의 내부 구조를 그대로 두고 증명하는 것은 매우 어렵기 때문에, **이상적인 상자로 대체해 증명을 단순화**한다. **RSA-OAEP·PSS** 등의 안전성 증명이 이 모델 위에 있다
- **한계** — **현실의 해시는 랜덤 오라클이 아니다**. 이 모델에서 안전해도 **실제 구현에서는 안전하지 않을 수 있다**는 반례가 존재한다. 그래서 **표준 모델(Standard Model)**에서의 증명을 더 강하게 본다

> **시험 한줄정리:** 해시=**임의 길이→고정 길이, 키 없음·복호화 없음** / 조건 **일방향성 · 두 번째 역상 저항성(약한 충돌) · 충돌 저항성(강한 충돌) · 눈사태 효과** / **생일 공격 때문에 충돌 저항 강도는 2^(n/2)** — 출력 길이를 2배로 잡는 이유 / **MD5(128)·SHA-1(160) 폐기 → SHA-2(256)·SHA-3(Keccak)**, 국내 **HAS-160→LSH**, 패스워드는 **bcrypt·PBKDF2** / **랜덤 오라클=이상적 해시를 가정한 증명 모델**

_관련 개념: mac · esign · cryptanalysis_

## MAC과 HMAC — Message Authentication Code / HMAC

`정보보안 일반`  `해시+대칭키` `무결성+송신자 인증` `부인방지 불가` `HMAC=키를 두 번 사용` `CMAC=블록암호 기반`

**한줄:** MAC=메시지와 공유 대칭키로 만든 인증 코드로 무결성과 송신자 인증을 함께 제공한다 / 단 송·수신자가 같은 키를 갖기 때문에 부인방지는 불가능하며, 해시 기반 구현이 HMAC

**왜 해시만으로는 부족한가**

해시값만 함께 보내면 **공격자가 메시지를 바꾸고 해시도 다시 계산해** 붙이면 그만이다. **해시는 누구나 계산할 수 있기 때문**이다.**[MAC의 해답]** **비밀 키를 아는 사람만** 만들 수 있게 한다. **MAC = f(메시지, 공유 비밀키)**. 키를 모르면 **올바른 MAC을 만들 수 없으므로** 변조가 탐지된다.

- 제공: **무결성 + 메시지 인증(송신자 확인)**
- 제공하지 않음: **기밀성**(내용을 감추지 않음), **부인방지**

**MAC이 부인방지를 못 하는 이유 (핵심 논리)**

**송신자와 수신자가 똑같은 키를 갖고 있다.** 따라서 **수신자도 그 MAC을 똑같이 만들 수 있다.**
- 분쟁이 생겨 제3자(법원)에게 가져가도 — "**수신자가 스스로 만든 것일 수도 있다**"는 반박을 배제할 수 없다
- 즉 **MAC은 둘 사이에서는 유효하지만 제3자에게 증명할 수 없다**
- **전자서명은 개인키가 서명자에게만 있으므로** 이 문제가 없다 → **부인방지는 전자서명만 가능**

- **MAC**: **대칭키** / 무결성·인증 **O** / 부인방지 **X** / **빠르다** / 사전에 키 공유 필요

- **전자서명**: **공개키(개인키로 서명)** / 무결성·인증 **O** / 부인방지 **O** / **느리다** / PKI 필요

**HMAC과 MAC의 종류**

- **HMAC(Hash-based MAC)** — **해시 함수와 비밀 키를 결합**한 표준 MAC. 표기는 **HMAC-SHA256**처럼 쓴 해시를 밝힌다

```
HMAC(K, M) = H( (K ⊕ opad) ‖ H( (K ⊕ ipad) ‖ M ) )
```

**키를 두 번(안쪽·바깥쪽) 사용하는 이중 구조**가 핵심 — 단순히 **H(K‖M)**으로 하면 머클-담고르 구조의 **길이 확장 공격**에 뚫리기 때문에 이렇게 설계됐다
- **CMAC** — **블록 암호(AES 등)**를 이용해 만드는 MAC. 해시 대신 암호 알고리즘을 재활용
- **CBC-MAC** — CBC 모드로 암호화한 **마지막 블록**을 MAC으로 쓴다(가변 길이 메시지에 취약해 CMAC으로 개선)
- **GMAC / AEAD** — **암호화와 인증을 한 번에** 처리(**AES-GCM**). 현대 프로토콜의 표준 방향

**사용 방식과 순서**

기밀성까지 필요하면 암호화와 MAC을 함께 쓰는데, **순서에 따라 안전성이 다르다**.
- **Encrypt-then-MAC (권장)**: **암호화한 뒤 그 암호문에 MAC**. 수신자는 **복호화 전에 MAC부터 검증**해 위조된 데이터를 아예 처리하지 않는다. **가장 안전**(IPSec 방식)

- **MAC-then-Encrypt**: 평문에 MAC을 붙이고 전체를 암호화. **SSL/TLS가 오래 쓴 방식**이며 **패딩 오라클 공격**의 원인이 되기도 했다

- **Encrypt-and-MAC**: 평문 MAC과 암호문을 각각 보낸다. **MAC이 평문 정보를 흘릴 수 있다**(SSH 방식)

**[활용]** **IPSec의 AH·ESP 인증, TLS 레코드 무결성, API 요청 서명, JWT(HS256)**가 모두 MAC(HMAC) 기반이다.

> **시험 한줄정리:** MAC=**메시지+공유 대칭키**로 만든 인증 코드 → **무결성·송신자 인증 O, 기밀성·부인방지 X** / **부인방지가 안 되는 이유는 수신자도 같은 키로 만들 수 있어서** — 부인방지는 **전자서명만** / **HMAC=H((K⊕opad)‖H((K⊕ipad)‖M)), 키를 두 번 써서 길이 확장 공격을 막는다** / **CMAC(블록암호)·GCM(암호화+인증)** / 순서는 **Encrypt-then-MAC이 권장**

_관련 개념: hash · esign · ipsec_
