# 레지스트리·이벤트 로그

> 자동 생성 — 원본은 `cards/sysrecord.js`. 직접 수정 금지.

## 윈도우 레지스트리 — Windows Registry

`시스템 보안`  `루트키 5개` `HKLM/HKCU` `하이브(Hive)` `Run 키 지속성` `regedit` `포렌식 아티팩트`

**한줄:** 윈도우 설정의 중앙 계층형 DB / 루트키 5개(HKLM·HKCU…) / 하이브 파일(SAM·SECURITY…) / Run 키=악성 지속성·포렌식 흔적

**정의**

윈도우의 **하드웨어·운영체제·설치된 프로그램·사용자별 설정**을 한곳에 모아 둔 **계층형(트리) 중앙 데이터베이스**. 옛날 여기저기 흩어져 있던 `.ini` 설정 파일들을 대체했다. 구조는 **키(Key) → 서브키(Subkey) → 값(Value)**이며, 값은 **이름·데이터·자료형**(`REG_SZ` 문자열, `REG_DWORD` 숫자 등)으로 이뤄진다. 편집 도구는 `regedit`, 명령줄은 `reg query/add/delete`.

**최상위 루트 키 5개 (시험 단골)**

윈도우가 정한 최상위 키는 5개다.
- **HKEY_LOCAL_MACHINE (HKLM)** — **컴퓨터 전체** 설정(하드웨어·설치된 SW·SAM·SECURITY·SYSTEM). 모든 사용자 공통.
- **HKEY_CURRENT_USER (HKCU)** — **지금 로그인한 사용자**의 개인 설정.
- **HKEY_USERS (HKU)** — **모든 사용자** 프로필 설정의 모음(HKCU는 그중 현재 사용자 부분).
- **HKEY_CLASSES_ROOT (HKCR)** — 파일 확장자 연결·COM 등록 정보.
- **HKEY_CURRENT_CONFIG (HKCC)** — 현재 하드웨어 프로필.
**[시험 포인트]** 루트키 **5개**의 이름과 역할, 특히 **HKLM ↔ HKCU** 구분이 그대로 출제된다.

**HKLM vs HKCU (적용 범위 구분)**

둘 다 설정을 담지만 **적용 범위**가 다르다.
- **HKLM**: 컴퓨터 **전체**에 적용 — 모든 사용자 공통.
수정에 **관리자 권한**이 필요.

- **HKCU**: **현재 로그인한 사용자**에게만 적용.
그 사용자 권한으로 수정 가능.

**하이브(Hive) — 디스크에 저장되는 파일**

레지스트리는 메모리에만 있는 게 아니라 **하이브(Hive)**라는 파일로 디스크에 저장된다.
- **시스템 하이브** — `C:\Windows\System32\config\` 폴더 안의 **SAM · SECURITY · SOFTWARE · SYSTEM**.
- **사용자 하이브** — 각 사용자 폴더의 `NTUSER.DAT`(그 사용자의 HKCU 내용).
**[연결]** **SAM·SECURITY** 하이브에 계정 정보·비밀번호 해시가 들어 있어, 이게 자격증명 탈취의 표적이다(윈도우 인증 체계 카드).

**보안 위협 — 지속성·자격증명 탈취**

**① 지속성(Persistence)** — 악성코드가 재부팅 후에도 자동 실행되려고 **자동 실행 키**에 자신을 등록한다. 대표 위치:

```
HKLM\Software\Microsoft\Windows\CurrentVersion\Run
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

같은 자리의 `RunOnce`도 같은 용도. **② 자격증명 탈취** — `SAM`·`SECURITY` 하이브에서 계정 해시를 덤프해 간다.**[단골]** '악성코드가 부팅 시 자동 실행되게 하는 대표 레지스트리 위치는?' → **Run 키**.

**포렌식 — 사용자 행위 흔적의 보고**

레지스트리는 **사용자 행위 흔적이 잔뜩 남는 곳**이라 디지털 포렌식·침해사고 분석의 핵심 아티팩트다. 최근 실행한 프로그램·문서(**UserAssist·RecentDocs·MRU**), **USB 연결 흔적**(USBSTOR), 자동 실행 항목, 시각·네트워크 정보 등이 남는다. 분석 도구: **RegRipper**, Registry Explorer.

**방어**

**최소 권한** — HKLM 등 시스템 영역 수정은 관리자만 가능하게. **자동 실행 감시** — Sysinternals **Autoruns**로 Run·서비스 등 자동 실행 지점을 점검, EDR로 Run 키 변경을 탐지. **변경 감사** — 중요 키에 감사(SACL)를 걸고 정기 백업.

> **시험 한줄정리:** 레지스트리 = 윈도우 설정 중앙 계층 DB / 루트키 **HKLM·HKCU·HKU·HKCR·HKCC** / 하이브(SAM·SECURITY·SOFTWARE·SYSTEM, NTUSER.DAT) / **Run 키=악성 지속성**·포렌식 흔적

_관련 개념: winauth · process · vss_

## 윈도우 이벤트 로그 — Windows Event Log

`시스템 보안`  `응용·보안·시스템` `4624/4625` `1102=로그삭제` `Logon Type` `evtx` `이벤트 뷰어`

**한줄:** 윈도우 활동을 시간순 기록 / 종류: 응용·보안·시스템 / 핵심 ID 4624·4625·1102(로그삭제) / 침해분석·포렌식 1차자료

**정의**

윈도우에서 일어나는 **활동을 시간순으로 기록**하는 로그. 로그온·프로그램 오류·서비스 시작·정책 변경 등이 남아, **침해사고 분석·감사(audit)의 1차 자료**가 된다. 확인 도구는 **이벤트 뷰어(`eventvwr`)**, 명령줄은 `wevtutil`·PowerShell `Get-WinEvent`.

**로그 종류 (기본 3종 — 시험 필수)**

기본 3종에 현대 윈도우가 2종을 더한다.
- **응용 프로그램(Application)** — 각 프로그램이 남기는 이벤트.
- **보안(Security)** — 로그온·권한·개체 접근 등 **감사 기록**. 보안의 핵심 로그.
- **시스템(System)** — OS 구성요소·드라이버·서비스 이벤트.
- **설치(Setup)** — 설치·업데이트 관련.
- **전달된 이벤트(Forwarded Events)** — 다른 PC에서 수집해 온 로그.
**[시험 포인트]** 기본 **3종(응용·보안·시스템)**은 반드시 암기. 그중 **보안 로그**가 인증·침해 분석의 핵심.

**파일 위치·항목 구성**

저장 형식은 옛날 `.evt` → 현재 **`.evtx`**이며, 위치는 `C:\Windows\System32\winevt\Logs\`다. 각 이벤트 항목의 구성:
- **날짜·시간**
- **원본(Source)** — 이벤트를 남긴 구성요소.
- **이벤트 ID** — 이벤트 종류를 식별하는 고유 번호.
- **수준(Level)** — 정보·경고·오류·중요.
- **사용자·컴퓨터**

**주요 보안 Event ID (전부 외울 필요 없음)**

이벤트 ID는 **다 외우지 않아도 된다.** 아래 **핵심 3개**만 확실히 하고, 나머지는 '이런 게 있다'는 수준으로 눈에만 익히면 충분하다.
- `4624` 로그온 **성공** · `4625` 로그온 **실패** — 비정상 로그인·무차별 대입 탐지의 기본.
- `1102` **보안 로그 삭제** — 안티포렌식의 대표 신호.
참고(여유 있을 때 눈에만):
- `4634`·`4647` 로그오프 · `4672` 특수 권한 로그온
- `4720` 계정 생성 · `4726` 계정 삭제
- `4688` 새 프로세스 · `7045` 서비스 설치
- `6005`·`6006` 로그 서비스 시작/종료 · `1074` 시스템 종료

**로그온 유형 (Logon Type)**

같은 로그온이라도 **어떤 경로로** 들어왔는지는 **Logon Type**으로 구분한다(4624/4625에 함께 기록).
- **Type 2** — 대화형(콘솔에서 직접 로그인).
- **Type 3** — 네트워크(파일 공유 등).
- **Type 10** — 원격 데스크톱(RDP).

**안티포렌식 — 로그 삭제 (1102)**

공격자는 침입 흔적을 지우려고 **보안 로그를 삭제**한다(`wevtutil cl Security`, 이벤트 뷰어의 '로그 지우기'). 하지만 그 **삭제 행위 자체가 `1102` 이벤트**로 남는다. 정상 운영 중 1102가 보이면 **강한 침해 징후**. '보안 감사 로그를 정리하면 남는 이벤트 ID는? → **1102**'가 전형적 출제.

**방어**

**감사 정책(Audit Policy)**을 켜야 로그온·개체 접근 등이 실제로 기록된다(안 켜면 아예 안 남음). 로그를 **중앙 수집**(SIEM·Windows 이벤트 전달 WEF)해 원본이 지워져도 사본을 확보하고, 로그 **크기·보존 기간**을 넉넉히, 접근 권한을 제한한다.

> **시험 한줄정리:** 이벤트 로그 = 시간순 활동 기록 / 종류 **응용·보안·시스템**(+설치·전달) / `.evtx` @ `winevt\Logs` / 핵심 ID **4624·4625·1102(로그삭제)** / 삭제 대비 중앙 수집(SIEM)

_관련 개념: registry · process · winauth_
