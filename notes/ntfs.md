# 파일시스템 (NTFS)

> 자동 생성 — 원본은 `cards/ntfs.js`. 직접 수정 금지.

## NTFS 파일시스템 — New Technology File System

`시스템 보안`  `MFT` `저널링` `ACL 권한` `EFS` `ADS` `FAT 비교`

**한줄:** 윈도우 기본 파일시스템 / 권한(ACL)·암호화(EFS)·저널링·감사 내장 / FAT엔 없던 보안기능

**정의**

윈도우 기본 파일시스템. FAT의 후속으로 **보안·복구 기능이 내장**. 세부 개념(EFS·BitLocker·ADS·VSS)이 전부 이 위에서 도는 '뿌리' 개념 — 이걸 지도로 잡고 나머지를 얹으면 안 헷갈림.

**FAT vs NTFS (시험 단골 비교)**

시험은 **FAT엔 없고 NTFS에만 있는 것**을 묻는다.
- **FAT**: 단순한 옛 파일시스템. **접근권한·암호화·저널링이 없다.** 보안 용도로는 부적합.

- **NTFS**: 보안·복구 기능을 갖춘 윈도우 기본 파일시스템.

NTFS에만 있는 기능(= FAT엔 없는 것):
- ① **접근권한(ACL, Access Control List = 접근제어 목록)** — 파일마다 사용자별 허용/거부 지정
- ② **암호화(EFS)** — 파일 단위 암호화
- ③ **저널링(복구)** — 작업 전 로그를 남겨 크래시에서 복구
- ④ **감사(Auditing)** — 접근 시도 기록
- ⑤ **압축·대용량·디스크 쿼터**
**[결론]** 권한·암호화·저널링이 필요하면 **NTFS**. 'FAT에 없는 기능은?'이 그대로 출제된다.

**핵심 구성요소**

- `MFT` (Master File Table, 마스터 파일 테이블) — 볼륨 안 **모든 파일의 메타데이터를 적어 둔 목록**.
- `$LogFile` — **저널링**(작업 로그)을 담는 파일.
- **ADS** (Alternate Data Streams, 대체 데이터 스트림) — 한 파일에 **여러 데이터 흐름**을 붙이는 기능. 편의이자 은닉에 악용되는 **양날의 검**.

**저널링 (Journaling) — 어원으로 이해**

**journal=일지·(회계) 분개장**: 최종 장부에 옮기기 **전에** 먼저 시간순으로 적어두는 기록('journ'=하루→날마다 적음, journey·저널리스트와 같은 뿌리). 파일시스템도 똑같이 **실제 디스크에 쓰기 전, 할 작업을 저널(로그)에 먼저 기록**(Write-Ahead Logging) → 도중에 정전·크래시가 나도 재부팅 때 저널을 보고 **재실행(redo)/되돌림(rollback)**해 일관성 유지. 핵심은 '자동 복구'가 아니라 **'하기 전에 먼저 적어둔다'**. NTFS=`$LogFile`, 리눅스 ext3/4·XFS도 저널링.

**NTFS라서 생기는 위험**

기능이 많아 **악용 포인트**도 생김: **ADS**로 악성코드 은닉, **VSS**(섀도 복사본)를 랜섬웨어가 삭제. 각각은 연결 카드 참고.

> **시험 한줄정리:** NTFS = 윈도우 기본 FS / **권한·암호화·저널링·감사** 내장(FAT엔 없음) / 세부개념 EFS·BitLocker·ADS·VSS의 뿌리

_관련 개념: efsbitlocker · ads · vss · adminshares_

## 파일 암호화 — EFS vs BitLocker — Encrypting File System / BitLocker

`시스템 보안`  `EFS=파일단위` `BitLocker=볼륨전체` `TPM` `FEK` `복구 에이전트`

**한줄:** EFS=파일·폴더 단위 암호화(사용자 계정) / BitLocker=볼륨(드라이브) 전체 암호화(TPM) / '단위'로 구분

**EFS (파일 단위)**

NTFS 기능. **파일·폴더 단위** 암호화. 대칭키 `FEK`(File Encryption Key=파일 암호화 키)로 파일을 암호화하고, 그 FEK를 다시 **사용자 공개키**로 암호화 → 그 사용자로 로그인해야 복호화. 즉 **사용자 계정 기반**.

**BitLocker (볼륨 전체)**

**드라이브(볼륨) 전체**를 통째로 암호화. **TPM(Trusted Platform Module, 신뢰 플랫폼 모듈)**—암호키를 하드웨어에 보관하고 부팅 무결성을 검증하는 **별도 보안칩**—과 연동해 부팅 전 무결성 검사. **노트북 도난 시 디스크 통째 보호**가 대표 시나리오. PIN·복구키로도 잠금.

**비교 (표로 암기 — 함정 방지)**

- **EFS**: **단위** — 파일·폴더 하나하나.
**인증** — 사용자 인증서(개인키).
**대표 상황** — 공용 PC에서 **특정 파일만 몰래** 보호.

- **BitLocker**: **단위** — 드라이브(볼륨) 전체.
**인증** — TPM·PIN·복구키.
**대표 상황** — **노트북 분실·도난** 시 디스크 통째 보호.

**[시험 함정]** '볼륨 전체 암호화는?' → **BitLocker** · '파일 단위 암호화는?' → **EFS**. '단위'로 구분한다.

**EFS 주의**

사용자 **인증서(개인키)를 잃으면 복호화 불가** → 데이터 영구 손실. 조직은 **복구 에이전트(DRA, Data Recovery Agent)**를 지정해 대비. 반대로 계정이 탈취되면 자동 복호화되므로 계정 보호가 전제.

> **시험 한줄정리:** **EFS=파일/폴더 단위(사용자 계정·FEK)** / **BitLocker=볼륨 전체(TPM)** / 분실대비=BitLocker · EFS는 복구에이전트(DRA)로 대비

_관련 개념: ntfs_

## 대체 데이터 스트림 (ADS) — Alternate Data Streams

`시스템 보안`  `NTFS 전용` `악성코드 은닉` `dir /r` `MOTW`

**한줄:** NTFS가 한 파일에 여러 데이터 흐름을 붙이는 기능 / 악성코드 은닉에 악용 / dir /r 로 탐지

**정의**

NTFS에서 하나의 파일에 **보이지 않는 추가 데이터 스트림**을 붙일 수 있는 기능. 원래는 메타데이터용(예: 인터넷서 받은 파일에 붙는 `Zone.Identifier`=MOTW(Mark of the Web), '다른 PC에서 온 파일' 경고).

**악용 — 은닉**

정상 파일 뒤에 악성 실행파일을 숨김.

```
type evil.exe > normal.txt:hidden.exe
```

탐색기·기본 `dir`엔 **안 보이고 파일 크기도 안 늘어 보임** → 백신·사용자 눈을 피함. NTFS 전용 기능이라 시험 단골.

**탐지·제거**

탐지: `dir /r` · PowerShell `Get-Item -Stream *` · Sysinternals **Streams**. 제거: 파일을 **FAT/exFAT·네트워크로 복사**하면 ADS가 사라짐(그 파일시스템들은 ADS 미지원). '메인 데이터는 그대로, 숨은 스트림만 탈락'이 포인트.

> **시험 한줄정리:** ADS = NTFS가 한 파일에 숨은 데이터 스트림 부착 / **악성코드 은닉**(크기·탐색기서 안 보임) / `dir /r`로 탐지, FAT 복사 시 소멸

_관련 개념: ntfs_

## 볼륨 섀도 복사본 (VSS) — Volume Shadow Copy Service

`시스템 보안`  `스냅샷` `이전 버전` `랜섬웨어` `vssadmin` `포렌식`

**한줄:** 특정 시점 스냅샷으로 백업·복원 / 랜섬웨어가 삭제해 복구 차단 / 포렌식 증거원

**정의**

실행 중에도 볼륨의 **특정 시점 스냅샷**을 만들어 백업·복원하게 해주는 서비스. 윈도우 '**이전 버전**' 복원·시스템 복원이 이걸로 동작. 쓰던 중에도 일관된 백업을 뜰 수 있는 게 핵심.

**랜섬웨어 악용 (시험·실무 포인트)**

랜섬웨어가 암호화 후 **섀도 복사본을 삭제**해 사용자의 복원 수단을 없앰.

```
vssadmin delete shadows /all
```

이 명령·이벤트가 보이면 랜섬웨어의 강한 징후 → 탐지·차단 지표로 활용.

**포렌식 활용**

반대로 방어·수사에선 무기. 섀도 복사본에 **과거 시점의 파일이 남아** 있어, 삭제·변조된 파일이나 이전 상태를 **복구해 증거로** 확보(안티포렌식 대응).

**방어**

백업을 **오프라인·별도 매체**에 이중화(3-2-1 백업)—온라인 섀도만 믿지 않기. `vssadmin delete` 같은 관리자 명령 **실행 모니터링**·권한 제한.

> **시험 한줄정리:** VSS = 시점 스냅샷 백업·'이전 버전' 복원 / **랜섬웨어가 vssadmin으로 삭제**해 복구 차단 / 포렌식 증거원

_관련 개념: ntfs_
