# 네트워크 활용(TCP/IP) — 메일·네트워크 관리

> 자동 생성 — 원본은 `cards/appsvc.js`. 직접 수정 금지.

## SMTP · 메일 프로토콜 — Simple Mail Transfer Protocol

`네트워크 보안`  `SMTP 25=송신` `POP3 110·IMAP 143=수신` `MUA→MTA→MDA` `오픈 릴레이` `SPF·DKIM·DMARC`

**한줄:** SMTP(25)=메일 송신·서버 간 전달 / 수신은 POP3(110, 받고 삭제)·IMAP(143, 서버 보관·동기화) / 평문·발신자 위조에 취약

**정의 · 역할 분담**

**SMTP(Simple Mail Transfer Protocol)** — 메일을 **보내고(송신)** 서버끼리 **전달**하는 프로토콜. 포트 **25**(TCP).**[핵심 구분]** **SMTP는 '보내기 전용'**이다. 사용자가 메일함에서 **받아 보는 것**은 **POP3·IMAP**이 담당한다. '메일 수신 프로토콜은?'에 SMTP를 고르면 오답.

**전달 경로 (MUA → MTA → MDA)**

- **MUA** — Mail **User** Agent — 사용자가 쓰는 메일 프로그램(아웃룩 등).

- **MTA** — Mail **Transfer** Agent — 메일 서버. **SMTP로 서버 간 전달**(sendmail·postfix).

- **MDA** — Mail **Delivery** Agent — 수신자 **사서함에 저장**.

- **수신** — 사용자가 **POP3/IMAP**으로 가져감.

**POP3 vs IMAP · 포트 정리**

- **POP3 (110)**: 서버에서 **내려받고 서버에선 삭제**(기본). 기기 **한 대**에서 쓰기 적합, 서버 용량 절약. 오프라인 열람 편함.

- **IMAP (143)**: 메일을 **서버에 그대로 두고** 목록만 동기화. **여러 기기**에서 같은 상태로 확인 가능(요즘 방식).

**포트 암기**: SMTP **25** · POP3 **110** · IMAP **143** / 보안(TLS) 버전 **SMTPS 465·submission 587 · POP3S 995 · IMAPS 993**.
**MIME**(Multipurpose Internet Mail Extensions) — 원래 SMTP는 **ASCII 텍스트만** 보낼 수 있어서, **한글·이미지·첨부파일**을 담기 위해 만든 확장 규격.

**보안 취약점**

- **평문 전송** — 본문과 인증 정보가 그대로 흘러 **스니핑**에 노출
- **오픈 릴레이(Open Relay)** — **아무나 중계**해 주도록 열린 메일 서버. **스팸 발송지로 악용**되어 IP가 차단당한다 → **반드시 릴레이 제한**
- **발신자 위조(스푸핑)** — SMTP는 **보내는 사람을 검증하지 않는다** → 피싱·**스피어 피싱**의 출발점
- **첨부파일**을 통한 악성코드 유포

**대응**

- **SMTP 인증(SMTP-AUTH)** + **릴레이 제한**(허용 대역만)
- **전송 구간 암호화** — STARTTLS·SMTPS(465/587)
- **발신자 검증 3종**: **SPF**(허용된 **발송 IP** 목록을 DNS에 공개) · **DKIM**(메일에 **전자서명**) · **DMARC**(SPF·DKIM 실패 시 **처리 정책**과 리포트)
- **본문 자체 암호화·서명** — **S/MIME**·**PGP**
- 스팸 필터·첨부 확장자 차단·백신 연동

> **시험 한줄정리:** **SMTP 25=송신·서버간 전달**(수신 아님!) / 수신 **POP3 110**(받고 삭제) vs **IMAP 143**(서버 보관·동기화) / 경로 **MUA→MTA→MDA** / 취약=평문·**오픈 릴레이**·발신자 위조 → **SMTP-AUTH·SPF·DKIM·DMARC·S/MIME**

_관련 개념: snmp · http · apt_

## SNMP (네트워크 관리 프로토콜) — Simple Network Management Protocol

`네트워크 보안`  `161 요청·162 Trap` `매니저·에이전트·MIB·OID` `Trap=능동 통보` `v1/v2c 커뮤니티 평문` `v3 인증·암호화`

**한줄:** 장비 상태를 수집·제어하는 관리 프로토콜(UDP 161, Trap 162) / 매니저·에이전트·MIB·OID / v1·v2c는 커뮤니티 스트링 평문, v3는 인증·암호화

**정의 · 구성 요소**

**SNMP** — 라우터·스위치·서버 등의 **상태를 수집하고 설정을 제어**하는 표준 관리 프로토콜. **UDP**를 쓴다.
- **매니저(Manager)** — 관리하는 쪽. 보통 **NMS**가 담당
- **에이전트(Agent)** — 관리 **대상 장비**에 올라가 정보를 제공
- **MIB**(Management Information Base) — 관리 정보를 **트리 구조로 정의한 DB**
- **OID**(Object Identifier) — MIB 안의 **개별 항목을 가리키는 번호**(예: 1.3.6.1.2.1…)

**포트 · 동작 방식 (시험 포인트)**

**포트 161** — 매니저가 **에이전트에게 질의**할 때(에이전트가 161에서 수신). **포트 162** — 에이전트가 **Trap을 보낼 때**(매니저가 162에서 수신).**[폴링 vs Trap]** 기본은 매니저가 주기적으로 물어보는 **폴링**(`GetRequest`·`GetNextRequest`·`SetRequest`). 반대로 **Trap**은 **사건이 생겼을 때 에이전트가 먼저** 매니저에게 알리는 **능동 통보**다. '누가 먼저 보내느냐'로 구분한다.
주요 메시지: **Get**(조회)·**GetNext**(다음 항목)·**Set**(설정 변경)·**Response**·**Trap**(통보). v2에서 **GetBulk·Inform** 추가.

**버전별 보안 (핵심)**

- **v1 / v2c**: 인증 수단이 **커뮤니티 스트링**(문자열 비밀번호)뿐이고 **평문**으로 오간다. 기본값이 **public(읽기)·private(쓰기)**라 **안 바꾸면 그대로 뚫린다**. v2c는 성능만 개선.

- **v3**: **인증(무결성)·암호화** 지원(USM). **실무·시험 모두 v3 사용을 권장**.

**공격에 어떻게 쓰이나**

- **정보 수집(정찰)** — 커뮤니티 스트링만 알면 **장비 종류·OS·인터페이스·라우팅·연결 목록**까지 읽어낸다(킬체인 **1단계 정찰**의 노다지)
- **설정 변경** — 쓰기 권한(private)이 열려 있으면 **장비 설정 변경·서비스 중단**까지 가능
- **UDP 기반**이라 **출발지 위조가 쉽고**, **증폭 DDoS**에 악용된다

**대응**

**SNMPv3 사용**(인증·암호화) · 기본 **커뮤니티 스트링 반드시 변경**하고 복잡하게 · **읽기 전용**으로 제한 · **접근 ACL**로 관리 서버 IP만 허용 · **불필요하면 비활성화** · 관리 트래픽은 **분리된 관리망**으로.

> **시험 한줄정리:** SNMP=장비 관리(UDP) / **161=질의·162=Trap** / 구성 **매니저·에이전트·MIB·OID** / **Trap만 에이전트가 먼저** 보냄 / **v1·v2c=커뮤니티 스트링 평문(public·private)** → **v3=인증·암호화** / 정찰·설정변경·증폭DDoS에 악용

_관련 개념: nms · netdevice · killchain_

## NMS · 네트워크 관리 (FCAPS) — Network Management System

`네트워크 보안`  `SNMP로 감시·제어` `FCAPS 5대 기능` `장애·구성·계정·성능·보안` `관리망 분리` `NMS 장악=전체 위험`

**한줄:** SNMP 등을 이용해 네트워크 장비를 감시·제어하는 관리 시스템 / ISO 관리 5대 기능=FCAPS(장애·구성·계정·성능·보안)

**정의**

**NMS(Network Management System)** — 네트워크 장비의 **상태를 한곳에서 감시하고 제어**하는 시스템. 주로 **SNMP**로 정보를 수집하며, SNMP 구조에서 **매니저(Manager)** 역할을 한다. 장애 알람·트래픽 그래프·구성 백업 등을 제공.

**FCAPS — 네트워크 관리 5대 기능 (ISO, 시험 단골)**

- **F — 장애 관리(Fault)**: 장애를 **탐지·격리·복구**하고 기록. 알람·Trap 처리
- **C — 구성 관리(Configuration)**: 장비 **설정·자산·버전** 파악과 변경 이력
- **A — 계정/과금 관리(Accounting)**: 사용자별 **자원 사용량 측정**·과금·할당
- **P — 성능 관리(Performance)**: **처리량·응답시간·가용성·이용률** 측정과 임계치 관리
- **S — 보안 관리(Security)**: **접근 통제·인증·키 관리·로그**
**앞글자 FCAPS**로 외운다. '5대 기능이 아닌 것은?' 형태로 자주 나온다.

**보안 관점 — NMS 자체가 표적**

NMS는 **모든 장비의 계정·설정·구조를 알고 있고, 설정을 바꿀 권한**까지 갖는다. 그래서 **NMS 한 대가 장악되면 네트워크 전체 통제권**이 넘어간다. 공격자에게는 **최고 가치의 표적**이다.

**대응**

**관리망 분리**(Out-of-Band — 서비스망과 분리된 별도 관리 네트워크) · NMS 접근에 **강한 인증·MFA**와 **IP 제한** · **SNMPv3** 사용 · 관리자 행위 **로그 감사** · 설정 **변경 이력 관리**와 백업.

> **시험 한줄정리:** NMS=SNMP로 장비를 **감시·제어**하는 시스템(SNMP의 **매니저** 역할) / ISO 5대 기능 **FCAPS = 장애(Fault)·구성(Configuration)·계정(Accounting)·성능(Performance)·보안(Security)** / NMS 장악=**전체 네트워크 통제권 상실** → 관리망 분리·강한 인증

_관련 개념: snmp · netdevice · eventlog_
