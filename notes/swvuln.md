# 소프트웨어 취약점 (개발 보안)

> 자동 생성 — 원본은 `cards/swvuln.js`. 직접 수정 금지.

## 경쟁 조건 — Race Condition · TOCTOU

`시스템 보안`  `동시 접근·타이밍` `TOCTOU` `심볼릭 링크 공격` `SetUID 권한상승` `원자적 연산·락`

**한줄:** 공유 자원에 동시 접근 시 실행 순서(타이밍)에 따라 결과가 갈리는 취약점 / 대표=TOCTOU / SetUID·임시파일 표적

**정의 (어원으로 기억)**

둘 이상의 프로세스·스레드가 **공유 자원**(파일·변수·메모리)에 **동시에 접근**할 때, **누가 먼저 실행되느냐(타이밍)에 따라 결과가 달라지는** 상황. 이름 그대로 자원을 두고 **경주(race)**를 벌이는 것 — 공격자는 그 **찰나의 틈**을 파고든다.

**TOCTOU — 대표 공격**

**TOCTOU(Time-Of-Check to Time-Of-Use, 검사 시점~사용 시점)**: 프로그램이 자원을 **검사한 뒤** 실제로 **사용하기 직전**의 틈에, 공격자가 그 자원을 **바꿔치기**한다.**[전형적 시나리오]** 권한을 검사한 파일을 그 순간 **심볼릭 링크**로 바꿔 **다른 파일(예: `/etc/passwd`)**을 가리키게 만든다 → 검사는 통과했는데 실제로는 엉뚱한 파일을 건드림 → **권한 상승·파일 훼손**.

**왜 위험한가 — SetUID·임시파일**

특히 유닉스 **SetUID(Set User ID)** 프로그램(실행되는 동안 **root 권한**을 가짐)에서 치명적이다. 검사~사용 틈에 파일을 바꿔치기하면 **root 권한으로 엉뚱한 파일을 쓰게** 되어 권한 상승으로 이어진다. 여러 프로그램이 공유하는 `/tmp` **임시파일 경쟁**도 단골 표적.

**방어**

핵심은 **검사와 사용을 하나로(원자적, atomic)** 묶어 틈을 없애는 것. 파일명 대신 **파일 디스크립터**로 먼저 열고(open) 그 핸들로 검사(fstat) — 이름이 바뀌어도 이미 연 파일을 본다. 임시파일은 **안전하게 생성**(`mkstemp`, `O_EXCL`). 공유 자원엔 **락(lock)·뮤텍스·세마포어**로 **동기화**. **SetUID 최소화**·권한 낮추기.

> **시험 한줄정리:** 경쟁 조건 = 공유 자원 동시 접근 시 **타이밍**으로 결과가 갈림 / 대표 **TOCTOU**(검사~사용 틈에 심볼릭 링크 바꿔치기) / **SetUID**·`/tmp` 표적 / 방어=원자적 연산·`mkstemp`·락
