## 네트워크 기초 (프로토콜 · 유형 · 토폴로지) — Protocol · LAN/WAN · Topology

`네트워크 보안`  `프로토콜 3요소` `구문·의미·순서` `PAN<LAN<MAN<WAN` `버스·스타·링·메시` `스타=가장 널리`

**한줄:** 프로토콜=통신 규약(3요소 구문·의미·순서) / 거리별 PAN<LAN<MAN<WAN / 토폴로지=연결 모양(버스·스타·링·메시·트리)

**네트워크 · 프로토콜**

**네트워크**=둘 이상의 장치를 연결해 **자원·정보를 주고받는 체계**. **프로토콜(Protocol)**=서로 다른 장치가 통신하기 위해 미리 약속한 **통신 규약**. 사람으로 치면 '같은 언어와 대화 예절'.

**프로토콜 3요소 (시험 단골)**

- **구문(Syntax)** — 데이터의 **형식·구조**(어떤 순서로 몇 비트씩)
- **의미(Semantics)** — 각 비트가 **무엇을 뜻하는지**, 어떻게 처리·제어할지
- **순서(Timing)** — **언제·얼마나 빠르게** 보낼지(송신 시점·속도 조절)
**구·의·순**으로 외우면 편하다. '3요소가 아닌 것?'으로 자주 나온다.

**거리에 따른 유형 (좁은 → 넓은)**

- **PAN** — Personal — 개인 주변 수 m(블루투스).

- **LAN** — Local — **건물·사무실** 단위. 속도 빠르고 오류 적음.

- **MAN** — Metropolitan — **도시** 규모.

- **WAN** — Wide — **국가·대륙** 간(인터넷). 느리고 오류율↑.

**토폴로지 — 연결 모양**

- **버스(Bus)** — 하나의 **공통 케이블**에 모두 연결. 설치 쉽고 저렴하지만 **충돌 많고** 백본이 끊기면 **전체 마비**.
- **스타(Star)** — **중앙 장비(허브·스위치)**에 각자 연결. **가장 널리 쓰임**. 관리·장애 파악 쉬움. 단 **중앙 장비가 고장나면 전체 마비**.
- **링(Ring)** — 원형으로 연결해 **한 방향** 전달(토큰 링). 충돌은 없지만 **한 노드 장애가 전체에 영향**.
- **메시(Mesh)** — **모두가 서로** 연결. **신뢰성 최고**지만 **비용·회선 수 폭증**(완전 연결 시 **n(n-1)/2**개).
- **트리(Tree)** — 계층적 확장 구조(스타를 여러 단으로).

> **시험 한줄정리:** 프로토콜 **3요소=구문(Syntax)·의미(Semantics)·순서(Timing)** / 거리 **PAN<LAN<MAN<WAN** / 토폴로지: 버스(저렴·충돌), **스타(가장 널리·중앙 고장 취약)**, 링(단방향), **메시(신뢰성 최고·회선 n(n-1)/2)**, 트리

_관련 개념: osi · netdevice_

## OSI 7계층 — OSI 7 Layer Model

`네트워크 보안`  `물데네전세표응` `PDU 비트·프레임·패킷·세그먼트` `2계층 MAC·3계층 IP` `4계층 포트` `표준 참조 모델`

**한줄:** 통신 과정을 7단계로 나눈 표준 참조 모델 / 1물리·2데이터링크·3네트워크·4전송·5세션·6표현·7응용 / 계층별 PDU와 주소가 다름

**왜 나누나**

국제표준화기구(ISO)가 만든 **참조 모델**. 복잡한 통신을 **기능별로 쪼개** 각 계층이 **독립적**으로 동작하게 한다 → 한 계층을 바꿔도 **다른 계층에 영향이 없고**(모듈화), 문제 발생 시 **어느 계층인지 좁혀서** 진단할 수 있다. 실제 인터넷은 TCP/IP를 쓰지만, **설명·시험의 기준**은 OSI다.

**7계층 (아래 → 위)**

- **1 물리(Physical)** — 비트를 **전기·광 신호**로. 케이블·리피터·허브. PDU=**비트**
- **2 데이터링크(Data Link)** — **인접 장비** 간 전달, **오류 검출**, **MAC 주소**. 스위치·브리지. PDU=**프레임**
- **3 네트워크(Network)** — **종단 간 경로 결정(라우팅)**, **IP 주소**. 라우터. PDU=**패킷**
- **4 전송(Transport)** — **종단 간 신뢰성**·흐름 제어, **포트 번호**. TCP·UDP. PDU=**세그먼트**
- **5 세션(Session)** — 연결의 **설정·유지·종료**, 동기점
- **6 표현(Presentation)** — **암호화·압축·인코딩**(형식 변환)
- **7 응용(Application)** — 사용자 서비스. HTTP·FTP·SMTP·DNS

**암기법 · 자주 묻는 대응**

아래부터 **물–데–네–전–세–표–응**.**[계층별 주소·PDU (표 형태로 출제)]** **2계층=MAC 주소·프레임** · **3계층=IP 주소·패킷** · **4계층=포트 번호·세그먼트**.
**암호화는 6계층(표현)**, **라우팅은 3계층**, **오류 검출(인접 구간)은 2계층**, **흐름 제어·재전송은 4계층**.

**시험 함정**

① **순서 뒤집기** — 표현↔세션, 네트워크↔전송을 바꿔 낸다. ② **역할 바꿔치기** — '라우팅=2계층'(X, 3계층), '암호화=7계층'(X, 6계층). ③ **오류 제어**는 **2계층(인접 구간)**과 **4계층(종단 간)** 둘 다 있으나 **범위가 다르다**.

> **시험 한줄정리:** **물–데–네–전–세–표–응** / PDU **비트–프레임–패킷–세그먼트–데이터** / 주소 **2계층 MAC · 3계층 IP · 4계층 포트** / **라우팅=3**, **암호화=6**, 흐름제어·재전송=4

_관련 개념: tcpip · netdevice · netbasic_

## TCP/IP 4계층 — TCP/IP Model

`네트워크 보안`  `실제 인터넷 표준` `네트워크액세스·인터넷·전송·응용` `OSI 대응` `캡슐화` `헤더 추가`

**한줄:** 실제 인터넷이 쓰는 4계층 모델 / 네트워크 액세스(OSI 1·2)·인터넷(3)·전송(4)·응용(5·6·7) / 내려갈수록 헤더가 붙는 캡슐화

**정의**

OSI가 **이론적 참조 모델**이라면, TCP/IP는 **실제로 인터넷이 돌아가는 방식**(사실상 표준). 계층이 **4개**로 더 단순하다.

**OSI ↔ TCP/IP 대응 (그대로 출제)**

- **4 응용 (Application)**: OSI **5·6·7**(세션+표현+응용)을 **하나로**. HTTP·FTP·SMTP·DNS·SNMP

- **3 전송 (Transport)**: OSI **4**와 동일. **TCP·UDP**, 포트 번호

- **2 인터넷 (Internet)**: OSI **3**과 동일. **IP·ARP·ICMP·IGMP**, 라우팅

- **1 네트워크 액세스 (Network Access)**: OSI **1·2**(물리+데이터링크)를 **하나로**. 이더넷, MAC 주소

**핵심: 위아래 양 끝이 합쳐졌다** — 응용에서 3개(5·6·7), 맨 아래에서 2개(1·2).

**캡슐화 (Encapsulation)**

데이터가 **아래 계층으로 내려갈 때마다 그 계층의 헤더가 덧붙는다**.

```
데이터 → [TCP헤더|데이터] → [IP헤더|TCP헤더|데이터] → [프레임헤더|IP헤더|TCP헤더|데이터|트레일러]
```

받는 쪽은 반대로 **헤더를 하나씩 벗기며(역캡슐화)** 위로 올린다. 그래서 **패킷을 분석하면 계층별 헤더가 겹겹이** 보인다.

> **시험 한줄정리:** TCP/IP 4계층 = **네트워크액세스(OSI 1·2) · 인터넷(3) · 전송(4) · 응용(5·6·7)** / 인터넷 계층=**IP·ARP·ICMP**, 전송=**TCP·UDP** / 내려갈 때 **헤더가 붙는 캡슐화**

_관련 개념: osi · tcpudp · netproto_

## OSI 계층별 네트워크 장비 — Repeater · Switch · Router · Gateway

`네트워크 보안`  `1계층 리피터·허브` `2계층 브리지·스위치` `3계층 라우터` `L4 스위치` `콜리전/브로드캐스트 도메인`

**한줄:** 1계층 리피터·허브(신호) / 2계층 브리지·스위치(MAC) / 3계층 라우터(IP·경로) / 4계층 L4스위치(포트) / 7계층 게이트웨이(프로토콜 변환)

**계층별 장비 (그대로 출제)**

- **1 물리 — 리피터(Repeater)**: 약해진 **신호를 증폭·재생**해 거리 연장. **허브(Hub)**: 멀티포트 리피터, **받은 걸 모든 포트로 그냥 복사**
- **2 데이터링크 — 브리지(Bridge)**: **MAC 주소**를 보고 필요한 쪽으로만 전달(소프트웨어 처리). **스위치(Switch)**: 브리지를 **하드웨어(ASIC)**로 구현해 빠름. **MAC 주소 테이블**로 포트 결정
- **3 네트워크 — 라우터(Router)**: **IP 주소**로 **다른 네트워크 간 최적 경로 결정(라우팅)**. L3 스위치도 여기
- **4 전송 — L4 스위치**: **포트 번호**까지 보고 분배 → **부하 분산(로드밸런싱)**
- **7 응용 — 게이트웨이(Gateway)**: **서로 다른 프로토콜 간 변환**. L7 스위치

**허브 vs 스위치 — 보안 차이 (중요)**

- **허브 (1계층)**: 받은 데이터를 **모든 포트에 복사** → 남의 트래픽도 내 포트로 온다 → **스니핑(도청)에 취약**. 모두가 **하나의 콜리전 도메인** → 충돌 많음

- **스위치 (2계층)**: **목적지 MAC의 포트로만** 전달 → 기본적으로 **스니핑이 어렵다**. **포트마다 콜리전 도메인 분리**

**[단, 스위치도 안전하지 않다]** **MAC 플러딩**(주소 테이블을 가짜로 채워 허브처럼 동작시킴)·**ARP 스푸핑**으로 스위치 환경에서도 스니핑이 가능하다.

**도메인 정리 (자주 나옴)**

- **콜리전(충돌) 도메인** — 충돌이 일어나는 범위. **허브**는 전체가 하나, **스위치**는 **포트별로 분리**
- **브로드캐스트 도메인** — 브로드캐스트가 퍼지는 범위. **라우터가 분리**한다(스위치는 못 나눔, 단 **VLAN**으로는 가능)

> **시험 한줄정리:** **1 리피터·허브**(신호) · **2 브리지·스위치**(MAC) · **3 라우터**(IP·라우팅) · **4 L4스위치**(포트·부하분산) · **7 게이트웨이**(프로토콜 변환) / **허브=스니핑 취약**, 스위치=포트별 전달 / 콜리전은 **스위치**가, 브로드캐스트는 **라우터**가 분리

_관련 개념: osi · netbasic · tcpip_

## TCP vs UDP — Transmission Control / User Datagram Protocol

`네트워크 보안`  `TCP=연결형·신뢰성` `UDP=비연결·빠름` `3-way handshake` `헤더 20 vs 8바이트` `SYN·ACK·FIN·RST`

**한줄:** TCP=연결형·신뢰성 보장(3-way handshake·재전송·흐름제어, 헤더 20B) / UDP=비연결·빠르고 가벼움(헤더 8B, 실시간·DNS)

**비교 (표째로 출제)**

- **TCP (전송 제어)**: **연결형**(3-way handshake) · **신뢰성 보장**(순서 보장·확인응답·**재전송**) · **흐름 제어·혼잡 제어** · 헤더 **20바이트** · 느리지만 정확
용도: **HTTP·FTP·SMTP** 등 정확해야 하는 것

- **UDP (사용자 데이터그램)**: **비연결형** · **신뢰성 없음**(순서·도착 보장 X) · 제어 기능 없음 · 헤더 **8바이트** · **빠르고 가벼움**
용도: **DNS·DHCP·SNMP·TFTP**, 실시간 **스트리밍·VoIP**

**3-way handshake (연결 수립)**

- **1 SYN** — 클라이언트 → 서버: “연결하자”

- **2 SYN+ACK** — 서버 → 클라이언트: “좋다, 나도 연결하자”

- **3 ACK** — 클라이언트 → 서버: “확인”

**종료는 4-way**: **FIN → ACK → FIN → ACK**(양쪽이 각자 끊어야 해서 한 단계 더 많다).**[보안 연결]** **SYN 플러딩**=①만 잔뜩 보내고 ③을 안 보내 서버의 **연결 대기 자원(백로그)을 고갈**시키는 DoS. 그래서 3-way handshake는 **공격과 세트로** 나온다.

**TCP 제어 플래그 6가지**

**URG**(긴급) · **ACK**(확인응답) · **PSH**(즉시 전달) · **RST**(연결 강제 종료·거부) · **SYN**(연결 요청) · **FIN**(정상 종료).
포트 스캔이 이 플래그를 조합해 이뤄진다(**SYN 스캔**·FIN 스캔 등) — 응답이 **SYN+ACK면 열림**, **RST면 닫힘**.

> **시험 한줄정리:** **TCP**=연결형·신뢰성(3-way **SYN→SYN+ACK→ACK**, 종료 **4-way**)·흐름/혼잡제어·헤더 **20B** / **UDP**=비연결·무보장·헤더 **8B**·빠름(DNS·스트리밍) / 플래그 **URG·ACK·PSH·RST·SYN·FIN**

_관련 개념: tcpip · netproto · osi_

## 주요 프로토콜 (IP · ARP · ICMP) — IP · ARP/RARP · ICMP · IGMP

`네트워크 보안`  `IP=비연결·비신뢰` `ARP: IP→MAC` `RARP: MAC→IP` `ICMP=오류·제어(ping)` `ARP 스푸핑`

**한줄:** IP=주소지정·라우팅(비연결·비신뢰) / ARP=IP를 MAC으로 변환(RARP는 반대) / ICMP=오류·상태 메시지(ping) / IGMP=멀티캐스트

**인터넷 계층 4총사**

- **IP**(Internet Protocol) — **주소 지정과 경로 배정(라우팅)**. **비연결형·비신뢰성**(도착·순서를 보장하지 않음 → 신뢰성은 **TCP가 담당**)
- **ARP**(Address Resolution Protocol) — **IP 주소 → MAC 주소** 변환. 실제 전송은 MAC으로 하므로 반드시 필요
- **RARP**(Reverse ARP) — **MAC → IP**(반대). 자기 IP를 모르는 장비가 사용
- **ICMP**(Internet Control Message Protocol) — **오류 보고·상태 확인** 메시지. **`ping`·`traceroute`**가 이걸 씀
- **IGMP**(Internet Group Management Protocol) — **멀티캐스트** 그룹 관리

**ARP 스푸핑 (매우 자주 출제)**

ARP에는 **인증이 없다** — 누가 “그 IP는 내 MAC이야”라고 응답해도 **그대로 믿는다**. 공격자가 **위조 ARP 응답**을 뿌려 피해자의 ARP 캐시를 오염시키면, 트래픽이 **공격자를 거쳐** 흐른다(**중간자 공격·스니핑**). **스위치 환경에서도 도청이 가능해지는** 대표 기법.**[대응]** **정적(static) ARP 등록**, ARP 캐시 **모니터링**(`arp -a`), **동적 ARP 검사(DAI)**·포트 보안, 암호화 통신(HTTPS)으로 **가로채도 못 읽게**.

**ICMP 악용**

**스캐닝**(ping 스윕으로 살아있는 호스트 탐색) · **ICMP 플러딩**(대량 전송으로 마비) · **스머프(Smurf) 공격**(출발지를 피해자로 위조해 **브로드캐스트**로 ping → 모든 응답이 피해자에게 몰림) · **터널링**(ICMP 페이로드에 데이터를 숨겨 유출).
그래서 방화벽에서 **불필요한 ICMP를 차단**하고, **디렉티드 브로드캐스트를 비활성화**한다.

> **시험 한줄정리:** **IP**=주소·라우팅(**비연결·비신뢰**) / **ARP**=IP→MAC, **RARP**=MAC→IP / **ICMP**=오류·제어(ping·traceroute) / **IGMP**=멀티캐스트 / **ARP는 인증이 없어 스푸핑**→중간자·스니핑, 대응=정적 ARP·DAI

_관련 개념: tcpip · tcpudp · netdevice_
