# 네트워크 보안 기술 — VPN·통합관리·무선·RFID

> 자동 생성 — 원본은 `cards/vpnetc.js`. 직접 수정 금지.

## 가상사설망 (VPN) · SSL VPN · PPTP · L2TP — VPN · SSL VPN · PPTP · L2TP

`네트워크 보안`  `터널링+암호화+인증` `2계층 PPTP·L2TP` `3계층 IPSec` `SSL VPN=브라우저` `L2TP는 암호화 없음`

**한줄:** 공중망을 사설망처럼 쓰는 기술(터널링·암호화·인증) / 계층별 2계층 PPTP·L2TP, 3계층 IPSec, 응용 SSL VPN / L2TP는 자체 암호화가 없어 IPSec과 함께 씀

**정의 · 3요소**

**VPN(Virtual Private Network)** — 공중망(인터넷) 위에 **가상의 전용선**을 만들어 사설망처럼 안전하게 쓰는 기술. 전용선보다 **훨씬 저렴**하다.
- **터널링(Tunneling)** — 패킷을 **다른 패킷으로 감싸** 통과시킴
- **암호화** — 내용을 못 읽게 (기밀성)
- **인증·무결성** — 상대가 맞는지, 변조되지 않았는지

**터널링 프로토콜 — 계층별 정리 (출제)**

- **2계층(데이터링크)**: **PPTP · L2F · L2TP**
- **3계층(네트워크)**: **IPSec**
- **4계층 이상(응용)**: **SSL/TLS VPN**
**PPTP**(Point-to-Point Tunneling Protocol) — 마이크로소프트 주도, 구현이 **간단**하지만 **보안이 취약**해 현재는 권장되지 않는다.
**L2TP**(Layer 2 Tunneling Protocol) — PPTP와 L2F를 결합. **자체 암호화 기능이 없다** → 실무에서는 반드시 **IPSec과 결합(L2TP/IPSec)**해서 쓴다. **이 점이 시험 함정**.

**SSL VPN vs IPSec VPN**

- **SSL VPN**: 응용 계층. **웹 브라우저만 있으면 되어** 별도 클라이언트 설치가 거의 필요 없다. **재택·이동 근무자**의 원격 접속에 적합하고 방화벽 통과가 쉽다(443).
➖ 보호 범위가 **특정 응용 중심**.

- **IPSec VPN**: 3계층. **모든 IP 트래픽을 통째로** 보호한다. **본사–지사 간 상시 연결(Site-to-Site)**에 적합.
➖ **전용 클라이언트·설정**이 필요하고 NAT 통과에 제약이 있다.

> **시험 한줄정리:** VPN=터널링+암호화+인증으로 공중망을 사설망처럼 / 계층 **2계층 PPTP·L2F·L2TP** · **3계층 IPSec** · **응용 SSL VPN** / **PPTP=간단하나 취약**, **L2TP=자체 암호화 없음 → IPSec과 결합** / **SSL VPN=브라우저·원격 사용자** vs **IPSec VPN=전체 IP 보호·지사 간**

_관련 개념: ipsec · firewall · http_

## IPSec VPN (AH · ESP · IKE) — IPSec · AH · ESP · IKE

`네트워크 보안`  `AH=인증만·암호화 없음` `ESP=암호화+인증` `IKE=키 관리` `전송 모드 vs 터널 모드` `SA·SPI`

**한줄:** 3계층 보안 표준 / AH=인증·무결성만(암호화 X), ESP=암호화+인증 / 키 관리는 IKE(UDP 500) / 전송 모드=페이로드만, 터널 모드=IP 패킷 전체 캡슐화

**두 개의 보안 헤더 — AH vs ESP (최다 출제)**

- **AH (Authentication Header)**: **인증·무결성·재전송 방지**만 제공.
**❌ 암호화는 제공하지 않는다** → 내용이 그대로 보인다.
프로토콜 번호 **51**.

- **ESP (Encapsulating Security Payload)**: **암호화 + 인증·무결성**을 모두 제공(기밀성까지).
실무에서 주로 쓰인다.
프로토콜 번호 **50**.

**[시험 함정]** “AH가 기밀성(암호화)을 제공하는가?” → **아니오**. 암호화가 필요하면 **ESP**다. 헷갈리면 **A=Authentication(인증만)**으로 기억.

**키 관리 = IKE**

**IKE(Internet Key Exchange)**가 **키 교환과 관리**를 담당한다 — “IPSec의 키 관리 담당은?” 하면 **IKE**가 답.
- **Diffie-Hellman** 방식으로 **안전하게 세션 키를 합의**
- 양쪽의 보안 정책 묶음인 **SA(Security Association)**를 설정. SA를 구분하는 번호가 **SPI**
- **UDP 500**번 사용(NAT 통과 시 4500). ISAKMP·Oakley를 기반으로 함
- 1단계에서 **안전한 통로**를 만들고, 2단계에서 **실제 데이터용 SA**를 만든다

**동작 모드 — 전송 vs 터널**

- **전송 모드 (Transport)**: **페이로드(데이터)만** 보호하고 **원래 IP 헤더는 그대로** 둔다.
→ **종단 간(호스트 ↔ 호스트)** 통신에 사용. 출발지·목적지가 **노출**된다.

- **터널 모드 (Tunnel)**: **IP 헤더를 포함한 패킷 전체를 캡슐화**하고 **새 IP 헤더**를 붙인다.
→ **게이트웨이 간(VPN 장비 ↔ VPN 장비)**에 사용. **원래 주소가 숨겨져** 더 안전. **VPN의 기본 모드**.

> **시험 한줄정리:** IPSec=3계층 보안 / **AH=인증·무결성만(암호화 ❌, 프로토콜 51)** vs **ESP=암호화+인증(50)** / **키 관리=IKE**(Diffie-Hellman·**SA**·SPI·**UDP 500**) / **전송 모드=페이로드만(종단 간)** vs **터널 모드=패킷 전체 캡슐화+새 IP 헤더(게이트웨이 간·VPN 기본)**

_관련 개념: vpn · netlayer · firewall_

## NAC (네트워크 접근 제어) — Network Access Control

`네트워크 보안`  `단말 보안상태 검사` `정책서버·차단서버·에이전트` `802.1X 인증` `치료(Remediation)` `비인가 단말 차단`

**한줄:** 네트워크에 붙으려는 단말의 신원과 보안 상태(백신·패치)를 검사해 접속을 통제 / 구성=정책서버·차단(인증)서버·에이전트·콘솔

**정의 — 방화벽과 무엇이 다른가**

방화벽이 **경계를 지나는 트래픽**을 통제한다면, **NAC**은 **네트워크에 접속하려는 단말 자체**를 통제한다.**[핵심 발상]** “**누구인지(인증)**”뿐 아니라 “**이 PC가 안전한 상태인가(백신·패치·설정)**”까지 확인하고, 기준에 못 미치면 **격리·치료 후에** 들여보낸다. 내부망으로 **웜·랜섬웨어가 유입되는 것을 막는** 것이 목적.

**구성 요소**

- **정책 관리 서버** — 접근·보안 **정책을 수립·배포**하고 이력을 관리(두뇌)
- **차단·인증 서버(집행 장치)** — 정책에 따라 **실제로 허용·격리·차단**을 수행
- **에이전트** — 단말에 설치되어 **보안 상태를 점검·보고**하고 치료를 수행(에이전트 없는 방식도 있음)
- **콘솔** — 관리자용 모니터링·설정 화면

**주요 기능 · 통제 방식**

**주요 기능**
- **사용자·단말 인증**과 **비인가 단말 차단**
- **무결성 점검** — 백신 설치·최신 여부, OS 보안 패치, 필수 프로그램
- **격리·치료(Remediation)** — 미흡한 단말을 **치료 전용망으로 보내** 패치·업데이트 후 재검사
- **IP·자산 관리**, 접속 이력 로그
**통제 방식(발전 흐름)** — 초기 **VLAN 분리** 방식과 **ARP 제어** 방식에서, 표준 인증 기반인 **IEEE 802.1X**(스위치 포트 단계에서 인증) 방식으로 발전했고, 여기에 **에이전트**를 더해 단말 상태까지 검사하는 형태가 일반적이다.

> **시험 한줄정리:** NAC=**접속하려는 단말**을 통제(방화벽=트래픽) / 인증 + **보안 상태 검사(백신·패치)** → 미흡하면 **격리·치료 후 재검사** / 구성 **정책관리서버·차단(인증)서버·에이전트·콘솔** / 표준 인증은 **IEEE 802.1X** / 목적=웜·비인가 단말의 내부망 유입 차단

_관련 개념: esm · wlan · firewall_

## ESM · SIEM — Enterprise Security Management · SIEM

`네트워크 보안`  `에이전트·매니저·콘솔` `보안장비 통합관제` `SIEM=전사 로그·빅데이터` `상관분석` `장기보관·컴플라이언스`

**한줄:** ESM=방화벽·IDS 등 보안장비 로그를 통합해 실시간 관제(에이전트·매니저·콘솔) / SIEM=보안장비를 넘어 전사 IT 로그를 빅데이터로 수집·장기 분석

**ESM — 왜 필요한가**

방화벽·IDS·IPS·백신·VPN이 **각자 따로 경보**를 쏟아내면 관리자가 감당할 수 없다. **ESM(Enterprise Security Management)**은 이 **보안 장비들의 로그·이벤트를 한곳에 모아** 통합 관제한다.**[핵심 가치 — 상관 분석]** 개별 장비에서는 사소해 보이는 이벤트도 **모아서 연관지으면** 하나의 공격 흐름이 드러난다(예: 포트 스캔 → 로그인 실패 반복 → 성공 → 대용량 전송). 이것이 **상관 분석(Correlation)**이다.

**ESM 구성 요소**

- **에이전트(Agent)** — 각 보안 장비에 붙어 **로그를 수집·정규화해 전송**
- **매니저(Manager)** — 수집한 이벤트를 **저장·분석·상관분석**하고 정책에 따라 경보 발생(핵심 엔진)
- **콘솔(Console)** — 관리자가 보는 **모니터링·대응 화면**

**ESM vs SIEM (차이점 — 출제)**

- **ESM**: 대상 = **보안 장비** 중심(방화벽·IDS·백신…)
초점 = **실시간 관제·경보 대응**
데이터 = 비교적 **정형화된 보안 이벤트**, 보관 기간 짧음

- **SIEM**: 대상 = **보안 장비 + 서버·네트워크·애플리케이션·DB 등 전사 IT**
초점 = **빅데이터 기반 장기 분석·포렌식·컴플라이언스**
데이터 = 비정형 포함 **방대한 로그**, **장기 보관**

**한 줄 정리**: **ESM은 '보안 장비 실시간 관제', SIEM은 '전사 로그 통합·장기 분석'**. SIEM이 ESM보다 **범위가 넓고 분석 지향**이다.

> **시험 한줄정리:** **ESM**=보안장비 로그 통합 **실시간 관제**, 구성 **에이전트·매니저·콘솔**, 핵심=**상관 분석** / **SIEM**=보안장비를 넘어 **전사 IT 로그**를 **빅데이터**로 수집·**장기 보관·분석**(포렌식·컴플라이언스) → **SIEM이 범위가 더 넓다**

_관련 개념: nac · ids · linuxlog_

## 무선 LAN 보안 (WEP · WPA · WPA2) — Wireless LAN Security

`네트워크 보안`  `WEP=RC4·IV 취약` `WPA=TKIP` `WPA2=AES-CCMP·802.11i` `개인(PSK) vs 기업(802.1X)` `Rogue AP`

**한줄:** 전파라 도청이 쉬움 / WEP(RC4·IV 짧아 취약) → WPA(TKIP) → WPA2(AES-CCMP·802.11i) → WPA3 / 운영모드 개인(PSK) vs 엔터프라이즈(802.1X+RADIUS)

**무선의 근본 취약점**

유선은 **선에 물려야** 하지만 무선은 **전파가 닿는 곳이면 누구나** 수신할 수 있다.
- **도청(스니핑)**이 매우 쉽다 — 물리적 침입 없이 주차장에서도 가능(**워 드라이빙**)
- **Rogue AP(비인가 AP)** — 몰래 설치한 AP로 내부망 우회 침투
- **이블 트윈(Evil Twin)** — 정상 AP와 **같은 SSID**의 가짜 AP로 유인해 중간자 공격
- **재밍**(전파 방해)으로 서비스 거부
**SSID 숨김·MAC 주소 필터링**은 **보조 수단일 뿐**이다 — 둘 다 쉽게 우회된다(시험 포인트).

**보안 기술의 진화**

- **WEP** — **RC4** 사용. **정적 키**를 공유하고 **IV(초기벡터)가 24비트로 짧아 재사용**됨 → **단시간에 크랙**. 사용 금지.

- **WPA** — **TKIP**(RC4 기반이나 **키를 동적으로 변경**) + **MIC**로 무결성 보강. WEP 장비를 쓰면서 급히 보완한 **과도기** 규격.

- **WPA2** — **AES-CCMP** 채택. **IEEE 802.11i** 표준을 온전히 구현한 **사실상의 표준**.

- **WPA3** — **SAE** 방식으로 사전 대입 공격에 강해지고 순방향 비밀성 제공.

**암기 짝**: **WEP=RC4 · WPA=TKIP · WPA2=AES(CCMP)**.

**운영 모드 — 개인 vs 엔터프라이즈**

- **개인 모드 (Personal · PSK)**: **사전 공유 키(비밀번호)**를 모두가 나눠 쓴다. 가정·소규모용.
➖ 키가 **한 명만 유출돼도** 전체가 위험하고, 약한 비밀번호는 **사전 공격**에 뚫린다.

- **엔터프라이즈 모드 (Enterprise)**: **IEEE 802.1X + RADIUS 인증 서버**로 **사용자마다 개별 인증**. 기업용.
➕ 퇴사자 계정만 막으면 되고, 사용자별 키가 달라 훨씬 안전.

> **시험 한줄정리:** 무선=전파라 **도청 쉬움**(워드라이빙·**Rogue AP**·이블트윈), **SSID 숨김·MAC 필터링은 보조 수단** / **WEP(RC4·IV 짧아 취약) → WPA(TKIP) → WPA2(AES-CCMP·802.11i) → WPA3(SAE)** / 모드 **개인=PSK 공유키** vs **엔터프라이즈=802.1X+RADIUS 개별 인증**

_관련 개념: rfid · nac · sniffing_

## RFID · USN 보안 — RFID · USN Security

`네트워크 보안`  `태그·리더·서버` `능동형 vs 수동형` `복제·추적 위협` `Kill 명령·패러데이 우리` `블로커 태그`

**한줄:** RFID=전파로 태그 정보를 읽는 기술(태그·리더·서버) / 위협=도청·복제·추적(프라이버시) / 대책=Kill 명령·패러데이 우리·블로커 태그·재암호화·인증

**RFID · USN이란**

**RFID(Radio Frequency IDentification)** — 무선 주파수로 **태그에 담긴 정보를 접촉 없이 읽는** 기술(교통카드·물류·출입증).
- 구성: **태그(Tag)** + **리더(Reader)** + **미들웨어·서버**
- **능동형** — 자체 **배터리**가 있어 인식 거리가 길다 / **수동형** — 배터리 없이 **리더의 전파로 동작**, 싸고 반영구적이나 거리가 짧다
**USN(Ubiquitous Sensor Network)** — 여기저기 배치한 **센서**가 정보를 수집해 네트워크로 전달하는 체계. RFID가 그 입구 역할을 한다.

**보안 위협**

- **도청(스니핑)** — 태그·리더 사이 무선 구간을 가로챔
- **복제·위조(Cloning)** — 읽은 정보로 **똑같은 태그를 만들어** 출입·결제에 악용
- **스푸핑** — 정상 태그·리더인 척 속임
- **재전송(Replay) 공격** — 가로챈 응답을 **그대로 다시 보내** 인증 통과
- **프라이버시 침해·위치 추적** — 소지품의 태그가 계속 응답해 **사람의 동선이 추적**된다(RFID 고유의 문제)
- **DoS·재밍** — 전파 방해로 인식 불가

**보안 기술 (대책)**

- **Kill 명령어** — 구매·사용 후 태그를 **영구 비활성화**(가장 확실하지만 재사용 불가)
- **패러데이 우리(Faraday Cage)** — **전파를 차단하는 금속 용기·지갑**에 넣어 읽히지 않게
- **블로커 태그(Blocker Tag)** — 리더에 **혼란스러운 응답을 흘려** 특정 태그를 읽지 못하게 방해
- **능동 방해(Active Jamming)** — 방해 전파 발생(주변 영향이 커 제한적)
- **재암호화(Re-encryption)** — 태그 값을 **주기적으로 바꿔** 추적을 막음
- **해시 기반 접근 제어·상호 인증 프로토콜** — 태그 ID를 그대로 노출하지 않고 **매번 다른 값**으로 응답

> **시험 한줄정리:** RFID=**태그·리더·서버**, **능동형(배터리·장거리)** vs **수동형(무배터리·단거리)** / 위협=도청·**복제**·스푸핑·재전송·**위치 추적(프라이버시)** / 대책=**Kill 명령·패러데이 우리·블로커 태그**·재암호화·해시 기반 인증

_관련 개념: wlan · nac · sniffing_
