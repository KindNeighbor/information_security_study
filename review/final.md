# 1과목 시스템 보안

## ★ 반복 오답

**LSA · SAM · SRM** — "참 헷갈린다"고 직접 지목한 항목

- **SAM = 인사팀 장부.** Security **Account Manager**. 로컬 계정·해시 DB. **장부는 판단하지 않는다**
- **LSA = 1층 발급 창구.** Local Security **Authority**. 인증하고 **액세스 토큰 발급**. `lsass.exe`, 사용자 모드
- **SRM = 각 층 문 앞 경비원.** Security **Reference Monitor**. 토큰 vs DACL 비교. **커널 모드**
- **가장 빠른 구분 — LSA·SAM은 로그온 때 한 번 / SRM은 접근할 때마다 매번**
- **「SAM이 접근 허용을 판단한다」는 무조건 오답**

**utmp · wtmp · btmp** — 2회 오답

- **utmp = 현재 접속 중**(`who`, `w`) / **wtmp = 접속 이력**(`last`) / **btmp = 실패**(`bad`, `lastb`)

**NTFS 4종**

- **ADS = 은닉**(보이지 않는 스트림) / **VSS = 백업**(섀도 복사본) / **EFS = 파일·폴더 암호화** / **BitLocker = 볼륨 전체**

**이벤트 로그 종류**

- **로그온 성공·실패, 권한 사용, 감사 = 보안 로그** / 시스템 로그 = 드라이버·서비스 / 응용 프로그램 로그 = 앱

**감사 항목 두 개가 이름이 비슷하다**

- **「로그온 이벤트 감사」 = 이 컴퓨터에 로그온한 기록**
- **「계정 로그인 이벤트 감사」 = 이 계정을 검증해준 기록** ← **도메인 계정이면 이쪽**(검증은 DC가 한다)

**관리 공유**

- 달러(`$`)가 붙어 **목록에서 숨겨지고 관리자 권한 필요**, 기본 **활성화**
- **IPC 공유는 프로세스 간 통신용**(널 세션 악용) / 드라이브 공유는 **C 드라이브 관리 공유**

## 1과목 — 2019-03 회차에서 나온 것

**★ 루트킷의 바이너리 변조 — 「그 명령어가 평소에 보여주는 것」을 숨긴다**

명령어도 그냥 **파일**이다(`/bin/ps`, `/bin/ls`). 관리자 권한을 뺏은 공격자는 그 파일을 **가짜로 덮어쓴다.**
프로세스는 **실제로 돌고 있는데 보여주는 눈을 멀게** 하는 것.

| 명령어 | 평소에 보여주는 것 | 변조하면 숨는 것 |
|---|---|---|
| **ps, top** | 프로세스 목록 | 공격자의 **프로세스** |
| **ls, du, find** | 파일·디렉터리 | 숨겨둔 **악성 파일** |
| **w, who, last** | 접속 중인 사용자 | 공격자의 **로그인** |
| **netstat** | **네트워크 연결 목록** | **외부와의 접속** |
| **ifconfig** | **인터페이스 상태(PROMISC 포함)** | **스니핑 중이라는 사실** |

- **「접속을 숨긴다」는 netstat이지 ifconfig가 아니다** — ifconfig는 랜카드 상태만 보여준다
- **ifconfig를 변조하는 이유** — 스니퍼를 돌리면 랜카드가 **무차별 모드(PROMISC)**가 되고 `ifconfig eth0`의 플래그에 **PROMISC가 뜬다.** 그 글자를 감추려는 것
- **대응은 「파일이 바뀌었나」를 보는 것** — **tripwire · AIDE**(해시 비교), 루트킷 전용은 **chkrootkit**
- **공격자는 보여주는 눈을 멀게 하고, 방어자는 눈 자체가 바뀌었는지 확인한다**

**도구 넷은 「무엇을 하느냐」로 갈린다**

**TCP Wrapper — allow를 먼저 본다**

```
hosts.allow  →  매치되면 허용하고 끝     ← 먼저 본다
hosts.deny   →  매치되면 거부
둘 다 없으면  →  허용
```

- **allow에서 걸리면 deny는 보지도 않는다.** `hosts.allow`에 `ALL: ALL`이면 **deny가 무의미**해진다
- **실무는 반대로** — `hosts.deny`에 `ALL: ALL`(기본 차단), `hosts.allow`에 필요한 것만 = **Deny All 정책**

**PAM은 리눅스다 — 윈도우 대응은 GINA / Credential Provider**

| | 리눅스 | 윈도우 |
|---|---|---|
| 인증 방식 끼워넣기 | **PAM**(Pluggable Authentication Modules) | **GINA**(통짜 msgina.dll) → **Credential Provider**(모듈식, Vista부터) |

- 지문 표지 — **「재컴파일하지 않고 인증 방법을 변경」**, **「공유 라이브러리 묶음」**
- `/etc/pam.d/<서비스>`, 타입 **auth · account · password · session**, **required(끝까지) vs requisite(즉시 중단)**

**파일시스템 — MINIX가 나오면 리눅스**

- **ext** — MINIX FS를 보완. 최대 2G, 파일명 255byte. **접근제어·inode 수정·타임스탬프 수정 불가**, 단편화 심함
- **ext → ext2**(접근제어·타임스탬프) **→ ext3**(저널링) **→ ext4**
- **FAT·NTFS는 마이크로소프트** 것이라 MINIX와 무관

**그 밖에**

- **index.dat** = IE의 **방문 기록·쿠키·캐시 색인**. **지워도 남아** 포렌식에 쓰인다
- **크래킹 세 가지** — **모든 경우 = Brute Force / 단어 목록 = Dictionary / 미리 계산한 표 = Rainbow Table**

# 2과목 네트워크 보안

## ★ 반복 오답

**포트 스캔 판정** — 세 회차에서 반복

| | 열린 포트 | 닫힌 포트 |
|---|---|---|
| **Half Open (-sS)** | **SYN+ACK** | RST+ACK |
| **FIN · NULL · XMAS** | **무응답** | **RST** |

- **FIN·NULL·XMAS는 「조용하면 열린 것」.** 없는 답으로 있음을 안다
- 일반 — **SYN+ACK=열림 / RST=닫힘 / 무응답=필터링**
- **SYN 스캔은 RST로 끊어 로그를 안 남긴다**

**IPSec 모드** — 18회·20회 연속

- **전송(Transport) = 페이로드만, 호스트 간 직접**
- **터널(Tunnel) = 원래 IP 헤더까지 통째로 감쌈, 게이트웨이 간**
- **고리 — 당사자끼리면 전송, 대신 감싸주는 장비가 끼면 터널.** 방화벽·VPN 장비는 **터널**
- **AH = 인증만 · 프로토콜 51 / ESP = 암호화+인증 · 50** (알파벳 순서와 번호가 반대)

**Snort content 옵션 4종** — 보강한 뒤에도 또 틀림

| 옵션 | 뜻 | 기준점 |
|---|---|---|
| **offset** | **어디서부터** | 페이로드 처음 (절대) |
| **depth** | **얼마나** | 페이로드 처음 (절대) |
| **distance** | **어디서부터** | 직전 매칭 끝 (상대) |
| **within** | **얼마나** | 직전 매칭 끝 (상대) |

- **고리 — 「o·d」는 처음부터, 「di·wi」는 직전부터. 각 짝에서 앞이 위치, 뒤가 길이**
- `msg`는 **탐지에 영향 없는 정보 제공** / **drop·reject는 옵션이 아니라 룰 헤더의 action**
- 그 외 — `dsize`(페이로드 크기) · `itype`·`icode`(ICMP) · **`sameip`(Land 탐지)**

**RIP vs OSPF** — 반복

- **RIP = 거리벡터 · 홉 수 · 최대 15홉(16=도달불가) · 소규모**
- **OSPF = 링크상태 · 비용(대역폭) · 다익스트라 · 홉 제한 없음 · 대규모**

**세션 하이재킹 vs DNS 스푸핑** — 반복

- **세션 하이재킹 = RST로 끊고 새 시퀀스 전송**
- **DNS 스푸핑 = 가짜 DNS 응답을 먼저 보냄**

**메일 발신자 인증 3종** — 2회 오답. **셋 다 DNS를 써서 헷갈린다. 「DNS에 무엇을 적어두느냐」로 가른다**

- **SPF** = **발송 서버 IP 목록** (어디서 왔나)
- **DKIM** = **공개키** (누가 서명했나) — 이름에 **Keys**
- **DMARC** = **실패했을 때의 처리 정책과 보고** (어쩔까)

**방화벽 구축 형태** — 2회 오답

- 스크리닝 라우터 → 듀얼 홈드(**NIC 2개**) → 스크린드 호스트(라우터 1개 + 베스천) → **스크린드 서브넷(라우터 2개 + DMZ)**
- **고리 — 「호스트」가 붙으면 호스트 한 대, 「서브넷」이 붙으면 중간에 별도 망(DMZ)**

**IP 단편화 계산 절차**

```
① MTU 1500 → 데이터는 1480      (IP 헤더 20을 뺀다)
② offset 단위는 8바이트 → 1480 ÷ 8 = 185씩 증가
③ 마지막 조각 크기 = 남은 데이터 + 헤더 20
④ flag(MF) = 0 이면 마지막 조각
```

· **놓치는 두 가지 — offset은 8바이트 단위**, **IP 헤더 20은 조각마다 다시 붙는다**(데이터 1020이면 패킷은 1040)

**스위치 전달 방식 3가지 — 이름이 답**

|---|---|---|---|
| **Cut-through** (= Direct Switching) | **목적지 MAC 6바이트만** | 가장 빠름 | **못 함** |
| **Fragment-Free** | 앞 **64바이트** | 중간 | 충돌 조각만 |
| **Store and Forward** | **프레임 전체** | 가장 느림 | **FCS로 전부** |

· **Store(저장) and Forward(전달) = 다 받아 저장한 뒤 보낸다** → 그래서 오류 검사가 되고 느리다

**ARP를 쓰는 공격 두 가지**

| | 누구 행세 | 보내는 방식 |
|---|---|---|
| **ARP Spoofing** | **특정 호스트** 행세 | 그 대상에게 |
| **ARP Redirect** | **라우터** 행세 | **브로드캐스트로 전체에게, 주기적으로** |

· **둘 다 ARP Reply를 보낸다.** 묻지도 않았는데 **「내가 걔야」라고 답**을 보낸다(Gratuitous ARP)
· **왜 통하나 — ARP에는 인증이 없어서 요청하지 않은 응답도 캐시에 그냥 들어간다**
· **「조작된 ARP Request를 전송」은 오답.** Request는 「누구세요?」를 묻는 것이라 거짓말을 할 수 없다
· **지문에 ARP가 쓰여 있으면 답도 ARP 계열**

**L2 스위치 환경의 스니핑 — 공격 계층은 제각각이다** (10-03 질문)

· **「L2 스위치로 구성된 환경」은 공격의 계층이 아니라 「상황」**을 말한다
· 허브는 모든 포트로 뿌려서 그냥 들리지만, **스위치는 목적지 포트로만 보내서 안 들린다** → **억지로 내 쪽으로 끌어와야** 한다

| 공격 | 계층 | 수법 |
|---|---|---|
| **MAC Flooding (Switch Jamming)** | **2** | MAC 테이블을 넘치게 해 **허브처럼** 만든다 |

| **ICMP Redirect** | **3** | 「경로가 바뀌었다」고 속인다 |
| **DNS Spoofing** | **7** | 가짜 주소를 알려준다 |

· **공통 목적은 하나 — 내 쪽으로 오게 만든다**
· **L2 스위치 = MAC으로 전달 / L3 스위치 = IP까지 보고 라우팅.** 브로드캐스트 도메인을 나누려면 **L3**

· **① 포트 미러링(Port Mirroring, SPAN)** — 스위치가 **트래픽을 복사해 모니터링 포트로** 보내준다 (**합법적 모니터링** 수단)

· 탐지 — **비동기화 상태 · Ack Storm · 패킷 유실과 재전송 증가 · 예상치 못한 리셋**
· **공격자가 시퀀스를 틀어놓으면 서버와 클라이언트가 서로 「내 번호가 맞다」며 ACK를 끝없이 주고받는다**

**소극적 공격 vs 적극적 공격**
· **소극적(Passive) = sniffing · eavesdropping · tapping · 트래픽 분석** — 가만히 듣는다. **탐지가 어려워 예방(암호화)이 중요**

· WEP(**RC4**, IV 24비트) → WPA(**TKIP**, RC4 기반, 802.11i의 중간 단계) → **WPA2(AES)** → WPA3(**SAE** + 순방향 기밀성)
· 지문에 **「RSN으로도 불린다」**가 있으면 **WPA2**

**포트 미러링(SPAN) — 미러 = 거울 = 복사본을 하나 더**

```
평소 스위치 :  A → B 트래픽이 B 포트로만 간다
미러링 설정 :  A → B 로 가고  ↘ 복사본이 모니터링 포트로도 한 부 더
```

· **원본은 정상적으로 목적지로 간다.** 복사본만 더 보내준다
· 왜 필요한가 — **스위치는 목적지 포트로만 보내서** IDS·분석기를 꽂아도 남의 트래픽이 안 보인다
· **스위치 관리자가 설정하는 합법적 기능.** ARP Spoofing은 **스위치 협조 없이 속여서** 끌어오는 공격 — **목적은 같고 수단이 정반대**
· **무차별 모드와 짝** — 스위치가 보내줘도 랜카드가 자기 MAC이 아니면 버리므로 둘 다 필요

**TCP Open vs Half Open — 마지막 패킷이 ACK냐 RST냐**

```
TCP Open(Connect) :  SYN → SYN+ACK → ACK   ← 3-way 완성. 로그 남음
TCP Half Open(SYN):  SYN → SYN+ACK → RST   ← 끊어버림.  로그 안 남음
```

· **반쯤 열고 닫아버려서** 서버 애플리케이션이 「연결됐다」고 기록할 기회가 없다

**세션 하이재킹은 「빼앗는」 것이지 「죽이는」 것이 아니다**
· 서버를 마비시키면 **빼앗을 세션도 없어진다.** 목적이 정반대
· **DoS = 못 쓰게 만든다 / 하이재킹 = 내가 대신 쓴다**
· 「데이터 처리율을 감소시키고 대기 상태에 빠지게 한다」는 **DoS 설명**이다

**서브넷 마스크는 항상 32비트**

```
255.255.255.0 = 11111111.11111111.11111111.00000000
                └──────────── 32비트 ────────────┘
                     앞의 1이 24개  →  "/24"
```

· **「/24」는 마스크의 길이가 아니라 「앞에서부터 1이 24개」**라는 뜻. 전체는 여전히 32비트
· **마스크는 IP 주소에 겹쳐 쓰는 것**이라 길이가 같아야 한다
· **서브넷팅은 논리적 분할이다** — 「각 서브넷이 모여 **물리적** 네트워크를 이룬다」는 오답

**★ DRDoS — 10-03~04에 세 번 나와 두 번 틀림**
· **지문 첫 줄이 「에이전트 설치의 어려움을 보완한」**이면 **답은 봇넷이 아니다**(에이전트를 설치하는 게 봇넷) — **「A의 어려움을 보완한 것」이면 답은 A가 아니다**
· **결정적 표지 — 「정상적인 서비스를 제공 중인 서버를 Agent로 활용」**

| | 쓰는 것 | 준비 |
|---|---|---|
| **Botnet** | **감염시킨 좀비 PC** | 악성코드를 심어야 한다(어렵다) |
| **DRDoS** | **감염되지 않은 정상 서버** | **아무 준비도 필요 없다** |

· **IP 위조는 「수단」이고 「정상 서버를 쓴다」가 「정체」다.** 지문에 위조 얘기가 없어도 DRDoS일 수 있다

**리피터 vs 허브 — 포트 개수 차이**
· **리피터 = 신호 증폭·재생(포트 2개)** / **허브 = 멀티포트 리피터 = 연결 집중 장치(포트 여러 개)**
· **둘 다 1계층.** 「멀티포트 리피터·연결 집중 장치」가 나오면 **허브**

**ICMP 주요 타입 — 다른 문제에서 전부 나온다**

| Type | 이름 | 어디서 나오나 |
|---|---|---|
| **0 / 8** | Echo **Reply** / Echo **Request** | **ping** (짝) |
| **3** | **Destination Unreachable** | **REJECT · UDP 스캔(닫힌 포트)** |
| **4** | **Source Quench** | **혼잡 제어** — Quench=가라앉히다, 「출발지를 진정시켜라=천천히 보내」 |
| **5** | **Redirect** | **ICMP Redirect 공격**(경로 변경) |
| **11** | **Time Exceeded** | **traceroute**가 쓰는 것 |

· **ICMP = Internet Control Message**(제어 메시지·오류 통보) / **IGMP = Internet Group Management**(멀티캐스트 그룹)
· **G가 보이면 Group = 멀티캐스트**

**도구는 묶음으로 두 개만 — 셋이 한 묶음이면 남는 하나가 답**
· **SIEM 3대 — Splunk · QRadar · ArcSight**
· **포렌식 2대 — EnCase · FTK**
· EnCase가 SIEM 자리에 끼면 바로 걸린다(3과목 도구)

**VPN 터널링에 가짜로 들어오는 건 R로 시작한다**
· **진짜 — PPTP · L2F · L2TP · IPSec · SSL/TLS**
· **가짜 — RSVP**(Resource ReSerVation, **자원 예약**·QoS) · **RTP**(Real-time Transport, **음성·영상 전송**·VoIP)
· 둘 다 **「나르는 터널」이 아니라 예약하거나 실시간 데이터를 보내는 것**

**AP = Access Point (무선 접속점, 무선 공유기)** — 무선과 유선을 잇는 다리

| 관련 용어 | AP와의 관계 |
|---|---|
| **SSID** | **AP가 뿌리는 이름표** |
| **Rogue AP(불법 AP)** | **가짜 AP를 설치**해 사람들이 붙게 만든다 |
| **Infrastructure 모드** | **AP를 거쳐** 통신 ↔ **Ad Hoc**은 AP 없이 단말끼리 |
| **WEP·WPA·WPA2** | **AP와 단말 사이** 무선 구간 암호화 |
| **KRACK** | AP와 단말의 **키 교환 절차** 취약점 |

**무선랜 공격 — 물리적이냐 기술적이냐**
· **물리적** — 장비 도난·파손, **구성 설정 초기화**(AP 본체에 손을 대야 한다)
· **기술적** — **전파 방해(재밍) · 불법 AP · 도청** (전파만으로 된다)
· 문제에 **「네트워크를 통해」**가 있으면 **원격으로 가능한 것**을 묻는다

**방화벽 4유형 — 「요청을 받은 것으로 가장」은 상태검사로 막는다**

| 유형 | 계층 | 특징 |
|---|---|---|
| **패킷 필터링** | 3·4 | 헤더만, **상태 모름**, 빠름 |
| **회로 레벨 게이트웨이** | 5 | SOCKS |
| **응용 레벨 게이트웨이** | 7 | 프록시, 정밀하지만 느림 |
| **상태 기반 검사(Stateful)** | — | **세션 테이블 유지. 현재 주류** |

· **「이미 연결된 세션의 응답인 척」(ACK 위조) 공격** — 패킷 필터링은 헤더만 보고 통과시키지만, **상태검사는 「그런 연결 연 적 없는데?」로 막는다**

## 뒤바꿈 짝

- **ICMP 증폭 = Smurf**(여럿이 한 명을) / **접속 자리 고갈 = SYN flooding**(자리만 잡고 안 앉기)
  - **이 둘의 설명을 서로 바꿔 내는 것이 전형적 출제**
- **Teardrop = 오프셋**(tear=찢다) / **PoD = 크기**(65,535 초과) / **Land = 출발지=목적지** / **Boink·Bonk = 오프셋 어긋남**
- **콜리전 도메인 = 스위치가 나눔 / 브로드캐스트 도메인 = 라우터·VLAN(L3)** — 허브·리피터는 아무것도 못 나눔
- **HIDS는 암호화를 본다(부하 큼) / NIDS는 못 본다(광범위)**
- **지식 기반 = 시그니처 · 오탐↓ · 제로데이 X / 행위 기반 = 프로파일 · 제로데이 O · 오탐↑**
- **DRDoS = 출발지를 피해자로 위조해 정상 서버가 응답을 쏘게 함.** 좀비 PC 불필요, 공격자 IP 은닉
- **Secure=HTTPS만 / HttpOnly=JS 차단(XSS) / SameSite=크로스사이트 차단(CSRF)**
- **VPN 계층 — PPTP·L2TP = 2계층 / IPSec = 3계층 / SSL VPN = 4~7계층** ← 「SSL VPN이 3계층」이 함정
- **MDM(기기 관리) / NAC(망 접속 통제) / ESM(보안장비 관제) / DLP(유출 방지)** — 이름에 **Device**가 든 게 기기
- **UTM = 기능을 합침 / SIEM = 로그를 합침**(상관분석·포렌식·조기경보)

## 순수 트리비아

- **Switch jamming = 가짜 MAC으로 MAC 테이블 넘치기**(= MAC flooding) → 허브처럼 플러딩 → 스니핑
- **Null Routing = 조용히 버린다.** `no ip unreachables`로 ICMP 에러를 끈다
- **802.11 프레임은 주소가 4개**라 이더넷(802.3)과 구조가 다르다
- **SSID 숨김은 보안이 아니다.** 직접 입력하면 접속되고 Probe Request에서 노출된다
- **WEP도 암호화와 인증을 제공한다**(약할 뿐). WEP(RC4) → WPA(TKIP) → WPA2(AES-CCMP) → WPA3(SAE)
- **Personal = PSK / Enterprise = 802.1X + RADIUS** · **802.1x = 포트 기반 접근제어(틀) / EAP = 그 안의 인증 프로토콜**
- **Enhanced Open(OWE) = 비밀번호 없는 개방형 와이파이의 암호화**
- **KRACK 문항에서 「SSID 브로드캐스팅」은 공격이 아니라 정상 기능**
- **블루재킹(던진다) / 블루스나핑(snarf=훔치다, 데이터 탈취) / 블루버깅(기기 조종) / 블루프린팅(장비 식별)**
- **NAC의 지문 표지 — 「IP 관리 시스템에서 발전」 + 「MAC 주소 기반」**
- **IoT SoA 4계층 = 센싱 → 네트워크 → 서비스 → 인터페이스** (트랜스포트는 OSI 쪽)
- **SCADA(감시제어·데이터수집) / PLC(현장 제어 장치) / Modbus(통신 프로토콜) / Stuxnet(공격)**
- **압축·암호화·인코딩은 표현 계층(6)** / 데이터링크(2)는 오류·흐름·회선 제어
- **단편화·오프셋·TTL·프로토콜 번호는 IP 헤더 = 3계층**

# 3과목 애플리케이션 보안

## ★ 반복 오답

**쿠키 vs 세션** — 20회에서 **같은 회차에 두 번 출제, 두 번 다 오답**

- **쿠키 = 클라이언트(브라우저)에 저장 / 세션 = 서버에 저장**
- **「웹서버에 저장된 쿠키값」은 틀린 문장**
- 유효기간을 설정하지 않으면 **브라우저 종료 시 삭제**(세션 쿠키)
- **쿠키 변조 공격이 성립하는 이유가 바로 「사용자 손에 있어서」**

**`/etc/ftpusers` = 접속 금지 목록**

- 이름에 users가 붙어 허용 명단으로 착각. root 등을 넣어 **FTP 로그인을 막는** 파일

**DNSSEC은 암호화가 아니다**

- 응답에 **전자서명**을 붙여 위조를 막는 것(무결성·출처 인증). **내용은 평문**
- **질의 UDP 53 / 존 전송 TCP 53** · **AXFR이 열려 있으면 도메인 통째 유출**
- **재귀 = 네임서버가 대신 끝까지 / 반복 = 클라이언트가 차례로 직접**
- **리버스 도메인 = IP → 도메인**(PTR, in-addr.arpa)

## 뒤바꿈 짝

- **삽입(Injection) 계열 = 입력값 검증 / XSS = 출력값 인코딩**
  - XPath·XQuery 삽입 문제에서 **「출력값 검증」이 보이면 그게 오답**
- **XSS = 훔친다 / CSRF = 시킨다**
- **집성 = 더하기**(조각→큰 그림) / **추론 = 나누기**(아는 값→모르는 값)
- **증분 = 직전 백업 기준**(백업 편하고 복구 고생) / **차등 = 전체 백업 기준**(반대)
- **액티브 FTP = 서버가 연결을 건다 / 패시브 = 클라이언트가 건다**
- **정적 = IDA(실행 안 함) / 동적 = 샌드박스(실행)**
- **PGP = 신뢰의 웹(분산, peer끼리 서명) / PEM = 중앙 CA(집중, 미사용) / S/MIME = X.509 상용 표준**
- **XKMS = 키 / SAML = 인증정보·SSO / XACML = 접근통제 정책**
- **TDE = 투명(Transparent), 응용 수정 불필요 / API = 코드 수정 필요 / Plug-in = 수정 최소**
- **SQL 삽입 1순위 대책 = 파라미터화 쿼리**

## 순수 트리비아

- **메일 발신자 추적 = `Received` 헤더.** 서버마다 쌓이고 **맨 아래가 최초 발신**. `From`은 위조가 쉽다
- **FTP Bounce = PORT 명령으로 제3자 주소 지정.** 지문의 표지는 **「목적지를 검사하지 않는다」**. `nmap -b`
- **HTTP Smuggling = Content-Length와 Transfer-Encoding이 같이 보이면**
- **웹 로그에 POST 본문은 남지 않는다.** 메서드·URL은 남고 보낸 내용은 안 남는다
- **TLS 공격 짝 — 외워야 하는 표**

| 공격 | 대상 |
|---|---|
| **BEAST** | **CBC의 IV** (TLS 1.0) |
| **POODLE** | **CBC의 패딩** (SSL 3.0) |
| **FREAK** | **export RSA** 다운그레이드 |
| **Logjam** | **export DH** 다운그레이드 |
| **Heartbleed** | OpenSSL **Heartbeat** |
| CRIME · BREACH | **압축** |

- 고리: **export가 보이면 다운그레이드(RSA면 FREAK, DH면 Logjam) / CBC가 보이면 IV는 BEAST, 패딩은 POODLE**
- **SET 이중서명 = 구매정보와 지불정보를 분리하되 연결성 유지.** **고객의 개인키로 서명하므로 인증·부인방지가 따라온다**
- **SSL은 부인방지를 제공하지 않는다**
- **ebXML 구성요소에 EDI 문서는 없다**(ebXML이 EDI를 대체하려고 만든 것)
- **전자입찰 요구사항 = 비밀성·무결성·공평성·익명성·부인방지.** **「동시성」은 DB 용어**
- **워터마킹(소유권 표시) vs 핑거프린팅(구매자 추적)**
- **휘발성 수집 순서 = 메모리 → 네트워크 → 디스크**

| 하는 일 | 누가 | 쓰는 키 |
|---|---|---|
| 암호화 | 송신자가 | **수신자의 공개키** |
| 복호화 | 수신자가 | 자기 개인키 |
| 서명 | 송신자가 | 자기 개인키 |
| 검증 | 수신자가 | **송신자의 공개키** |

- 지문에 **「수신자의」·「송신자의」**처럼 **남**이 적혀 있으면 → **공개키**
- **「수신자의 개인키로 서명」 같은 문장은 읽는 즉시 X.** 남의 개인키를 쓰는 자리는 없다
- **기밀성 + 부인방지 동시 → A의 개인키(서명) → B의 공개키(암호화).** 서명 먼저
- **하이브리드(전자봉투) = 본문은 대칭키로, 그 대칭키만 수신자 공개키로**
- **전자서명은 기밀성을 제공하지 않는다**

**왜 그런가 — 반대일 수 없는 이유 (10-03 질문, 이게 빠져서 표가 안 붙었다)**

> **개인키로 암호화하면 공개키를 가진 전 세계가 열 수 있다. 그건 숨긴 게 아니다.**

- **자물쇠 비유** — **채우는 건 아무나 할 수 있어야 하고(공개키), 여는 건 주인만 할 수 있어야 한다(개인키).** 우편함과 같다. 반대면 "주인만 넣고 아무나 꺼내는 함"이 된다
- **교재가 서명을 「개인키로 암호화」라고 쓰는 바람에 혼동이 생긴다.** 그건 숨기기가 아니라 **증명**이다 — 열린다는 사실이 "그 사람의 개인키로 만들었다"를 보여준다

**시험장 판별 2단계**

1. **누구 것인가** — 「송신자의」·「수신자의」처럼 **남**을 가리키면 **공개키**. 남의 개인키는 손에 넣을 수 없다
2. **숨기려는가, 증명하려는가**

| 지문의 단어 | 쓰는 키 |
|---|---|
| 기밀성 · 비밀 · **세션키 분배** · 남이 못 보게 | **수신자의 공개키** |
| 부인방지 · 인증 · 내가 썼다는 증거 | **송신자의 개인키** |

**전자봉투 전체 흐름**

```
A                                            B
① 세션키(대칭키) 생성
② 본문을 세션키로 암호화        ─────→   ⑤ 세션키로 본문 복호화
③ 세션키를 B의 공개키로 암호화  ─────→   ④ 자기 개인키로 세션키 복호화
```

- **RSA를 세션키에만 쓰는 이유** — 공개키 연산이 느려서 본문 전체에는 못 쓴다. **짧은 세션키 하나만** 감싼다
- **기출(2019-09 80번)** — "비밀 세션키를 공유" → **숨기기** → **수신자 B의 공개키**. 「A의 개인키」를 고르면 **A의 공개키를 가진 전 세계가 세션키를 얻는다**

**두 줄로**
> **한 명만 열어야 하면 → 그 사람의 공개키로 잠근다**
> **전 세계가 확인해야 하면 → 내 개인키로 서명한다**

**인증서** — 2회 이상 오답

- **인증서에는 개인키가 없다. PKI 어디에도 개인키가 보관되는 곳은 없다**(저장소에도 없다). 개인키는 본인만(pfx·p12·HSM)
- 들어가는 것 — **주체의 공개키 + 발급자 식별명 + 발급자 서명**
- **발급자의 공개키는 인증서에 없다.** 발급자 자신의 인증서에 있다 → **그래서 인증서 체인이 생긴다**
- **자기 서명 인증서는 발급자와 주체가 같다**(= 루트 CA)
- **신뢰하려면 세 가지 — ① CA 서명 ② 유효기간 ③ 폐지 여부.** 둘만 쓰여 있으면 그 보기가 오답
- **X.509 v3에서 확장 영역 도입**(CRL 배포지점 등)

**폐지**

- **CRL = 책자**(주기적 배포, **시차 있음**) / **OCSP = 전화 조회**(실시간, good·revoked·unknown)
- **폐지는 소유자만 하는 게 아니다** — CA·RA·소속 조직도 한다. **개인키가 멀쩡해도 폐지된다**
- **만료된 인증서는 CRL에서 뺀다**(유효기간에서 이미 걸리므로)

**PKI 계층 — 아래로 갈수록 사람을 직접 만난다** ★ 반복

```
PAA   최상위 정책 승인              (사람 안 만남)
PCA   자기 도메인 정책 + 하위 CA 인증
CA    발급 · 폐지
RA    신원 확인 · 등록 대행          (사람 직접 만남)
```

- **「PAA가 신원을 확인한다」는 오답 / 「RA가 발급한다」도 오답**

**KDC는 다른 세계다** ★ 18회·20회 반복

> **⚠️ 커버로스 — 「요구사항」과 「제공 서비스」를 구분해서 묻는다**
> **설계 요구사항**(시스템이 갖출 것) = **보안성 · 신뢰성 · 투명성 · 확장성**
> **제공 서비스**(사용자에게 주는 것) = **인증 · SSO**. **가용성·기밀성은 제공 서비스가 아니다**
> · 「KDC가 안 죽게 만든다(신뢰성)」와 「사용자의 가용성을 보장한다」는 다른 얘기
> · 커버로스의 본업은 **인증 하나**. 이름이 **케르베로스(지옥문을 지키는 개) = 문지기**

- **KDC는 대칭키 세계.** 세션키를 **마스터키(대칭키)**로 감싸 전달한다
- **「세션키를 공개키로 암호화한다」는 지문은 항상 오답**
- 키 수는 **n(n−1)/2 → n**으로 **줄 뿐이지 0이나 상수가 아니다**(사용자 100명이면 KDC는 100개)
- **커버로스 = KDC의 구현체, 대칭키 기반**
  - 순서 — **AS 인증 → TGT → TGS가 서비스 티켓 → 서버 접속 → 허가**
  - **타임스탬프로 재전송 대응** → 시간 동기화 **5분**
  - **각 서버는 사용자 패스워드를 보관하지 않는다**(그러려고 KDC를 둔 것)
- **Needham-Schroeder가 아버지, 커버로스가 아들.** 아버지의 **재전송 약점**을 아들이 타임스탬프로 고쳤다
  - **「NS가 커버로스를 개선했다」는 오답**(순서가 반대)

## ★★ KDC · NS · 커버로스 · RSA · DH — 다섯이 섞일 때 (10-03 질문)

> **전부 「둘이 같은 키를 어떻게 갖나」에 대한 답이다. 답이 세 갈래로 갈린다.**

```
① 중앙이 만들어서 나눠준다      →  KDC   (대칭키)
                                   └ 그 절차가 Needham-Schroeder, Kerberos
② 한쪽이 만들어서 보낸다        →  RSA   (공개키)
③ 아무도 안 보낸다, 각자 만든다  →  DH    (공개키)
```

**층위가 다르다는 것부터** — **KDC는 「자리(기관)」, NS·커버로스는 「절차(프로토콜)」.** 은행과 입금 절차의 관계다.

**KDC = AS + TGS (10-03 질문) — 층위를 구분할 것**

```
          ┌──────── KDC ────────┐
          │   AS        TGS      │
          │ (1번 창구)  (2번 창구) │
          └──────────────────────┘
```

| | 커버로스 | 민원실 |
|---|---|---|
| **KDC** | 전체 | **건물** |
| **AS** | 사용자 인증 | **1번 창구 — 신분 확인** |
| **TGT** | AS가 발급 | **출입증** ← **물건** |
| **TGS** | 서비스 티켓 발급 | **2번 창구 — 출입증 보고 이용권 발급** |
| **서비스 티켓** | TGS가 발급 | **부서 이용권** ← **물건** |

- **AS·TGS는 「창구(서버)」, TGT·서비스 티켓은 「표(데이터)」.** **TGT를 구성요소로 넣은 보기는 틀린다**
- **왜 창구를 둘로 나눴나 — SSO 때문.** 창구가 하나면 서비스마다 신분 확인을 다시 해야 하고, 그러면 **패스워드가 계속 네트워크에 돈다**. TGT가 그걸 대신한다
- **KDC는 커버로스만의 것이 아니다.** NS도 KDC를 쓴다(창구 하나). **KDC=자리 / NS·커버로스=그 자리를 쓰는 방법**
- **구성요소를 물으면 — 클라이언트 · 서버(서비스) · KDC(AS+TGS)**
  · ※ 18회 기출의 커버로스 3요소 문항은 **오류 신고된 문제**. 깊이 파지 말 것

**NS vs 커버로스 — 차이는 하나**

| | **Needham-Schroeder**(1978) | **Kerberos**(MIT) |
|---|---|---|
| 관계 | **아버지** | **아들** |
| 재전송 | **취약** | **타임스탬프로 방어** → **시간 동기화 필요(5분)** |
| 구조 | KDC 하나 | **AS + TGS**로 분리 → **SSO** |

· **「NS가 커버로스를 개선했다」는 순서가 거꾸로라 항상 오답**

**왜 DH가 중간자에 취약한가 (10-03 질문) — 상대를 확인하는 단계가 없어서**

```
A ────주황───→  [중간자 M]  ────M의 주황───→  B
A ←──M의 초록──  [중간자 M]  ←───초록────────  B

→ A와 M이 갈색1 공유 / M과 B가 갈색2 공유. 양쪽 다 상대와 공유한 줄 안다
→ M은 갈색1로 풀어 읽고 갈색2로 다시 잠가 넘긴다
```

· **A가 받은 공개값이 B에게서 온 건지 알 방법이 없다.** 페인트에는 **서명이 없다**
· **해결 — 공개값에 서명을 붙인다.** 서버가 자기 공개값을 개인키로 서명하고 **인증서로 보증**한다 = **TLS의 DHE·ECDHE**(E=Ephemeral)
· **한 줄 — DH는 「키를 만드는 법」은 알지만 「상대가 누군지」는 모른다**

**⚠️ 재전송에 취약한 것은 커버로스가 아니라 NS다 (10-03 질문)**

```
1978  Needham-Schroeder  →  재전송 취약 (옛 메시지를 그대로 재사용해도 구분 못 함)
                    ↓ 그 약점을 고쳐서
1980s Kerberos           →  타임스탬프로 막음. 대신 시간 동기화(5분)가 필요해짐
```

· 그 대가 — 5분 안에서는 여전히 가능해서 **replay cache**를 따로 둔다
· **커버로스의 진짜 약점 — KDC 단일 실패점 · 시간 동기화 의존 · krbtgt 해시 탈취(Golden Ticket)**
· **가르는 법 — 「재전송 취약」+키 분배 → NS / 「타임스탬프·시간 동기화·TGS」 → Kerberos**

**DH를 페인트로**

```
공개된 색(노랑) — 모두가 본다
A: 노랑+빨강(비밀)=주황  ──→          ←──  B: 노랑+파랑(비밀)=초록
A: 초록+빨강 = 갈색                        B: 주황+파랑 = 갈색
                    ↑ 둘 다 같은 색인데 갈색은 한 번도 전송되지 않았다
```

· 중간에서는 **주황·초록만** 보이고, **섞인 페인트에서 원래 색을 뺄 수 없다** = **이산대수 문제**

**한 장 표**

| | **KDC** | **NS** | **커버로스** | **RSA** | **DH** |
|---|---|---|---|---|---|
| 무엇 | 기관(역할) | 프로토콜 | 프로토콜 | 알고리즘 | 알고리즘 |
| 키 세계 | **대칭키** | **대칭키** | **대칭키** | **공개키** | **공개키** |
| 중앙 | — | **있다** | **있다(AS+TGS)** | **없다** | **없다** |
| 키를 | 만들어 **나눠줌** | 나눠받음 | 나눠받음 | 만들어 **보냄** | **각자 만듦** |
| 기반 | — | — | — | **소인수분해** | **이산대수** |
| 용도 | — | — | SSO | **암호화 + 서명** | **키 교환만** |
| 약점 | 단일 실패점 | **재전송** | 시간 동기화 | **순방향 기밀성 없음** | **중간자** |

**지문 표지**

| 보이면 | 답 |
|---|---|
| 「신뢰할 수 있는 제3자」·「티켓」·「마스터키」 | **KDC 계열** |
| 「티켓 발급 서버」·「타임스탬프」·「시간 동기화」 | **커버로스** |
| 「재전송 공격에 취약」 + 키 분배 | **Needham-Schroeder** |
| 「소인수분해」·「서명에도 사용」 | **RSA** |
| 「이산대수」·「계산하여 만들어낸다」·「중간자 공격」 | **DH** |

**가장 빠른 두 갈래** — ① **중앙 기관이 나오나?**(나오면 KDC 계열) ② **키를 보내나, 각자 만드나?**(보내면 RSA, 각자면 DH)

> **KDC** 열쇠 관리실(자리) / **NS** 옛날 절차, 재전송에 뚫림 / **커버로스** 고친 절차, 시계를 맞춰야 함
> **RSA** 내가 만들어 상대 금고에 넣어 보냄, 서명도 됨 / **DH** 아무도 안 보내는데 같은 값이 생김, 대신 상대가 누군지 모름

> ### ★★★ DH — 10-03에 네 번 틀림. 고리를 이걸로 바꾼다
> **서명은 혼자 한다. DH는 둘이 해야 돌아간다.**
> 전자서명은 내가 **혼자** 만들어 붙이지만, DH는 **상대가 같이 계산해주지 않으면 아무것도 안 나온다.**
> 그래서 **DH로 서명하는 것은 구조적으로 불가능**하다.
> 그리고 **DH는 「키를 만드는 기계」지 「데이터를 숨기는 기계」가 아니다** — 만든 키로 암호화하는 건 AES가 한다.

**DH 계산 문제 푸는 절차 (10-03 기출 65번)**

주어진 것 — **g, p, 각자의 개인키 a·b**

```
1단계  각자 공개값 = g^(개인키) mod p
2단계  공유키 = (받은 공개값)^(내 개인키) mod p
```

예) g=3, p=7, a=2, b=3
· A의 공개값 = 3² mod 7 = **2** / B의 공개값 = 3³ mod 7 = **6**
· A: 6² mod 7 = 36 mod 7 = **1** / B: 2³ mod 7 = 8 mod 7 = **1** → 공유키 **1**

- **왜 같은 값인가** — A는 (gᵇ)ᵃ, B는 (gᵃ)ᵇ. **둘 다 g^(ab)**. 페인트를 어느 순서로 섞어도 같은 색
- **지름길 — 바로 g^(a×b) mod p 를 계산해도 된다** (3⁶ mod 7 = 1)
- **수를 키우지 말 것** — 729를 구하지 말고 **매 단계 mod**. 3²≡2 → 3⁶=(3²)³≡2³=8≡1

**은닉서명 vs 이중서명 — 둘 다 「가린다」라서 헷갈린다**

| | 누구에게 가리나 | 어디서 |
|---|---|---|
| **은닉서명** | **서명하는 사람**에게 (내용·신원을 모른 채 서명) | 전자화폐 — 추적 방지 |
| **이중서명** | **받는 사람들**에게 각각 다른 쪽을 | SET — 판매자는 결제정보를, 금융기관은 주문내역을 모름 |

· **한 줄 — 은닉서명은 위를 가리고, 이중서명은 양옆을 가린다**
· 이중서명은 그러면서도 **둘이 한 거래라는 연결은 유지**한다

**세션키 공유 기법 구분 (기출 79번)**
· **「랜덤으로 생성한 세션키를 수신자의 공개키로 암호화하여 전달」 = RSA 키 분배**(만들어서 보냄)
· **DH는 아무도 세션키를 보내지 않는다**(각자 계산) · **Challenge-Response는 인증**이지 키 분배가 아니다

> ### ★ 기반 문제 — R로 시작하는 둘이 소인수분해
> **RSA · Rabin = 소인수분해** / **DH · DSA · ElGamal · ECC = 이산대수**
> 그래서 **ECDH·ECDSA는 있어도 「ECRSA」는 없다** (ECC는 이산대수에만 붙는다)

**DH 한 번 더 (10-03에 네 번 틀림)** — 기반 **이산대수** · **키 교환 전용**(암호화 ✗ 서명 ✗) · 약점 **중간자** · 그래서 **서명을 붙여 씀(DHE·ECDHE)** · **ECC 적용 가능(ECDH)** · **순방향 기밀성 제공**

**PRNG vs TRNG** — **P=Pseudo(가짜)=계산으로 흉내=시드가 같으면 결과도 같음=소프트웨어** / **T=True(진짜)=물리 현상(열잡음·방사성붕괴)=하드웨어**. 암호용은 **CSPRNG**를 쓴다

**IV 재사용 금지** — 같은 키 + 같은 IV면 **같은 평문이 늘 같은 암호문**이 되어 **ECB의 약점이 돌아온다**. **WEP가 깨진 핵심 원인**(IV가 24비트로 짧아 금방 재사용)

**커버로스 설계 요구사항 4가지 — 보안성 · 신뢰성 · 투명성 · 확장성**
· **보안성**(도청자가 가장 못 하게) · **신뢰성**(분산 서버로 가용성) · **투명성**(패스워드 입력 외엔 인증을 못 느끼게 = SSO 경험) · **확장성**

· 원래 **OTP의 조건**인데 OTP는 키를 실제로 그만큼 나눠줘야 해서 못 쓴다 → **스트림 암호가 짧은 키로 긴 키스트림을 만들어 흉내 낸 것**
· **「대칭키 암호」는 상위 범주라 답이 아니다.** 더 구체적인 답이 있으면 그걸 고른다

**개발 목적**

| | 개발 목적 |
|---|---|
| 스트림 암호 | **OTP 실용화** |
| 블록 암호 | **기밀성** (위·변조 방지가 아님) |
| 공개키 암호 | **키 배송·키 관리 문제** |
| **해시 함수** | **무결성 검증** ← 「전자서명을 위해」는 **응용이지 목적이 아니다** |

**블록암호 3대 공격 = 차분 · 선형 · 전수**
· **차분**(입력 차이 → 출력 차이) · **선형**(선형 근사식) · **전수**(모든 키)
· **「고정점 연쇄공격」은 해시 공격**(Merkle-Damgård 연쇄 구조). **「연쇄」는 해시 쪽 어휘**

## ★ 키를 쓰느냐 — 세 줄

- **해시 = 키 없음** (그래서 공격자도 다시 계산할 수 있다)
- **MAC = 대칭키** (그래서 **부인방지 불가** — 수신자도 만들 수 있어 제3자에게 증명 못 함)
- **전자서명 = 개인키** (그래서 **부인방지 가능**)
- **HMAC이 키를 두 번 쓰는 이유 = 길이 확장 공격 방어**

> ### ★ 10-03 하루에만 네 번 나온 줄
> **대칭키 · MAC — 둘이 같은 키 → 서로는 믿지만 제3자에게 증명 못 함 → 부인방지 ✗**
> **전자서명 — 나만 가진 개인키 → 제3자도 확인 가능 → 부인방지 ✓**
> **해시 — 키 없음 → 누구나 계산 → 무결성만**
>
> 대칭키가 주는 것은 **기밀성 + 무결성 + (둘 사이의) 인증**까지다. **「동일한 키로 부인방지를 제공한다」는 항상 오답.**

## 해시 함수의 세 가지 저항성 — 「무엇이 주어졌나」로만 갈린다 (10-03 질문)

| | **주어진 것** | 찾을 것 | 계산량 |
|---|---|---|---|
| **역상 저항성** (= **일방향성**) | **해시값** | 그 값이 나오는 **입력** | **2ⁿ** |
| **두 번째 역상 저항성** (= **약한** 충돌 저항성) | **입력 x 하나** | x와 같은 해시값의 **다른 입력** | **2ⁿ** |
| **충돌 저항성** (= **강한** 충돌 저항성) | **없음** | h(x)=h(x')인 **아무 두 개** | **2^(n/2)** |

**주어지는 게 줄어들수록 공격자가 자유로워져 쉬워진다.**

- 지문에 **「주어진 x에 대해」**가 있으면 → **두 번째 역상**
- 지문이 **「2개의 서로 다른 입력을 찾는다」**면 → **충돌** (둘 다 내가 고름)

**⚠️ 한국어 별칭이 함정 — 「약한」이 붙은 쪽이 오히려 깨기 어렵다(2ⁿ).**
「약한」은 난이도가 아니라 **요구 조건이 느슨**하다는 뜻이다(공격자에게 x를 쥐여주고 시작).

**왜 충돌만 2^(n/2)인가 — 생일 역설**

| | 생일로 치면 | 필요 인원 |
|---|---|---|
| 역상 · 두 번째 역상 | **나와** 생일 같은 사람 | **253명** |
| **충돌** | 생일 같은 **두 사람** | **23명** |

· **MD5·SHA-1이 폐기된 것도 충돌이 먼저 깨졌기 때문.** 역상은 아직 안 깨졌다

**나머지 특성** — **압축성**(출력 고정 길이) · **효율성**(계산이 빨라야) · **눈사태 효과**(1비트 바꾸면 출력 절반이 바뀜) · **키를 쓰지 않음**

## 블록 운용 모드 — 세 가지 질문으로만 나온다

| 질문 | 답 |
|---|---|
| **메시지 인증(MAC)에 쓰이는 것** | **CBC · CTR** ← CCM=CTR+CBC-MAC, GCM=CTR+GHASH |
| **오류 전파가 없는 것** | **OFB · CTR** (CBC·CFB는 다음 블록까지 번진다) |
| **완전 병렬 처리되는 것** | **ECB · CTR** (CBC는 암호화가 순차, 복호화만 병렬) |

- **CTR이 세 줄 모두에 들어간다.** 문제에 **「카운터」**가 나오면 CTR
- **ECB = Electronic Code Book = 대응표** → 같은 입력이면 같은 출력
- **OFB는 스트림 암호처럼 동작한다**

**네 번째 질문 — 지문으로 모드를 찾아내기 (10-03 질문)**

**① XOR이 암호화 앞이냐 뒤냐**

```
CBC :  P ⊕ C(앞블록)  →  [E]  →  C      ← XOR 먼저, 그다음 암호화
CFB :  C(앞블록) → [E]  ⊕ P   →  C      ← 암호화 먼저, 그다음 XOR
```

- 지문에 **「암호화한 값과 평문을 XOR」** → 암호화가 먼저 → **CBC가 아니다**
- 지문에 **「평문과 초기치를 XOR한 후 암호화」** → **CBC**

**② 암호화 먼저인 셋(CFB·OFB·CTR)은 「다음 암호화에 무엇을 넣느냐」로만 갈린다 — 이름 앞 글자가 답**

```
CFB :  [E] ← 직전 암호문 C        ← Cipher  FeedBack
OFB :  [E] ← 직전 암호화 출력 O    ← Output  FeedBack
CTR :  [E] ← 카운터 1, 2, 3…      ← Counter
```

**③ 오류 전파 범위**

| 모드 | 암호문 오류의 영향 |
|---|---|
| ECB | **그 블록만** |
| **CBC · CFB** | **그 블록 + 다음 한 블록** (번지지만 멈춘다) |
| **OFB · CTR** | **그 블록만** (키스트림이 암호문과 무관) |

- **CFB·CBC의 지문 표지 — 「암호화에서는 계속 영향, 복호화에서는 계속은 아님」이라는 비대칭**
  · 암호화는 암호문이 앞으로 흘러가 **뒤 전부**가 바뀌고, 복호화는 **두 블록에서 멈춘다**

**★ 그림으로 나오면 — 평문의 위치만 본다 (10-03 기출 79번, 하루에 세 번 다루고 또 틀림)**

```
CBC      평문 ──⊕── [암호화] ── 암호문      평문이 상자 안으로 들어간다
               │
              IV

CFB      IV ── [암호화] ──⊕── 암호문        평문이 상자에 안 들어간다
                         │
                        평문
```

> ### 평문이 상자 안으로 들어가면 → ECB · CBC
> ### 평문이 상자 밖에서 ⊕만 하면 → CFB · OFB · CTR

· 그림이든 지문이든 **질문은 하나**다. 그다음은 **다음 상자에 뭐가 들어가나**(암호문=CFB · 출력=OFB · 카운터=CTR)

**⑤ 지문에서 모드를 찾는 소거 순서 (10-03 기출 75번)**

1. **평문이 블록암호의 입력으로 들어가나?** → 들어가면 **ECB**(평문 그대로) 또는 **CBC**(평문⊕앞암호문)
2. 안 들어가면 셋 중 하나 → **오류가 후속 블록에 번지나?**
3. **번진다 → CFB**(암호문을 되먹여서) / **안 번진다 → OFB·CTR**
4. **되먹임이면 OFB, 카운터면 CTR**
   · **OFB는 직전 출력을 되먹여 순차 / CTR은 1·2·3으로 세므로 병렬·임의 접근 가능**

> **⚠️ 「블록 암호를 기반으로 한 스트림 암호」라는 말만으로는 못 고른다.** CFB·OFB·CTR이 **전부** 해당한다.
> 갈라주는 건 **오류 전파 여부**다.

**④ 복호화에 쓰는 함수**
- **CFB·OFB·CTR은 복호화할 때도 암호화 함수 E를 쓴다.** 복호 알고리즘 D가 아예 필요 없다(키스트림을 다시 XOR하면 원문)
- **ECB·CBC는 D가 필요하다**

## 뒤바꿈 짝

- **FAR = 타인을 통과시킴(보안 사고) / FRR = 본인을 거부함(불편).** 동시에 못 낮춘다, **CER은 낮을수록 우수**
- **BLP = 기밀성**(No Read Up + No Write Down) / **Biba = 무결성**(정반대)
  - 고리: BLP는 물이 아래로 새는 걸 막고, Biba는 오물이 위로 올라오는 걸 막는다
- **ACL = 객체 기준(문에 붙인 명단), 취소 쉬움 / Capability = 주체 기준(손에 든 열쇠꾸러미), 취소 어려움** ★ 18회
  - **둘 다 DAC의 구현 메커니즘이다**(접근제어행렬·ACL·Capability = 하나씩 지정). **MAC의 구현은 보안 레이블**(등급 비교) — 그래서 MAC은 **규칙 수가 적다**
- **DH의 지문 표지 — 「계산하여 만들어낸다」·「이산대수」·「중간자 공격에 취약」.** KDC·NS는 **나눠주고**, DH는 **각자 계산해 같은 값에 도달**
- **PRNG = 소프트웨어**(P=Pseudo=가짜, 시드 기반) / **HRNG(TRNG) = 물리 현상**(열잡음·방사성 붕괴). SRNG·RRNG는 없는 용어
- **IV = 첫 블록에 「앞 암호문」이 없어서 그 자리를 채우는 비트열.** 패딩은 **뒤**를 메우는 것
- **만료 ≠ 폐지.** 폐지는 **아직 살아 있는 것을 죽이는 일**. 만료된 건 날짜로 걸러지니 폐지 사유가 아니고 CRL에도 안 남긴다
- **선택 평문 = 평문을 넣어 암호문을 얻음 / 선택 암호문 = 암호문을 넣어 평문을 얻음**
  - 강도 순 **암호문 단독 → 기지 평문 → 선택 평문 → 선택 암호문**(고를 수 있을수록 강하다)
- **치환 = 글자를 바꾼다(빈도가 변함) / 전치 = 순서만 섞는다(빈도가 보존됨)**
  - **치환이든 전치든 빈도는 숨겨지지 않는다.** 치환은 빈도가 **글자를 따라 옮겨가고**(그래서 빈도분석으로 깨짐), 전치는 빈도가 **그대로 있다**(그래서 전치임을 알 수 있음)
- **비제네르 = 다중 치환**(10-03 질문) — 키워드 길이만큼 **표를 돌려 쓴다**

```
평문   A  T  T  A  C  K
키     K  E  Y  K  E  Y     ← 키워드 반복
암호문 K  X  R  K  G  I     ← 같은 T가 X와 R로 다르게 나온다
```

  - **같은 글자가 자리마다 다른 글자로 흩어져** 빈도가 평평해진다 → 빈도 분석 저항
  - **깨는 법 — 키 길이를 먼저 알아낸다(카시스키 검사).** 키가 3이면 1·4·7번째는 같은 표를 쓴 것이므로 그것만 모으면 **단일 치환으로 환원**된다
  - **표 개수로 한 줄** — **카이사르·단일치환 = 1개 고정 / 비제네르 = 키 길이만큼 / OTP = 평문 길이만큼, 1회용**
  - **비제네르는 「키를 반복해서 쓰는 OTP」다. 반복하는 순간 약해진다**
- **생일 공격 = 2^(n/2)**(충돌은 반으로 접는다) / **일방향성 = 2^n**. SHA-256의 충돌 강도는 실질 128비트
- **DSS = 표준 이름 / DSA = 그 안의 알고리즘** ★ 18회
- **용도 — 암호화+서명 = RSA·ElGamal / 키 교환 전용 = DH / 서명 전용 = DSA·KCDSA·ECDSA**
- **기반 문제 — RSA·Rabin = 소인수분해 / DSA·DH·ElGamal·ECC = 이산대수** ★
- **2요소는 다른 통에서.** 아는 것·가진 것·자신인 것. **지문+홍채는 둘 다 생체라 1요소**
- **메모리 카드 = 저장만 / 스마트카드 = CPU 내장, 개인키가 밖으로 안 나옴**
- **변조 = 있던 걸 고침 / 위조 = 없던 걸 만듦**
- **트래픽 분석 = 내용을 못 읽는 상태에서 송수신자·빈도·길이로 유추**(내용 노출은 도청이다)
- **substitution = 치환**(다른 요소로 바꿔치기) / **transposition·permutation = 전치**(자리만 바꾸기) — 치환/전치의 영어 이름
- **Challenge-Response는 키를 생성하지 않는다** — 서버가 **난수**를 던지고, 기기가 **이미 가진 키**로 **응답**을 만든다. 「키를 생성한다」가 보이면 DH나 세션키 얘기지 시도-응답이 아니다
- **인증서는 CA가 발행한다** — 「사용자가 직접 발행」은 오답. 인증서는 **남이 보증해주는 문서**다
- **만료된 인증서도 일정 기간 보관한다** — 과거 서명의 유효성을 나중에 증명해야 하므로(부인방지). **CRL에서 빼는 것과 아카이브 보관은 별개**

## ★★ 「요구사항이 아닌 것」 유형 — 반대말을 찾는다 (10-03까지 세 번 걸림)

> ### 보기 넷을 훑어 **다른 보기와 뜻이 반대인 것**을 찾는다. 목록을 다 외울 필요가 없다.

| 문제 | 답으로 끼운 것 | 그 반대말 |
|---|---|---|
| 해시 요구사항 | **역방향성** | **일방향성** |
| 생체 요구사항 | **시간의존성 · 유연성** | **지속성 · 영구성** |

- **해시 요구사항 = 계산 용이성 · 일방향성 · 약한 충돌회피성 · 강한 충돌회피성**
- **생체 요구사항 = 보편성 · 유일성(구별성) · 영구성(지속성) · 획득성** (+ 성능 · 수용성 · 기만 불가능성)

## 키 배송 문제의 세 갈래 — 「해당하지 않는 것」으로 출제된다

**① KDC(중앙이 나눠줌) · ② DH(각자 만듦) · ③ 공개키 암호(감싸 보냄)**
· **전자서명은 키를 나르지 않는다** — 인증·부인방지용이다. 보기에 섞여 나오면 그게 답

## Feistel vs SPN

| 구조 | 알고리즘 |
|---|---|
| **Feistel** | DES · 3DES · **SEED** · RC5 · Blowfish · Twofish · Camellia |
| **SPN** | **AES(Rijndael) · ARIA** |

· **SPN은 AES와 ARIA 둘뿐**이라고 외우는 게 빠르다
· **국산이 갈린다 — SEED=Feistel / ARIA=SPN.** ARIA가 AES를 참고해 만들어져서 **AES와 한 묶음**

## CRL 필드 · 이중서명 (10-03)

- **CRL의 Reason Code = 「폐지」 사유**(키 손상·CA 손상·소속 변경·대체·운영 중지·보류). **「갱신」 사유가 아니다**
  · CRL은 Certificate **Revocation** List, 문서 전체가 폐지 얘기다
- 그 밖의 필드 — **Hold Instruction Code**(일시 유보) · **Certificate Issuer**(발행자) · **Invalidity Date**(유효하지 않게 된 시점)
- **이중서명이 보이면 무조건 SET.** SSL이 아니다
  · **SSL은 「관」**(통로 암호화, 안에 뭐가 흐르는지 모름) / **SET은 「절차」**(주문정보는 판매자에게, 지불정보는 금융기관에게)
  · 생성 — 두 다이제스트를 이어 붙여 다시 해시한 뒤 **구매자의 개인키로 서명**

## 알고리즘 분류 — 「~가 아닌 것은」 유형의 원천 (10-03, 한 회차에서 3문항)

| 분류 | 알고리즘 |
|---|---|
| **대칭키 — 블록** | DES · 3DES · **AES(Rijndael)** · **SEED** · **ARIA** · **HIGHT** · **LEA** · IDEA · Blowfish · Twofish · Camellia · SKIPJACK · **RC5 · RC6** |
| **대칭키 — 스트림** | **RC4** · **A5/1 · A5/2** · SEAL · ChaCha20 · LFSR 기반 |
| **공개키 — 소인수분해** | **RSA** · **Rabin** |
| **공개키 — 이산대수** | **DH** · **ElGamal** · **DSA** · **KCDSA** · **ECC 계열**(ECDH · ECDSA · EC-KCDSA) |
| **해시** | MD5 · SHA-1/2/3 · HAS-160 · RIPEMD |
| **전자서명** | RSA · **DSA · KCDSA · ECDSA · EC-KCDSA** · ElGamal · Schnorr |

**함정 셋**

- **RC4만 스트림, RC5·RC6은 블록.** 같은 Rivest Cipher 가족인데 4만 다르다
- **이름에 DSA가 들어가면 전자서명**(DSA·KCDSA·ECDSA·EC-KCDSA). **A5에는 DSA가 없다**
- **국산 = SEED · ARIA · HIGHT · LEA · HAS-160 · KCDSA.** HIGHT·LEA는 **경량**(IoT·RFID)

**스트림 암호가 쓰이는 자리 — 「무선 · 음성 · 실시간」**
· **RC4 = WEP**(Wired Equivalent Privacy) · 초기 SSL/TLS / **A5/1·A5/2 = GSM(2G) 음성**
· 이유: 끝없이 흘러오고 **전체 길이를 미리 모르는** 데이터는 블록만큼 모일 때까지 기다릴 수 없다

**ECC는 「이산대수 기반」에만 얹을 수 있다**

| 원본 | 기반 | ECC 버전 |
|---|---|---|
| DH · DSA · KCDSA · **ElGamal** | **이산대수** | **있다** (ECDH·ECDSA·EC-KCDSA·EC-ElGamal) |
| **RSA · Rabin** | **소인수분해** | **없다** |

· **고리 — ECDH·ECDSA는 있는데 「ECRSA」는 없다.** 그게 답이다

> **「~가 아닌 것」 요령 — 모르는 보기가 있으면 아는 셋의 공통점을 찾는다. 그 공통점이 없는 게 답이다.**

## 숫자·제원

- **DES** 블록 **64** / 키 **56** / **Feistel 16라운드** · **3DES는 EDE**(EEE 아님)
- **AES**(Rijndael) 블록 **128** / 키 **128·192·256** / **SPN 10·12·14라운드**
- **SEED** 블록 128 · 키 **128·256**(192 없음) / **ARIA** 블록 128 · 키 **128·192·256** · KS X 1213
- **IDEA** 블록 64 · 키 128 (PGP) · **HIGHT·TDEA 블록 64**
- 해시 출력 **MD5 128 / SHA-1 160 / HAS-160 160 / SHA-256 256** (MD5·SHA-1 폐기)
- **RSA 권장 2048비트 이상**
- **LFSR 주기는 2ⁿ−1의 약수** (8차면 255=3×5×17의 약수)
- **Rabin은 복호화 시 평문 후보가 4개**(제곱 기반)

## 그 밖에 틀렸던 것

- **스트림 암호는 긴 주기 · 높은 선형 복잡도.** OTP를 실용화하려고 만든 것
- **순방향 기밀성 = 지금 키가 털려도 과거 트래픽은 안전.** 막는 게 아니라 **털려도 괜찮은** 것
  - 세션마다 임시 키(**DHE·ECDHE**)를 만들고 버린다. **RSA 키 교환은 제공하지 않는다**
- **해시를 쓰는 이유는 「빨라서」지 「안전해서」가 아니다**
- **은닉서명 = 서명을 요청한 사람의 익명성**(전자화폐 추적 방지)
- **전자투표 비강제성(무영수증성) = 남에게 증명할 수 없어야.** 검증 가능성과 정면 충돌
- **TCSEC = 기밀성만**(오렌지북·미 국방부) / **ITSEC = 무결성·가용성까지** / **TCSEC D→C1→C2→B1→B2→B3→A1, B부터 MAC** / **CC는 EAL 1~7**
- **접근 통제 4단계 = 식별 → 인증 → 인가 → 책임추적성** · **3원칙 = 최소 권한 · 직무 분리 · 알 필요성**
- **참조 모니터 3요건 = 항상 호출 · 변조 불가 · 검증 가능**
- **TCB는 작을수록 검증이 쉬워 안전**

## 4과목 목록·분류 (10-03 기출에서 걸린 것)

- **재전송 방지 3종 = 순서번호 · 타임스탬프 · 비표(Nonce)**
  · **「비표」는 Nonce의 번역어** — **N**umber used **once**, 한 번만 쓰는 난수. **CBC는 운용 모드라 무관**
- **RA vs CRL — 「무엇을 확인하나」**
  · **RA = 발급 전, 사람의 신원** / **CRL = 발급 후, 인증서가 살아 있는지**
  · 시간 순서 **RA(신원 확인) → CA(발급) → CRL(폐지 확인)**. 「유효성 확인」을 물으면 뒤쪽
- **생체인증 요구사항 = 보편성 · 유일성 · 지속성 · 획득성** (+ 성능 · 수용성 · 기만 불가능성)
  · **「시간의존성」은 지속성과 정반대라 오답.** 보기에 둘이 같이 나오면 모순으로 걸러진다
- **통제 시점에서 FDS·IDS는 「탐지」** — 미리 막으면 정상 거래·정상 트래픽까지 막히므로, **일단 받고 이상을 잡아내는** 구조일 수밖에 없다
- **정보보호 3요소는 동사로 가른다** — **「못 보게」= 기밀성 / 「못 바꾸게」= 무결성 / 「쓸 수 있게·적시에·유지」= 가용성**
  · 「인가된 사용자가」 같은 수식은 **전제**지 목표가 아니다

# 5과목 정보보안 관리 및 법규

## ★★ 5과목 순서 문제는 하나의 원리로 묶인다 — 「큰 방향이 먼저, 구체적 실행이 나중」

| | 큰 방향 | 구체적 실행 |
|---|---|---|
| **BCP 5단계** | **복구전략 개발** | **복구계획 수립** |
| **위험관리 5단계** | **정보보호대책 수립** | **정보보호계획 수립** |

**BCP 5단계**

```
범위 설정·기획 → 사업영향평가(BIA) → 복구전략 개발 → 복구계획 수립 → 테스트·유지보수
```

**위험관리 5단계**

```
자산식별 → 위험 분석·평가 → 정보보호대책 수립 → 정보보호계획 수립 → 주기적 재검토
```

- **무엇이 있나 → 얼마나 위험한가 → 무엇으로 막을까 → 어떻게 실행할까 → 다시 본다**
- **핫사이트를 쓸지 정하지도 않고 복구 절차를 짤 수는 없다** (BCP)
- **무엇으로 막을지 정하지도 않고 실행 계획을 짤 수는 없다** (위험관리)

**★★★★★ 개념 고리가 다섯 번 실패했다. 글자로 외운다.**

> ### 범 · 영 · 전 · 계 · 테
> **범**위 설정 → 사업**영**향평가 → 복구**전**략 → 복구**계**획 → **테**스트

> ### 자 · 분 · 대 · 계 · 재
> **자**산식별 → **분**석·평가 → **대**책 수립 → **계**획 수립 → **재**검토

- **둘 다 끝에서 두 번째가 「계」다. 계획은 항상 마지막 직전.**
- **전략은 「돈 쓰는 결정」, 계획은 「문서 쓰는 일」** — 핫사이트를 살지 먼저 정하고 그다음 절차서를 쓴다

**위험관리 3단계 버전** — 무엇이 위험한가(분석) → 얼마나 위험한가(평가) → 어떻게 할까(처리)

## 5과목 — 법률 용어는 법이 쓰는 말로 묻는다

| 지문의 설명 | 법률 용어 | 틀린 말 |

| 해킹·바이러스·논리폭탄·메일폭탄·서비스 거부·고출력 전자기파로 발생한 사태 | **침해사고** | 보안사고 · 사이버공격 |
| 업무 목적으로 개인정보파일을 운용하는 공공기관·법인·단체·개인 | **개인정보처리자** | 개인정보관리자 |

**개인정보 관련 세 사람**

| | 누구 |
|---|---|
| **개인정보처리자** | 업무 목적으로 개인정보파일을 **운용**하는 공공기관·법인·단체·개인 |

| **수**집제한 | 적법·공정하게, 최소한으로 |

## 5과목 — 평가·인증 제도 4종은 ISO 숫자로 가른다

| 제도 | 대상 | 기준 |
|---|---|---|
| **정보보호제품 평가·인증 (CC)** | **제품** | **ISO 15408** (+ **18045** 평가방법론) |

## 5과목 — 주요정보통신기반시설 지정 고려사항

| 고려한다 |
|---|
| 업무의 **국가사회적 중요성** |
| 그 업무의 **정보통신기반시설 의존도** |
| **다른 기반시설과의 상호연계성** |
| 침해 시 **국가안전보장·경제사회에 미치는 피해 규모와 범위** |
| **침해사고 발생가능성 또는 복구의 용이성** |

- **「개인정보의 규모」는 고려사항이 아니다**
- **기반시설은 「멈추면 나라가 멈추는가」로 지정한다**
- **법마다 관심사가 다르다 — 기반보호법 = 가용성**(멈추면 안 됨) / **개인정보보호법 = 기밀성**(새면 안 됨)
- **개인정보 얘기가 기반보호법 문제에 나오면 그게 답**

## 5과목 — 「과도한 서술」도 오답이다

- **너무 넓은 것** — CCTV 설치 사유의 「소관 업무 수행을 위해 불가피」
- **너무 엄격한 것** — 파기에서 「**미래에 개발될 기술까지** 고려하여 복구 가능성 원천 차단」
- **법은 가운데에 있다.** 실현 가능한 것만 요구한다

## 5과목 — 개인정보 파기

### ② 정량 vs 정성 위험분석 — 4회 출제, 3회 오답

| | **정량적** | **정성적** |
|---|---|---|
| **기준** | **금액** — 도입·복구·교체 비용 | **등급·서술** — 중요도, 영향도 |
| **기법** | **수학공식 · 확률분포 추정 · 과거자료 분석** | **델파이 · 시나리오 · 순위결정** |
| **계산** | **SLE = AV × EF / ALE = SLE × ARO** | **계산을 안 한다** |
| **객관성** | **높음** | 낮음(주관적) |
| **시간·비용** | **많이 든다** | **적게 든다** |
| **성능 평가** | **용이** | 어려움 |
| **비용·이익 평가** | **필수** | **안 한다** |

- **「정성적은 계산 노력이 적다」는 참**(등급만 매기므로). **「정성적은 비용·이익 평가가 필수」는 거짓**(금액을 안 다룬다)

**위험분석 4접근법**

| | 뜻 | 적합 |
|---|---|---|
| **기준선** | 체크리스트 일괄 | 작은 조직, 빠르고 쌈 |
| **비정형(전문가 판단)** | 전문가의 감 | **작은 조직**. 주관적 |
| **상세** | 절차대로 정밀하게 | 큰 조직. 정확하지만 비쌈 |
| **복합** | **중요 시스템만 상세 + 나머지는 기준선** | **실무 주류** |

- **복합 = 기준선 + 상세 둘뿐.** 전문가 판단을 끼워 넣은 보기는 오답
- **전문가 판단법(비정형)은 작은 조직용.** 「큰 조직에 적합」은 오답

## 5과목 — 위험분석 정량 vs 정성

| | 정량적 | 정성적 |
|---|---|---|
| 표현 | **금액·확률·백분율** | 높음/중간/낮음 |
| 기법 | **과거자료 · 수학공식 · 확률분포** | **델파이 · 시나리오 · 순위결정** |
| 객관성 | 높음 | 낮음(주관적) |
| **시간·비용** | **많이 든다** | **적게 든다** |

- **정량은 「재는」 것이라 품이 든다.** **시간·비용 절약은 정성적의 장점**
- **「과거자료가 어려울 때」면 수학공식**

**손실 계산 — 두 번 곱한다**

```
SLE = AV × EF          단일 예상 손실 = 자산 가치 × 노출 계수
ALE = SLE × ARO        연간 예상 손실 = 단일 예상 손실 × 연간 발생 횟수
```

- **노출 계수(Exposure Factor) = 자산의 몇 %가 날아가나**
- 예) 10억 자산, 60% 손상 → SLE **6억** / 10년에 한 번(ARO 0.1) → ALE **6천만**

## 5과목 — 「동의 없이 되는가」 판별

**동의 없이 수집·이용 가능** (제15조)

**⚠️ 제3자 제공은 수집보다 좁다** (제17조는 제15조의 **2호·3호·5호만** 인용)
- **「계약 체결·이행」(4호)은 수집은 되지만 목적 범위 내 제3자 제공 근거가 아니다**
- **계약은 나와 정보주체 사이의 일**이라 「그래서 남에게 넘겨도 된다」는 근거가 안 된다

**민감정보는 별도 동의** — 종교·질병·범죄경력 등은 **원칙 금지**, 별도 동의나 법령 근거가 있어야 한다

**⚠️ 「마케팅」이라는 말에 흔들리지 말 것 — 셋이 다르다**

| | 필요한 것 |
|---|---|
| 내가 **직접 광고를 보낸다** | **수신 동의**(옵트인) |
| 광고 업무를 **남에게 맡긴다** | **위탁 알림** |
| 개인정보를 **남에게 넘긴다** | **제3자 제공 동의** |

- 지문이 **「위탁하는 경우」**면 가운데다. **홍보·판매 권유 위탁도 동의가 아니라 알림**
- **「수탁자가 단독으로 손해배상 책임을 진다」도 오답** — 위탁자가 함께 책임진다(수탁자를 소속 직원으로 봄). **그게 위탁은 알림으로 족한 이유**

**위탁 = 알림 / 제3자 제공 = 동의**
- **위탁은 「내 일을 대신 시키는 것」이라 책임이 나에게 남는다** → 그래서 **알리면 되고**(제26조③), **사고도 내가 배상한다**(제26조⑥, 수탁자를 소속 직원으로 본다)
- 홍보·판매 권유 위탁도 **동의가 아니라 알림**

**CISO(정보보호 최고책임자)**
- **임원급** 지정, **과기정통부장관에 신고**, **겸직 제한**(일정 규모 이상)
- **「기업 형편에 따라 겸직할 수 있다」는 오답** — 보안 책임자가 다른 일도 맡으면 보안이 뒷전이 된다
- **CPO(개인정보보호책임자)는 다른 자리** — CISO는 망법, CPO는 개인정보보호법

**클라우드 — 장관에게 보고하는 건 「정보 유출」 하나뿐**
- **이용자에게 알린다** — 침해사고 / 정보 유출 / 사전예고 없는 서비스 중단
- **과기정통부장관에게 알린다** — **정보 유출만**
- 서비스 중단은 **계약 문제**고, 정보 유출은 **국가가 알아야 할 사안**

**개인정보보호 원칙 — 익명처리가 우선**
- **「익명처리가 가능하면 익명으로」**(제3조⑦). 순서는 **익명 → 가명 → 실명**
- **「가능한 경우에도 식별하여 처리해야 한다」는 정반대라 오답**

**내부 감사**
- **구성원을 정보보호 전문가로 제한하면 안 된다** — 업무 맥락을 놓친다
- **독립성 유지**가 핵심 요건 · 범위는 **포괄적**일수록 좋다
- **「~로 제한한다」·「~만 한다」가 든 보기는 감사·통제 문제에서 대체로 오답**

**법률 용어는 법이 쓰는 말로 묻는다**
- 해킹·바이러스·논리폭탄·메일폭탄·서비스 거부·고출력 전자기파로 발생한 사태 = **「침해사고」**(보안사고·사이버공격이 아니다)
- **악성 프로그램 유포가 나오면 정보통신망법**(제48조, 7년)
- 통신비밀보호법 = 감청·통신사실확인자료 / 정보통신기반보호법 = 주요정보통신기반시설

## ★★ BIA가 복구전략보다 먼저 — 사흘간 3번 나와 3번 다 오답

> **BCP 5단계 — 범위 설정 → 사업영향평가(BIA) → 복구전략 수립 → 복구계획 수립 → 테스트·유지보수**
> **고리 — 범위를 정해야 분석하고, 영향을 알아야 목표(RTO·RPO)가 나오고, 목표가 있어야 전략을 고른다**
> **「복구전략을 세운 뒤 BIA」는 무조건 오답**

## ★ 숫자 — 반복해서 틀리는 것만

| 항목 | |

| **개인정보취급자 식별정보(계정)** | 누가 |
| **접속일시** | 언제 |

**접속기록 1 · 2 · 3 사다리** (2회 연속 오답)

- **접속기록 1년** → **접속기록(민감) 2년** → **접근 권한 부여·변경·말소 기록 3년**
- 2년 조건 — **5만 명 이상** 처리 **또는** **고유식별정보·민감정보** 처리
  - **고유식별정보는 딱 4개** — 주민등록번호·여권번호·운전면허번호·외국인등록번호
- 점검 **월 1회** · 백신 갱신 **일 1회** · 인터넷망 차단 **일평균 100만**

**ISMS 의무 대상**

- **매출 100억 / 이용자 100만 / 병원·대학 1,500억(재학생 1만)** ← **1,000억이 보이면 오답**
- **ISMS-P 자체는 자율** · 간편인증 **매출 300억 미만**
- 인증기준 **ISMS 80개(16+64) / ISMS-P 101개(+21)** — **가장 많은 게 보호대책 64**
- 유효기간 **3년**, **사후는 매년 · 갱신은 만료 때**, 신청 전 운영 **2개월 이상**, 보완조치 **최대 100일**

**법정형 3 → 5 → 7**

- **침입 3년 / DDoS·비밀누설 5년 / 악성프로그램 유포 7년(최고)**
- 고리: 악성코드는 한 번 뿌리면 통제를 벗어나니 가장 무겁다

**통지·신고**

- **개인정보 유출 통지·신고 = 72시간** ← **기출의 24시간은 2023-09-15 개정으로 폐지됐다. 시험엔 72시간**
- 침해사고 신고 **24시간** · 파기 **지체 없이(5일)** · **GDPR도 72시간**
- 과징금 **전체 매출액 3%** / GDPR **2천만 유로 또는 전 세계 매출 4%**

**영향평가**

- 대상 **5만(민감·고유식별) / 50만(연계) / 100만**
- **고려사항 세 가지 — 개인정보의 수 · 제3자 제공 여부 · 권리를 해할 가능성.** **위탁 여부는 아니다**

## ★ 뒤바꿈 짝

**RTO vs RPO** — 재해 순간을 0으로 놓고 양쪽

```
   ←── RPO ──┤          ├── RTO ──→├── WRT ──→
 마지막 백업  재해 발생          시스템 복구  업무 정상화
             ├────────── MTD ──────────┤
```

- **왼쪽(과거) = RPO = Point = 시점 = 데이터를 얼마나 잃어도 되나.** RPO가 **백업 주기**를 정한다
- **오른쪽(미래) = RTO = Time = 시간 = 얼마나 기다려도 되나**
- **MTD ≥ RTO + WRT → RTO는 항상 MTD보다 짧다**

**BCP vs DRP**

- **BCP = 회사가 계속 돌아가게(넓다, 경영진, 사람·시설·절차 포함)**
- **DRP = 전산을 다시 살리게(좁다, IT 부서)** → **DRP ⊂ BCP**
- **「DRP가 BCP보다 넓다」는 무조건 오답**

**PP vs ST**

- **PP = Protection Profile = 제품군 공통 규격서(수요자 관점, 구현 무관)**
- **ST = Security Target = 우리 제품 명세서(개발자 관점, 구현 종속)**

**위험분석 4접근법**

- **기준선 = 체크리스트 일괄(빠름·쌈) / 비정형 = 전문가 감(주관적) / 상세 = 절차대로(정확·고비용) / 복합 = 중요 시스템만 상세(실무 주류)**

**위험처리 4전략**

- **감소**(통제 추가) / **수용**(그냥 둠) / **전가**(보험·외주) / **회피**(활동 중단)
- **법이 의무로 정한 것은 「수용」할 수 없다** ← 수탁자 감독을 일부만 하는 건 수용이 아니다
- **회피는 원래 극단적이다**(회원 가입 자체를 없앰) — 그게 회피의 정의

**정성 vs 정량**

- **정성 = 델파이 · 시나리오 · 순위결정 / 정량 = 과거자료 · 수학공식 · 확률분포**
- **「과거자료가 어려울 때」면 수학공식** · **ALE는 두 번 곱한다** (SLE = AV × EF → ALE = SLE × ARO)

**순서 나열형** — 약점으로 지목된 유형

- **위험관리 3단계** — 무엇이 위험한가(분석) → 얼마나 위험한가(평가) → 어떻게 할까(처리)
- **심사원 등급** — **「보」가 붙으면 가장 아래.** 심사원보 → 심사원 → 선임심사원 → 책임심사원
- **FDS** — 정보수집 → 분석·탐지 → 대응 → 모니터링
- **자산 식별** — 조직의 **「업무특성」**에 따라 분류, **「중요도」** 산정. **위협은 아직 안 본다**
- **통제 시점** — 예방(방화벽·직무분리) → 탐지(IDS·로그) → 교정(백업 복구)

## ★ 기관 — 2회 연속 오답

- **국무조정실장** = **정보통신기반보호위원회 위원장** (소속은 **국무총리**)
  - 여러 부처(전력·금융·통신·교통)가 걸려 있어 조정 부처가 맡는다
- **개인정보보호위원회** = **국무총리 소속 중앙행정기관**

- **KISA** = **침해사고 신고 접수** · ISMS-P 인증기관 · CSAP

## 법 조문에서 반복된 것

- **위탁 = 알려야 한다 / 제3자 제공 = 동의를 받아야 한다** ★
  - 위탁은 **내 일을 대신 시키는 것**이라 책임이 남아 있고, 제공은 **넘기는 것**이라 동의가 필요하다
  - 홍보·판매 권유 위탁도 **동의가 아니라 알림**
  - 손해배상에서 **수탁자는 위탁자의 소속 직원으로 본다**
- **유출 통지에서 「아직 파악 못 했다」는 정당한 사유가 아니다.** 안 사실만으로 먼저 알리고 나중에 보완
- **열람 제한 사유** — 법률상 금지 / 타인의 생명·신체·재산 침해 우려 / 공공기관의 **조세·시험·자격심사·보상금 산정·감사** 업무에 중대한 지장
  - **「처리하지 않으면 소관 업무를 못 한다」는 수집·이용 근거**이지 열람 거절 사유가 아니다
- **주민등록번호는 동의로도 처리 불가**(법령 근거 필요)
- **가명 = 개인정보 O / 익명 = X.** **익명처리가 우선** · 가명정보 특례 3목적(**마케팅은 아님**) · **결합은 지정 전문기관만, 반출도 승인**
- **개인정보를 국외로 이전해도 국내법상 보호조치 의무는 그대로**
- **광고 — 옵트인(사전 명시적 동의) + 21시~08시 별도 동의 + 수신거부 무료**
  - **푸시 알람 승인 ≠ 광고 수신 동의**(별개다)
  - **거래조건 변경 안내(등급 변경·포인트 소멸)는 광고성 정보의 예외**
- **데이터 소유자(Owner) = 분류·책임 / 관리자(Custodian) = 위탁받아 백업·보관 수행 / 사용자 = 절차 준수**
- **「기반시설」이 붙으면 법적 의무제도**(주요정보통신기반시설 취약점 분석·평가). 준비도 평가·클라우드 보안인증·정보보호 공시는 자율
- **ISO 27001만 인증을 받는다**(27002는 가이드). 27005 위험관리 / **27014 거버넌스**(평·지·모·소·보, 위임 없음) / 27017·27018 클라우드 / 27701 개인정보
- **ISO 27002 2022판 93개·4테마** (조직 37 · 인적 8 · 물리 14 · 기술 34)
- **위협은 제거할 수 없다. 줄일 수 있는 건 취약점뿐이고 잔여 위험은 0이 되지 않는다**
- **일반통제가 부실하면 응용통제도 신뢰할 수 없다**(감사에서 일반통제를 먼저 보는 이유)
- **IoT 운영·관리·폐기 단계 문항에서 보기에 「개발」이 있으면 그게 답**
