## 1. 최우선 재출제 (아직 안 붙음)

### 약어
| 약어 | 정답 | 놓친 지점 |
|---|---|---|
| SAS | **S**ecure **A**ttention **S**equence | 역할(Ctrl+Alt+Del 로그온 창)은 아는데 풀이가 안 나옴 |
| SACL | **S**ystem **A**ccess **C**ontrol **L**ist | S를 Security로 착각. DACL과 달리 **System** (감사 로그 대상 지정) |
| LSA | **L**ocal **S**ecurity **A**uthority | Authority를 Authentication으로 씀 |
| CSP | **C**ontent **S**ecurity **P**olicy (웹) | 윈도우 **C**redential **P**rovider와 이름이 겹침 — 문맥으로 구분 |
| RIP | **R**outing **I**nformation **P**rotocol | 4회차까지 백지. 고리: 이름이 제일 밋밋 = 제일 오래되고 단순 = 기준도 단순(홉 수) |

### 개념
- **SNMP 포트 161/162** — 3회차까지 "102, 103?"으로 답함. 161=매니저가 조회(폴링), 162=에이전트가 트랩 발송. 고리: 번호 큰 162가 에이전트 쪽에서 능동적으로 튀어나오는 알림
- **사설 IP 172 대역 범위** — 172.16 ~ 172.31 (`172.16.0.0/12`). 고리: **16에서 시작해 16개**. 10.0.0.0/8과 192.168.0.0/16은 안정적
- **콜리전 vs 브로드캐스트 도메인** — 3회차. "충돌 지점 / 퍼지는 범위"까지는 나오는데 **무엇이 나누는가**가 계속 누락. 콜리전=**스위치**가 포트별로, 브로드캐스트=**라우터·VLAN**이
- **허브 vs 스위치 (스니핑 관점)** — 허브는 받은 신호를 **모든 포트로 복사**해 뿌림 → 같은 허브에 물린 누구나 남의 트래픽을 봄(스니핑 공짜). 스위치는 MAC 보고 해당 포트로만 → 그래서 **ARP 스푸핑**이 필요해짐
- **GINA vs Credential Provider** — 4회차. Vista 교체 시점은 정답. 누락: 둘 다 **자격증명 수집 UI**이지 인증 자체가 아님(인증은 LSA). GINA는 통짜 `msgina.dll`, Credential Provider는 모듈식 복수 등록(지문·얼굴·스마트카드)
- **ARP 스푸핑 대응책** — 원인("ARP가 인증을 안 함")은 정답. 대응이 백지: 정적 ARP 등록 / DAI(Dynamic ARP Inspection) / 암호화 통신
- **TCP 4-way 종료가 4단계인 이유** — 전이중이라 방향별로 닫아야 하고, B의 ACK와 FIN 사이에 보낼 데이터가 남아 있을 수 있어 못 합침. (연결은 SYN+ACK가 합쳐져 3단계)
- **UDP 헤더 4필드** — 출발지 포트·목적지 포트·길이·체크섬(8바이트). 고리: 외우지 말고 **TCP에서 신뢰성 필드를 다 뺀 것**(순서번호·확인응답·플래그·윈도우 없음)
- **헤더 크기** — TCP 20바이트 / UDP 8바이트 / IP 20바이트
- **프로토콜 번호** — 1=ICMP, 6=TCP, 17=UDP
- **IP 오프셋 단위 8바이트** — 1480 ÷ 8 = 185
- **HTTP 3대 특징** — 요청-응답 / 비연결성(선을 끊는다) / 무상태(기억을 못 한다). 무상태만 나옴
- **HTTP/1.0 vs 1.1** — 1.1 = **지속 연결(Keep-Alive)** + **Host 헤더 필수**(가상 호스팅)
- **enable password vs enable secret** — password는 평문 저장(`show running-config`에 노출), secret은 해시 저장이며 **우선 적용**. secret을 쓸 것
- **Boink** — Teardrop 변종. Bonk=오프셋 전부 동일, Boink=일정하게 어긋남

## 2. 선행 지식 공백 — 진짜 원인이었던 것들

개념이 반복해서 안 붙을 때는 암기 부족이 아니라 **밑에 빠진 단어**가 원인이었다. 5회 반복된 패턴.

- **IP 단편 재조립 · 오프셋** — 오프셋 뜻을 모른 채 "Teardrop은 오프셋을 겹치게"를 외우고 있었음. MTU → 단편화 → Identification·MF 플래그·Fragment Offset부터 잡으니 풀림
- **프로세스에도 UID가 붙어 있다** — 이걸 모른 채 SetUID를 외우려 해서 계속 실패. 순서: ① 프로세스에 UID 딱지가 있다 → ② 보통은 실행한 사람 것 → ③ SetUID면 파일 소유자 것 → ④ `cat` vs `passwd`로 같은 상황 비교
- **삭제 권한은 파일이 아니라 디렉터리의 쓰기 권한에서 나온다** — 이걸 알아야 스티키 비트(`/tmp` 1777)가 이해됨
- **각 계층의 "주소"가 무엇인가** — 1=주소 없음(전기 신호 복사) / 2=MAC / 3=IP / 4=포트 번호. 허브 vs 스위치, 콜리전 도메인, ARP 스푸핑이 안 붙던 공통 원인
- **DLL이 무엇인가** — 정적 링크 vs 동적 링크. 이걸 모른 채 "GINA는 통짜 DLL"을 외우려 했음. DLL 인젝션 / DLL 하이재킹 / GINA 트로이목마로 이어짐
- **취약점 공격 vs 악성코드 설치** — 취약한 코드는 원래 피해자 OS에 있고 공격자는 패킷만 보냄. 그래서 대응이 백신이 아니라 **패치**. DDoS의 악성코드는 피해자가 아니라 **좀비 PC**에 심는 것

## 3. 해결됨 (하루 이상 간격 두고 재확인 통과)

- **스머프 vs Fraggle** — 스머프=ICMP, Fraggle=UDP. 3회 놓친 뒤 **"스머프는 핑"** 고리 하나로 해결
- **DRDoS** — 피해자 IP로 요청 → 제3자의 응답이 피해자에게(반사·증폭). 스머프가 그 원형
- **HULK** — URL 파라미터를 매번 랜덤화해 캐시 무력화
- **Ping of Death vs Teardrop** — 둘 다 IP 단편 재조립을 노림. PoD=크기(65,535 초과), Teardrop=오프셋 겹침
- **TCP 플래그 6종** — URG·ACK·PSH·RST·SYN·FIN. 고리: 연결 담당(SYN·FIN·RST) / 데이터 담당(ACK·PSH·URG)
- **특수 권한** — SetUID 4000(소유자 자리 `s`) / SetGID 2000(그룹 자리 `s`) / 스티키 1000(기타 자리 `t`). `s`가 두 번, 자리로 구분
- **SetUID 원리** — 권한 검사를 건너뛰는 게 아니라 **검사받는 신분이 파일 소유자로 바뀜**. 소유자가 bob이면 root가 실행해도 bob이 됨
- **umask** — 기본 권한(파일 666·디렉터리 777)에서 뺌. 022 → 644
- **심볼릭 vs 하드 링크** — 하드는 같은 inode라 원본을 지워도 **데이터가 살아있음**. 심링크는 경로를 가리켜 **깨짐**(파일은 남지만 쓸모없음)
- **utmp / wtmp / btmp** — 현재 접속(`who`) / 접속·종료 이력(`last`) / 실패(`lastb`). 바이너리라 전용 명령 필요
- **인증 vs 인가** — 401=인증, 403=인가 / LSA=인증(토큰 발급), SRM=인가(매 접근 판정). 두 도메인 모두 정답
- **DAC vs MAC** — Discretionary=임의적(소유자 재량, rwx·DACL) / Mandatory=강제적(시스템 정책, SELinux·AppArmor)
- **Kerberos 티켓 발급처** — AS가 TGT → 그 TGT로 TGS에서 서비스 티켓
- **winlogon vs lsass** — winlogon은 진행 총괄(사회자), lsass는 검증(심사관)
- **쿠키 3옵션** — Secure→도청 / HttpOnly→XSS / SameSite→CSRF
- **TRACE·XST** — 요청 헤더를 그대로 되돌려줘 응답 **본문**으로 쿠키가 샘 → **HttpOnly를 우회**
- **Pass-the-Hash** — NTLM은 해시로 응답을 만드니, 훔친 해시만 있으면 비밀번호 없이 인증 통과
- **허브1 · 스위치2 · 라우터3 계층** — L4 스위치가 4계층
- **비연결성 vs 무상태** / **SMTP 25** / **SYN_RECEIVED** / **위장 프로세스 판별(경로가 System32인지)**

## 4. 학습 방법 메모

- **원리형과 암기형은 대응이 다르다.** 원리가 있는 개념은 비유·메커니즘 설명 한 번에 붙는다. 원리 없이 짝만 있는 것(Fraggle, Bonk/Boink, 포트 번호, 플래그 나열)은 **억지 기억 고리**를 걸고 **다음 날 다시** 꺼내야 한다
- **설명 직후 재확인은 원리형에만 유효하다.** 암기형은 단기기억 복사라 의미가 없다. 반드시 하루 이상 두고 물을 것
- **읽기는 인출이 아니다.** 카드에 다 있는데도 안 외워졌던 이유. 꺼내보고 → 틀리면 확인, 이 순서로
- **풀네임을 이해하면 약어가 붙는다.** 대부분의 이름은 정직하다 — OSPF=Open Shortest Path First, SAM=Security Account Manager, GINA=Graphical Identification and Authentication
- **개념이 안 붙으면 밑에 빠진 단어부터 의심한다.** 2절이 그 목록이다
