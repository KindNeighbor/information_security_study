## 0. 이번 주에 확인된 학습 방법 (가장 중요)

지금까지 막힌 지점 대부분은 암기 부족이 아니었다. 세 가지 패턴이 반복됐다.

**① 밑에 빠진 단어가 있었다.** 오프셋을 모른 채 Teardrop을, 프로세스 UID를 모른 채 SetUID를, 삭제 권한의 출처를 모른 채 스티키 비트를, IP/TCP 헤더 내용을 모른 채 UDP 4필드와 방화벽 유형을 외우려 했다. → **개념이 반복해서 안 붙으면 암기를 더 시키지 말고 "이 단어 뜻 아세요?"를 먼저 물을 것.**

**② 설명 언어가 어려우면 안 붙는다.** "지식기반=시그니처 대조(오탐 적음, 제로데이 못 잡음)"처럼 시험 용어를 그대로 쓴 설명은 붙지 않았다. 반면 "남의 번호로 단체문자=스머프", "tear=찢다=오프셋", "문에 붙인 명단 vs 손에 든 열쇠꾸러미"는 한 번에 붙었다. → **일상 비유로 먼저 심고, 시험 용어는 그다음에 얹을 것.**

**③ 진입 순서가 틀리면 눈에 안 들어온다.** IP 헤더 필드 표를 먼저 보여주면 "아는 게 없어서 눈에 안 들어온다". 칸마다 **"이 칸이 없으면 무슨 일이 나나"**를 옆에 붙여야 읽힌다. → **표보다 임무가 먼저.**

그리고 운영상의 규칙 둘.

- **설명 직후 재확인은 원리형에만 유효하다.** 암기형은 단기기억 복사라 의미가 없다 — 하루 이상 두고 물을 것. 이 원칙이 옳다는 증거가 지금까지 **네 번** 나왔다(약어가 하루 뒤 재출제에서 연달아 해결됨).
- **읽기는 인출이 아니다.** 카드에 다 들어 있는데도 안 외워졌던 이유.

참고 — **네트워크 뼈대 정리 아티팩트**를 따로 만들어 두었다. 네트워크에서 막히면 처음부터 재설명하지 말고 그 페이지 위에 얹는다.

### 네트워크
- **콜리전 vs 브로드캐스트 도메인** — 4회차. 콜리전=스위치 정답. 브로드캐스트는 **L3 라우터·VLAN**(L4로 답한 이력)
- **캡슐화 · PDU · 계층별 헤더** — 데이터→(TCP)세그먼트→(IP)패킷→(MAC)프레임→신호. 중간 라우터는 2계층만 갈아 끼운다
- **NAT · PAT** — 공유기 안쪽 사설 IP는 서로 다름. 바깥에서 하나로 보이는 게 NAT, 포트로 구분하는 게 PAT
- **SNMP 포트 161/162** — 3회차까지 오답. 161=매니저 조회, 162=에이전트 트랩. 고리: 큰 번호가 능동 알림
- **사설 IP 172 범위** — 172.16 ~ 172.31 (`/12`). 고리: **16에서 시작해 16개**
- **UDP 헤더 4필드** — 4회차. 8바이트·포트 2개는 나옴, **길이·체크섬**이 계속 누락
- **IP 헤더 필드** — "포트는 없다"는 정답. 나머지 백지. 임무에서 파생시킬 것(옮기기: 출발지·목적지 IP·프로토콜번호·TTL·단편화 3필드·길이·체크섬)
- **TCP 4-way 종료 이유** — 전이중이라 방향별로 닫아야 하고 ACK와 FIN 사이에 시간이 필요해 못 합침
- **SYN Flooding** — 원리는 안정적. 남은 것: 상태명 **SYN_RECEIVED**, 고갈 대상 **백로그 큐**
- **Ping of Death vs Teardrop** — **PoD=크기**(65,535 초과) / **Teardrop=오프셋** 조작
- **Boink** — 오프셋을 일정하게 어긋나게 (Bonk는 전부 동일)
- **RIP 상한** — 최대 15홉(16=도달 불가)
- **프로토콜 번호** 1=ICMP, 6=TCP, 17=UDP / **헤더 크기** IP·TCP 20바이트, UDP 8바이트 / **오프셋 단위** 8바이트
- **HTTP 3대 특징** — 요청-응답 / 비연결성(선을 끊는다) / 무상태(기억을 못 한다)
- **HTTP/1.0 vs 1.1** — 1.1 = 지속 연결(Keep-Alive) + **Host 헤더 필수**
- **enable password vs secret** — password=평문 노출, secret=해시·**우선 적용**
- **포트 번호** — 20·21 FTP → 22 SSH → 23 Telnet → 25 SMTP 연속, 53 DNS, 80/443, 161·162 SNMP

### 보안 장비 (firewall · vpnetc · netattack)
- **포트 스캔 판정** — SYN+ACK=열림 / RST=닫힘 / 무응답=필터링. SYN 스캔은 RST로 끊어 **로그를 안 남김**
- **방화벽 유형** — 패킷필터링(3·4) / 회선(5) / 애플리케이션(7·프록시) / 상태기반(세션 문맥 기억·주류). 기본 정책 **Deny All**
- **방화벽 구축 형태** — 스크리닝 라우터 → 듀얼 홈드 → 스크린드 호스트 → **스크린드 서브넷**(라우터 2개 + DMZ). 베스천 호스트는 형태가 아니라 강화된 최전방 호스트
- **HIDS vs NIDS** — 갈림길은 **암호화를 보느냐**. HIDS는 봄(부하) / NIDS는 못 봄(광범위)
- **지식 기반 vs 행위 기반** — 시그니처(오탐↓·제로데이 X) vs 프로파일(제로데이 O·오탐↑). 백신 시그니처 vs 휴리스틱 구조
- **AH vs ESP** — 갈림길은 **암호화 유무**. AH=인증만·프로토콜 51 / ESP=암호화+인증·50
- **무선랜** — WEP(RC4·IV 짧음) → WPA(TKIP) → WPA2(AES-CCMP) → WPA3(SAE). Personal=PSK / Enterprise=802.1X+RADIUS
- **미출제로 남은 카드** — Snort 룰 구조·Suricata·YARA / 허니팟·허니넷 / PPTP·L2TP·SSL VPN 계층 / IPSec 전송모드 vs 터널모드 / NAC 동작 / RFID·USN

### 시스템 · 윈도우
- **utmp / wtmp / btmp** — utmp를 2회 "로그인 기록"으로 오해. 정답은 **현재 접속 중**(who/w). wtmp=이력(last), btmp=실패(lastb)
- **DAC vs MAC** — 번역은 정답. 남은 것: **누가 정하는가** — DAC=자원 **소유자** 재량, MAC=시스템·관리자가 보안등급 라벨로 강제
- **GINA vs Credential Provider** — 4회차. Vista 교체는 정답. 남은 것: 둘 다 **자격증명 수집 UI**이고 인증은 LSA가 함 / 통짜 `msgina.dll` vs 모듈식
- **SRM 참조모니터 3요건** — 항상 호출 · 변조 불가 · 검증 가능
- **SAM vs AD** — 로컬 계정 해시 vs 도메인 중앙관리
- **Kerberos** — 타임스탬프=리플레이 방지·시간 동기화 5분 / Golden Ticket=krbtgt 해시 탈취
- **DRDoS** — 원리는 정확. 용어만 누락: **반사(reflection)·증폭(amplification)**
- **Pass-the-Hash** — 원리는 정답. 용어 누락: NTLM 챌린지-리스폰스 / LSASS 메모리 탈취 / 횡적 이동
- **HTTP GET Flooding · Cache Control** — 3-way 완성이 필요해 IP 위조 불가 → 실제 좀비 PC 필요

### 접근 통제 (access.md) — 09-09 1회차
- **접근 통제 4단계** — 식별(ID 주장) → 인증(증명) → 인가(권한 부여) → **책임추적성**(로그)
- **3원칙** — 최소 권한 · 직무 분리 · 알 필요성
- **키 개수** — 대칭키 **n(n−1)/2**(모든 쌍), 공개키 **2n**. "둘 다 n개"로 오답했음
- **BLP vs Biba** — **BLP=기밀성**(No Read Up + No Write Down) / **Biba=무결성**(정반대). 고리: **BLP는 물이 아래로 새는 걸 막고, Biba는 오물이 위로 올라오는 걸 막는다**
- **ACL vs Capability List** — **ACL=문에 붙인 명단**(객체 기준) / **Capability=손에 든 열쇠꾸러미**(주체 기준)
- **클락-윌슨** = 상업용 무결성, 검증된 프로그램으로만 변경 + 직무 분리 / **만리장성(Brewer-Nash)** = 이해충돌 방지, 접근 이력에 따라 권한이 동적으로 바뀜
- **아직 안 다룬 것** — Secure OS·TCB 세부 / TCSEC(D→C→B→A, **B등급부터 MAC**)·CC(EAL1~7) / DES(블록64·키56·Feistel)·AES(Rijndael·SPN)·SEED·ARIA / 블록 운용모드 ECB·CBC·CTR / RSA(소인수분해)·DH(이산대수·키교환 전용·중간자 취약)·DSA(서명 전용)·ECC(짧은 키)

**틀린 9개 — 성격이 두 가지로만 갈린다.**

_뒤바꿈 유형 (기존 SAM/SRM · BLP/Biba와 같은 패턴)_
- **RTO vs RPO** — 설명을 서로 반대로 골랐다. 고리: 재해 순간을 0으로 놓고 **RPO는 뒤(과거·마지막 백업 시점), RTO는 앞(미래·다시 문 열기까지)**. RPO가 **백업 주기**를 정하고, 0에 가까우려면 실시간 복제. **MTD ≥ RTO + WRT**이므로 RTO는 MTD보다 **짧아야** 한다
- **PP vs ST** — PP=제품군 공통 규격서(**수요자 관점·구현 무관**) / ST=우리 제품 이력서(**개발자 관점·구현 종속**)
- **BCP vs DRP** — **BCP=회사가 계속 돌아가게(넓다)** / **DRP=전산을 다시 살리게(좁다, BCP의 부분집합)**. 이름이 곧 답: B=Business, D=Disaster Recovery
- **위험분석 접근법 4가지** — 기준선=체크리스트 일괄(빠름·싸다) / 비정형=전문가 감(주관적) / 상세=절차대로(정확·고비용) / 복합=중요 시스템만 상세(실무 주류). 상세와 기준선의 설명을 바꿔 낸 보기에 걸렸다

- **DNSSEC은 암호화가 아니다** — 응답에 **전자서명**을 붙여 위조를 막는 것(무결성·출처 인증), 내용은 평문. 같은 문항에서 함께 확인된 것: **질의 UDP 53 / 존 전송 TCP 53**, **재귀=네임서버가 대신 끝까지 / 반복=클라이언트가 차례로 직접**, **AXFR 열려 있으면 도메인 통째 유출**

### 정보보안 일반 (secbasic · crypto · esign) — 09-28 1~3회차, 15문제 **6개(40%)**

**네 과목 중 가장 낮다. 과락선(40)에 걸쳐 있어 최우선 재출제 대상.** 암호·해시·PKI 세부가 약하다.

_틀린 9개_
- **대칭키 vs 공개키 키 개수 — 2회 연속 오답(재출제 실패)**. 지난 회차 "둘 다 n개", 이번엔 두 수를 뒤바꿈.
  고리: **대칭키 n(n−1)/2 = 둘이 <u>같이 쓰는</u> 키라서 쌍의 개수 = 악수 횟수** / **공개키 2n = 각자 자기 것 한 쌍**. 100명이면 4,950 vs 200
- **FAR vs FRR** — **FAR=타인을 통과시킴(보안 사고)** / **FRR=본인을 거부함(불편)**. 문지기 비유: FAR은 아무나 들여보내고 FRR은 주인도 막는다. 엄격히 하면 **FAR↓ FRR↑**로 **동시에 못 낮추며**, 그래서 만나는 점인 **CER(낮을수록 우수)**로 비교
- **생일 공격 = 2^(n/2)** (2^n으로 답함). 2^n은 **일방향성**(해시값→원본)의 난이도. 차이는 "특정 값과 같은 것" vs "아무 두 개가 같은 쌍". SHA-256의 충돌 강도는 실질 **128비트**
- **X.509에 개인키는 들어가지 않는다** + **PKI 저장소도 개인키를 보관하지 않는다**(두 문항 연속 오답). **PKI 어디에도 개인키가 보관되는 곳은 없다** — 인증서에도, 저장소에도. 개인키는 본인만 가진다(pfx/p12·HSM)
- **DH는 키 교환 전용** — 암호화 알고리즘이 아니다. 용도로 갈라둘 것: **암호화+서명=RSA·ElGamal / 키 교환=DH / 서명 전용=DSA·KCDSA·ECDSA**
- **암호 분석 4분류에서 가장 강력한 것 = 선택 암호문(CCA)**. **암호문 단독 → 기지 평문 → 선택 평문 → 선택 암호문** 순으로 공격자가 유리. 고리: **고를 수 있는 게 많을수록 강하다**
- **DES/AES 수치와 구조** — **DES 블록64·키56·Feistel 16라운드** / **AES(Rijndael) 블록128·키128·192·256·SPN 10·12·14라운드**. 구조를 뒤바꾼 보기에 걸림. **3DES는 EEE가 아니라 EDE**(키를 다 같게 하면 단일 DES가 되는 하위 호환 때문)
- **2요소 인증** — **지문+홍채는 둘 다 생체라 2요소가 아니다**. 고리: **통이 셋(아는 것·가진 것·자신인 것)이고 서로 다른 통에서 하나씩** 꺼내야 2요소. 같은 통에서 둘은 여전히 1요소

_맞힌 것_ — 변조(있던 걸 고침) vs 위조(없던 걸 만듦) · **OFB·CTR은 오류 전파 없음**(CBC·CFB는 다음 블록까지) · 전자서명은 **기밀성 미제공** · **MAC이 부인방지 못 하는 이유**(같은 키라 수신자도 만들 수 있어 제3자 증명 불가) · **OCSP=실시간 한 건씩(good·revoked·unknown) vs CRL=주기적 목록(시차)** · PMI 속성 인증서는 유효기간이 짧다

## 2. 선행 지식 공백 — 반복된 진짜 원인

- **IP 단편 재조립 · 오프셋** — 뜻을 모른 채 "Teardrop은 오프셋을 겹치게"를 외우고 있었음
- **IP · TCP 헤더에 무슨 칸이 있는가** — UDP 4필드·방화벽 유형·TTL·프로토콜번호·오프셋·SYN Flooding이 **동시에** 막힌 공통 뿌리
- **3-way handshake는 인증이 아니라 유실 보완 장치** — 이 오해가 "인증 필드 없음"과 "읽는 깊이"를 뒤섞게 만들었음. **두 축을 분리할 것: ① 어디까지 읽나(깊이)=방화벽 유형 ② 읽은 걸 믿을 수 있나(무인증)=스푸핑 계열**
- **프로세스에도 UID가 붙어 있다** — 이걸 모른 채 SetUID를 외우려 해서 계속 실패
- **삭제 권한은 파일이 아니라 디렉터리의 쓰기 권한에서 나온다** — 스티키 비트의 전제
- **각 계층의 "주소"가 무엇인가** — 1=주소 없음 / 2=MAC / 3=IP / 4=포트 번호
- **MAC 주소에는 위치 정보가 없다** — 스위치가 "출발지 MAC = 들어온 포트"를 기록해 표를 스스로 만듦(MAC 학습). 표가 가득 차면 허브처럼 동작 = MAC 플러딩
- **브로드캐스트 MAC(FF:FF:FF:FF:FF:FF)** — "이 랜 전원"이라는 약속. 표에 못 올라오니 스위치는 전부로 복사, 라우터는 MAC 헤더를 벗고 IP를 보므로 안 넘김. ARP 요청이 이것이라 랜을 못 넘음
- **목적지 MAC 판단 규칙** — 물리적으로 거쳐 가는 것과 목적지 MAC에 적히는 것은 다름. **같은 네트워크면 상대 MAC, 다른 네트워크면 게이트웨이 MAC**
- **캡슐화 방향** — 나갈 때 붙이고 도착해서 뗌. 중간 라우터는 2계층만 갈아 끼움(물류센터는 송장만 바꿔 붙이지 상자를 안 뜯는다)
- **DLL이 무엇인가** — 정적 링크 vs 동적 링크. DLL 인젝션 / 하이재킹 / GINA 트로이목마로 이어짐
- **취약점 공격 vs 악성코드 설치** — 취약한 코드는 원래 피해자 OS에 있고 공격자는 패킷만 보냄. 대응이 백신이 아니라 **패치**. DDoS의 악성코드는 **좀비 PC**에 심는 것
- **라우팅은 경로 결정이지 이름 해석이 아니다**
- **실물 배선 이미지 부재** — 집 공유기 한 대가 라우터+스위치+무선AP 합체품이라 셋이 실물로 구분될 일이 없었음

## 4. 통했던 설명 방식 (재사용할 것)

- **네트워크 장비** — 차이는 **"무엇까지 읽을 수 있느냐"** 하나. 허브=못 읽음 / 스위치=MAC / 라우터=IP. 그리고 **"읽을 게 없으면 뿌릴 수밖에 없다."** 여기서 콜리전 도메인·허브 스니핑·MAC 테이블·MAC 플러딩·ARP 스푸핑·브로드캐스트 경계가 전부 파생된다. 동작 목록을 외우게 하지 말 것
- **윈도우 로그온** — 조립 라인(SAS → winlogon → 자격증명 창구 → lsass → 토큰 → SRM)으로 제시하고 리눅스와 대응표를 그림(UID 딱지 ↔ 액세스 토큰, rwx ↔ DACL, 커널 ↔ SRM, /etc/shadow ↔ SAM)
- **SetUID** — ① 프로세스에도 UID 딱지가 있다 → ② 보통은 실행한 사람 것 → ③ SetUID면 파일 소유자 것 → ④ `cat` vs `passwd`로 같은 상황 두 번 비교
- **키 분배 문제** — 대칭키는 키를 안전히 전달할 통로가 필요한데, 그 통로가 있으면 그걸로 데이터를 보내면 되는 **닭-달걀**. 공개키가 이걸 푼 것. 키 개수 공식과 한 덩어리로 설명하면 붙는다
- **초기 프로토콜은 평문·무인증이 기본, 대응은 보안 버전 신설/상위 감싸기** — ARP→DAI, DNS→DNSSEC, SNMPv1v2→SNMPv3, Telnet→SSH, FTP→FTPS/SFTP, HTTP→HTTPS. "이 프로토콜의 보안 대안은?" 형태로 출제됨
- **풀네임을 이해하면 약어가 붙는다.** 대부분의 이름은 정직하다 — OSPF=Open Shortest Path First, AH=Authentication Header, ESP=Encapsulating Security Payload(감싼다=암호화)
- 원리 없이 짝만 있는 항목(Fraggle, Bonk/Boink, 포트 번호, 플래그 나열)은 **억지 기억 고리**를 걸고 **다음 날 다시** 꺼낼 것. 본인이 카드를 직접 만드니, 반복 오답은 카드에 고리 한 줄을 넣는 게 낫다

### 자주 흔들리는 짝 — 그림으로 잡기

본인이 "계속 봐야겠다"고 한 항목들. 설명을 다시 쓰지 말고 이 그림을 그대로 쓸 것.

**RTO vs RPO — 재해 순간을 0으로 놓고 시간축의 양쪽**

```
        ←─── RPO ───┤         ├─── RTO ───→├── WRT ──→
      마지막 백업   재해 발생            시스템 복구   업무 정상화
                    ├──────────── MTD ────────────┤
```

- **왼쪽(과거)=RPO** — 마지막 백업 이후 데이터는 날아간다. 그 손실 허용치. **RPO가 백업 주기를 정한다**(RPO 1시간 → 1시간마다 백업, RPO 0 → 실시간 복제)
- **오른쪽(미래)=RTO** — 시스템이 다시 서기까지 기다릴 수 있는 시간. 짧게 잡을수록 미러·핫 사이트가 필요해 비싸다
- **MTD** = 이 이상 멈추면 회복 불가능한 한계선 · **WRT** = 복구 후 업무 정상화까지
- **MTD ≥ RTO + WRT**, 그래서 **RTO는 항상 MTD보다 짧다**
- 한 줄: **RPO=Point=시점="데이터를 얼마나 잃어도 되나"** / **RTO=Time=시간="얼마나 기다려도 되나"**

**BCP vs DRP — 본사에 불이 났다고 상상할 것**

- **DRP가 하는 일**: 서버·데이터를 백업 센터에서 살린다(전산 복구)
- **BCP가 하는 일**: 그것까지 포함해 회사가 굴러가게 한다 — 직원은 어디서 일하나, 대표전화는 어디로, 고객 응대는 누가, 협력사 통보는, 대금 결제는
- **전산이 살아나도 사람·공간·절차가 없으면 업무는 안 돌아간다** → **DRP ⊂ BCP**

| | BCP | DRP |
|---|---|---|
| 대상 | **조직 전체 업무**(사람·시설·절차·공급망·IT) | **IT 시스템·데이터** |
| 목적 | 업무를 **계속**하기 | 시스템을 **복구**하기 |
| 주도 | **경영진** | **IT 부서** |
| 범위 | 넓다(**DRP 포함**) | 좁다 |

이름이 곧 답: **B**usiness=사업 전체 / **D**isaster **R**ecovery=복구=IT.
공통점: **둘 다 BIA에서 출발 · RTO·RPO를 기준 · 정기 테스트 필수**.
**"DRP가 BCP보다 범위가 넓다"는 지문은 무조건 오답.**

**접속기록 보관 — 1·2·3 사다리 (2회 연속 오답)**

- **접속기록(일반) 1년** → **접속기록(민감) 2년** → **접근 권한 부여·변경·말소 기록 3년**
- **"평범하면 1년, 민감하면 두 배인 2년, 권한은 3년."**
- **무엇이 '민감'인가 — 둘 중 하나라도 걸리면 2년**
  · **규모**: 5만 명 이상의 정보주체 개인정보를 처리
  · **종류**: **고유식별정보**(주민등록번호·여권번호·운전면허번호·외국인등록번호 **딱 4개**) 또는 **민감정보**(사상·신념, 노조·정당, 정치적 견해, 건강·성생활, 유전정보, 범죄경력, 생체인식정보, 인종·민족)
- 실무에선 대부분 걸려서 2년이지만, 시험은 **"5만 명 이상 또는 고유식별·민감정보"** 라는 조건문 자체를 묻는다

**기관별 역할 (정보통신기반보호위원회 위원장을 2회 연속 오답)**

- **국무조정실장** = 정보통신기반보호**위원회** 위원장. 전력(산업부)·금융(금융위)·통신(과기정통부)·교통(국토부)처럼 **여러 부처에 걸쳐 있어 조정 부처가 맡는다**
- **국가정보원** = 보안적합성 검증 · **KCMVP**(암호모듈) · CC 인증 체계
- **KISA** = **침해사고 신고 접수** · ISMS-P 인증기관 · CSAP

**ISMS-P 심사 3종 — 3년 주기 그림**

- **최초**(취득) → **사후**(1년 뒤) → **사후**(2년 뒤) → **갱신**(3년, 만료 전)
- **"사후는 매년, 갱신은 만료 때."**

### 약어 — 풀네임이 답을 알려주는 것 (풀어서 외운다)
- **CBC** Cipher Block **Chaining** = 사슬처럼 앞 블록과 엮임 · **ECB** Electronic **Code Book** = 대응표라 같은 입력이면 같은 출력 · **CTR** Counter · **OFB** Output Feedback
- **AH** Authentication Header = **인증만** · **ESP** Encapsulating Security Payload = **감싼다 = 암호화**
- **OSPF** Open Shortest Path First · **RIP** Routing Information Protocol
- **SAM** Security **Account Manager** = 계정 **관리**(명부) · **SRM** Security **Reference Monitor** = 접근 **검사**(문지기)
- **PP** Protection **Profile** = 제품군 공통 규격서(수요자) · **ST** Security **Target** = 우리 제품 명세(개발자) · **TOE** Target of Evaluation = 평가 대상
- **FAR** False **Acceptance** = 타인을 받아들임 · **FRR** False **Rejection** = 본인을 거부함
- **RTO** Recovery **Time** = 시간 · **RPO** Recovery **Point** = 시점 · **MTD** Maximum Tolerable Downtime
- **SLE** Single / **ALE** Annualized Loss Expectancy · **ARO** Annualized Rate of Occurrence
- **TCB** Trusted Computing Base = 신뢰 부품 전체(작을수록 안전)

### 약어 — 이름이 답을 안 알려주는 것 (억지 고리 필요)
- **PGP**(Pretty Good Privacy) = **P**eer끼리 서로 서명 = **분산·신뢰의 웹** / **PEM**(Privacy Enhanced Mail) = **위에서 중앙 CA가 관리** = 집중, 복잡해 미사용 / **S/MIME** = X.509 상용 표준
- **ARIA** = **A**cademy · **R**esearch **I**nstitute · **A**gency (학·연·관) · **KCDSA** = Korea + DSA · **Rijndael** = AES의 원래 이름
- **몬덱스 양도 O / 비자캐시 양도 X**
- **utmp 현재 접속(who) / wtmp 이력(last) / btmp 실패(bad, lastb)**
- **ADS 은닉 / VSS 백업 / EFS 파일 암호화 / BitLocker 볼륨 암호화**
- **XKMS 키 / SAML 인증정보·SSO / XACML 접근통제 정책**
- **집성 = 더하기**(조각→큰 그림) / **추론 = 나누기**(아는 값→모르는 값)
- **BLP 기밀성**(No Read Up + No Write Down) / **Biba 무결성**(정반대)
- **델파이·시나리오·순위결정 = 정성** / **과거자료·수학공식·확률분포 = 정량**
- **증분 = 직전 백업 기준**(백업 편하고 복구 고생) / **차등 = 전체 백업 기준**(반대)
